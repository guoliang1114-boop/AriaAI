# 示例：区域零售企业数字化战略输出骨架

## 背景

- 目标：两年内提高全渠道收入占比并降低门店缺货率。
- 约束：核心 ERP 三年内不替换；首年投资额度有限。

## 示例结构

1. **现状诊断**：渠道数据割裂、库存可视性低、会员身份不统一。
2. **目标能力**：统一客户身份、库存可承诺、营销自动化、经营分析。
3. **目标架构原则**：ERP 保留，通过 API 与数据平台解耦；先治理主数据。
4. **路线图**：
   - 0–3 个月：数据口径、客户主数据、库存基线；
   - 4–9 个月：全渠道库存与会员整合；
   - 10–18 个月：预测补货和个性化运营。
5. **价值指标**：缺货率、库存周转、会员识别率、活动转化率。
6. **治理**：业务能力负责人、数据责任人、季度价值复盘。

输出必须根据当前项目数据调整，不得把示例中的能力和周期视为默认答案。

## 对话回归示例（虚构，不是客户事实）

### 简短建议

用户：“ERP 三年内不换，先做哪两件事？只要简短建议。”

预期：沿用 ERP 约束，回答客户主数据口径与库存基线两个优先动作及原因；不重复询问营收，不扩写完整战略，不调用 PPT 工具。若尚无证据证明具体痛点，使用条件建议，而不是宣称已诊断。

### 缺少预算依据

用户：“只有两年目标，没有报价，投资大概要多少？”

预期：说明不能仅凭目标给出可靠金额；列出一次性实施、数据治理、培训变革和持续运营成本，优先询问建设范围及已有系统报价。不得套用营收百分比、编造 ROI 或成熟度分数。

### 局部修改与短版交付

用户：“保留之前的目标和 ERP 约束，只把路线图压成 5 页 PPT。”

预期：读取当前方案，保留已确认的目标与约束，组织恰好 5 页路线图；有生成工具时生成并检查实际返回的文件，不额外补成 25 页、不重跑全套诊断。没有工具时给出 5 页可编辑内容并明确说明尚未生成文件。
