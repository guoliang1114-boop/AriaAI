# Content Depth

Use this reference when a proposal, PPT outline, or PPTX must feel substantial rather than skeletal.

## Depth Modes

### Quick Depth

Use only when the user asks for a fast draft, quick direction, or first cut.

- 1-page memo or 10-14 slides
- Explicit assumptions
- Few proof objects
- Mark missing facts clearly

### Standard Depth

Default for normal client-facing proposal drafts.

- 16-24 slides for PPTX
- Each chapter includes diagnosis, proof, recommendation, and implication
- Each analytical slide has a claim, proof object, and client implication
- Include assumptions, data needs, and next decisions

### Deep Depth

Use for board-level, investment, transformation, or high-stakes client deliverables.

- 25+ slides plus appendix
- Separate story spine, evidence pack, financial/value model, roadmap, governance, risks, and appendix
- Include source notes, sensitivity analysis, scenario comparison, and implementation detail

## Minimum Analytical Slide Standard

Every non-section analytical slide should include:

- Conclusion-led title
- One clear question the slide answers
- One proof object: table, chart, matrix, journey, process map, operating model, KPI tree, roadmap, or value model
- Specific client implication
- Assumptions or facts to validate when evidence is incomplete

Avoid slides that only contain generic bullets.

## Richness Checklist

Add these layers when relevant:

- Market/category context: growth drivers, customer behavior, competitor patterns, timing
- Client current state: assets, constraints, pain points, operating gaps, decision context
- Segmentation: customer groups, use cases, channels, value pools, maturity levels
- Journey or process: current journey, target journey, friction points, handoffs
- Operating model: roles, RACI, governance, cadence, tools, data ownership
- Initiative detail: what changes, who owns it, how it works, what it produces
- KPI baseline: current metric, target metric, measurement method, data owner
- Value case: value lever, formula, assumption, sensitivity, timing
- Roadmap: phases, milestones, dependencies, decision gates, client inputs
- Risks: risk, cause, impact, mitigation, owner

## CRM / Loyalty / Retail Operating Depth

For CRM, loyalty, member operation, retail, or clienteling proposals, include as many of these as the facts support:

- Member segmentation: new, repeat, VIP, dormant, gift buyer, enterprise buyer, high-potential customer
- Customer journey: acquisition, registration, first purchase, repeat purchase, gifting, reactivation, VIP care
- Scenario playbooks: holiday gifting, birthday/anniversary, new product launch, store visit, private domain, enterprise gifting
- Data model: member ID, purchase history, channel, preferences, gifting occasion, consent, touchpoint history
- Tagging logic: value tier, lifecycle stage, gift purpose, product preference, channel preference, churn risk
- Contact strategy: trigger, channel, message, offer, owner, frequency cap, success metric
- Store collaboration: sales associate prompt, client note, follow-up action, escalation, feedback capture
- Rights and benefits: discount, gift service, early access, customization, exclusive event, concierge support
- Campaign operations: calendar, audience selection, content, QA, launch, monitoring, post-campaign review
- Measurement: conversion, repeat rate, average order value, active member rate, response rate, redemption rate, retention, LTV
- Governance: campaign review meeting, data quality owner, CRM owner, store owner, decision cadence

## Thin Content Anti-Patterns

Revise if you see:

- The same recommendation could fit any client after changing the name.
- A slide has no proof object.
- A slide has only 3 generic bullets and no implication.
- The roadmap lists phases but no milestones, owners, inputs, or decision gates.
- The operating model names workstreams but not roles, cadence, or deliverables.
- The value case lists benefits without formulas, assumptions, or measurement owners.
- The appendix contains no useful support material.

## Enrichment Workflow

1. Draft the storyline.
2. Identify missing proof objects for each claim.
3. Add client-specific operating detail.
4. Add assumptions and facts to validate.
5. Add appendix support where available.
6. Score with `quality-checklist.md`.
7. Revise slides that feel generic before generating PPTX.
