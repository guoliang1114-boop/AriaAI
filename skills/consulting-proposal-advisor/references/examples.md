# Examples

Use these examples when output risks becoming generic. Adapt the pattern, not the specific facts.

## Good vs Bad Titles

Bad: `市场分析`  
Good: `市场增长放缓正在倒逼客户重构获客效率和存量客户运营能力`

Bad: `解决方案`  
Good: `三阶段转型路径可在90天内验证核心价值，并为规模化推广建立基础`

Bad: `项目计划`  
Good: `前60天应聚焦高频场景试点，先验证机制有效性再扩大推广`

Bad: `CRM运维优化`  
Good: `CRM运维应从被动工单处理升级为面向会员经营结果的业务支撑机制`

Bad: `Risks`  
Good: `Adoption risk is concentrated in field execution, not in the system configuration itself`

Bad: `Implementation Plan`  
Good: `A 12-week pilot can validate value before committing to a full operating model rollout`

## Executive Summary Example

Use this structure for a one-page proposal summary. This is a fictional example; adapt the pattern, not the facts.

```text
核心判断
[某高端零售品牌]的CRM运维问题不只是系统稳定性问题，而是会员经营链路缺少面向业务结果的运维机制。当前CRM已承载会员识别、权益、活动触达和门店执行等关键环节，但需求分级、数据质量、活动保障和业务复盘尚未形成闭环。

核心建议
建议将CRM运维从“被动工单处理”升级为“稳定保障 + 数据治理 + 活动运维 + 业务共创”的四位一体模式。近期不建议启动大规模系统改造，而应先围绕会员数据质量和高频活动保障建立30-60天试点。

预期价值
试点成功后，客户可缩短活动上线周期，减少会员数据争议，提高门店执行一致性，并让CRM运维价值从系统可用率扩展到活动效率、数据准确率和业务满意度。

下一步
建议在项目启动前确认试点活动、资料权限、访谈对象和成功指标，并在两周内完成现状诊断与试点机制设计。
```

## PPT Slide Example

```text
Title:
CRM运维的机会正在从“降低系统故障”转向“提升会员经营效率与客户体验”

Bullets:
- CRM已承载会员识别、权益、活动触达和门店执行等关键经营链路
- 当前运维若只围绕故障关闭率管理，难以支撑高频营销活动和门店协同
- 客户应优先建立活动保障、数据质量和业务复盘机制，而不是直接启动大规模系统改造

Visual suggestion:
Use a 3-column table: `业务链路 -> 当前运维痛点 -> 对客户的启示`, with a highlighted implication column.
```

## Rich PPT Slide Example

Use this richer pattern for Standard Depth decks:

```text
Title:
高端零售CRM运营应从“节庆促销触达”升级为“会员生命周期经营”

Question answered:
客户为什么不能只靠单次活动提升复购？

Proof object:
Use a lifecycle table with columns:
`会员阶段 -> 典型行为 -> 当前运营缺口 -> 建议运营动作 -> 成功指标`

Example rows:
- 新客 -> 首次购买后缺少偏好沉淀 -> 无法判断礼赠/自用/企业采购目的 -> 购买后7天内触发偏好收集和欢迎权益 -> 偏好补全率、二购率
- 礼赠客户 -> 节庆购买高但复购不稳定 -> 未记录礼赠对象和节日场景 -> 建立节日前提醒、礼盒推荐和企业采购跟进 -> 节庆复购率、客单价
- VIP客户 -> 高客单但服务动作不稳定 -> 门店和总部缺少统一服务记录 -> 配置专属导购跟进、生日/纪念日权益和新品优先试用 -> VIP留存率、服务满意度
- 沉睡客户 -> 6-12个月未复购 -> 缺少沉睡原因和唤醒策略 -> 按历史偏好和价格敏感度设计不同唤醒包 -> 唤醒率、退订率

Client implication:
CRM运营的近期重点不是增加更多活动，而是先把会员阶段、场景标签、触达动作和复盘指标打通。

Assumptions to validate:
会员ID是否能跨门店、电商和私域统一；历史购买是否能识别礼赠场景；门店是否能回填客户偏好和服务记录。
```

## Bad To Better Rewrite

Bad:
`我们将赋能客户提升CRM运营效率，打造闭环管理体系。`

Better:
`我们将围绕会员数据质量和高频营销活动建立运维机制，使活动上线周期、数据准确率、问题关闭率和业务满意度可以被持续追踪。`

Bad:
`项目将优化流程并提升协同。`

Better:
`项目将明确需求分级、SLA、活动上线检查清单和月度复盘节奏，减少临时沟通和重复问题。`
