# Engagement Types

Use this file to tailor proposal structure and proof objects by engagement type.

## Selection Logic

Choose the primary engagement type by the decision the client must make:

- Choose Strategy / Market Entry when the decision is where to play, whether to enter, which option to pursue, or how to compete.
- Choose Operations / Process Improvement when the decision is how to improve cost, speed, quality, service, productivity, or process performance.
- Choose Digital / IT / Data when the decision depends on systems, data, architecture, vendors, automation, CRM, ERP, analytics, or operating technology.
- Choose Change Management when the decision depends on adoption, behavior change, stakeholder readiness, training, or organization alignment.
- Choose Commercial / Growth when the decision is how to grow revenue, improve funnel performance, retain customers, price, sell, or run GTM.

If multiple types apply, pick the type with the highest delivery risk as primary and include one secondary lens. For example, a CRM operations project is often Digital / IT / Data primary with Operations secondary and Commercial / Growth as a value lens.

## Strategy / Market Entry

Emphasize:
- Market attractiveness and growth drivers
- Customer segments and willingness to pay
- Competitive landscape and white space
- Strategic options and tradeoffs
- Entry path, investment thesis, and scenarios

Useful pages:
- Market map
- Segment attractiveness matrix
- Competitor comparison
- Strategic options table
- Scenario-based roadmap

Executive summary angle:

```text
The strategic question is not whether the market is attractive in aggregate, but which segment offers a defendable entry point given the client's assets, timing, and investment appetite.
```

## Operations / Process Improvement

Emphasize:
- Current-state process map
- KPI baseline and operational bottlenecks
- Root cause analysis
- Target operating model
- Implementation waves and capability building

Useful pages:
- Process pain point map
- KPI baseline table
- Root cause tree
- Workstream plan
- Benefits tracking dashboard

Executive summary angle:

```text
The performance gap is driven less by individual execution issues than by process handoffs, unclear ownership, and weak KPI visibility across the operating model.
```

## Digital / IT / Data

Emphasize:
- Business capabilities supported by technology
- Current architecture and integration pain points
- Data quality and governance
- Vendor or platform options
- Delivery roadmap, risks, and operating model

Useful pages:
- Capability architecture
- System landscape
- Data governance model
- Vendor comparison
- Pilot and rollout roadmap

Executive summary angle:

```text
The technology issue should be reframed as a business capability issue: systems, data, process ownership, and governance must be redesigned together to create measurable operating value.
```

## Change Management

Emphasize:
- Stakeholder groups and change impact
- Adoption risks
- Communication, training, and reinforcement
- Governance and sponsor model
- Readiness metrics

Useful pages:
- Stakeholder map
- Change impact assessment
- Adoption journey
- Training and communication plan
- Readiness scorecard

Executive summary angle:

```text
The main risk is not solution design but adoption; the program needs sponsor alignment, role-specific behavior change, and reinforcement mechanisms from day one.
```

## Commercial / Growth

Emphasize:
- Growth levers and customer economics
- Funnel, retention, pricing, and channel performance
- Segment priorities
- GTM motions and campaign cadence
- Experiment roadmap and metrics

Useful pages:
- Growth lever tree
- Funnel analysis
- Segment priority matrix
- GTM operating model
- Experiment roadmap

Executive summary angle:

```text
Growth should be managed as a portfolio of measurable levers, with near-term experiments used to validate which segments, offers, and channels can scale profitably.
```
