# Proposal Structure

Use this structure for client-ready proposals. Adapt labels to the user's language and deliverable type.

## Consulting-Firm Logic

A proposal recommendation should read like a persuasion chain, not a project description:

```text
客户为什么必须现在行动
-> 我们判断问题本质是什么
-> 推荐什么方案
-> 如何落地
-> 能带来什么价值
-> 下一步怎么启动
```

For Chinese deliverables, the default full proposal structure is:

1. 执行摘要
   - 客户当前面临的核心问题
   - 关键判断
   - 推荐方案一句话概括
   - 预期价值与落地周期
   - 需要客户决策的事项

2. 项目背景与客户挑战
   - 行业与市场变化
   - 客户当前业务现状
   - 已暴露的关键痛点
   - 问题带来的业务影响
   - 为什么现在是启动变革的窗口期

3. 核心诊断与问题拆解
   - 主要症状
   - 深层根因
   - 对业务、组织、流程、系统或客户体验的影响
   - 关键机会点
   - 若不采取行动的风险

4. 方案总体思路
   - 方案设计原则
   - 目标状态蓝图
   - 推荐路径
   - 为什么选择该路径
   - 与其他可选方案的对比

5. 具体解决方案
   - 各工作模块的目标、关键动作、交付物和客户参与要求
   - 常见模块包括战略/业务模式/增长方向、运营流程/组织机制/管理体系、数字化/数据/系统能力、变革落地/培训/治理机制

6. 实施路径与项目计划
   - 阶段一：诊断与共识
   - 阶段二：方案设计
   - 阶段三：试点验证
   - 阶段四：推广落地
   - 关键里程碑、决策节点、前30-60天重点行动

7. 项目治理与协作机制
   - 项目组织架构
   - 双方角色分工
   - 沟通机制
   - 高层 Steering Committee
   - 风险升级机制

8. 预期价值与收益测算
   - 财务价值：收入提升、成本降低、效率改善
   - 运营价值：流程提速、质量提升、响应周期缩短
   - 管理价值：决策透明、组织协同、能力沉淀
   - 战略价值：竞争力、可扩展性、长期增长能力
   - 核心测算假设

9. 风险、假设与保障措施
   - 关键风险
   - 前置假设
   - 客户需配合事项
   - 数据、人员、决策、系统等依赖
   - 风险应对方案

10. 项目团队与相关经验
   - 顾问团队配置
   - 核心成员角色
   - 类似项目经验
   - 方法论与工具
   - 差异化优势

11. 商务安排或服务范围
   - 服务范围
   - 不包含范围
   - 项目周期
   - 交付物清单
   - 费用模式，如需要

12. 下一步行动
   - 客户需确认的问题
   - 建议启动时间
   - Kickoff 前准备事项
   - 近期行动清单

## One-Page Executive Proposal

1. Context and decision
   - Client situation
   - Core decision needed
   - Why now

2. Diagnosis
   - Main issue
   - Root causes
   - Business impact

3. Recommendation
   - Recommended path
   - Why this path
   - Alternatives considered

4. Engagement approach
   - Workstreams
   - Key activities
   - Deliverables
   - Client participation required

5. Roadmap
   - Phase 1: diagnose and align
   - Phase 2: design and validate
   - Phase 3: pilot and refine
   - Phase 4: scale and embed

6. Value and risks
   - Expected benefits
   - Key assumptions
   - Risks and mitigations

7. Next steps
   - Decisions required
   - Immediate actions
   - Proposed kickoff timing

## PPT Proposal Flow

1. Executive summary: the recommendation in one page
2. Client context: the business problem and urgency
3. Key diagnosis: what is really blocking progress
4. Opportunity size: value at stake
5. Recommended solution: target state and design principles
6. Workstreams: how the work will be delivered
7. Roadmap: sequence, milestones, and decision gates
8. Governance: roles, cadence, and client involvement
9. Value case: expected benefits and assumptions
10. Risks and mitigations: delivery confidence
11. Credentials or relevant experience, if requested
12. Commercial model or SOW summary, if requested
13. Next steps: what happens after approval

## Strong Slide Titles

Prefer titles that make a claim:

- "Three root causes are slowing order fulfillment and raising service cost"
- "A phased operating model redesign can capture value within 90 days"
- "The recommended path balances speed, control, and organizational adoption"
- "市场增长放缓正在倒逼客户重构获客与运营效率"
- "三阶段转型路径可在90天内验证核心价值并形成规模化推广基础"

Avoid topic-only titles:

- "Background"
- "Solution"
- "Timeline"
- "Risks"
- "市场分析"
- "解决方案"
