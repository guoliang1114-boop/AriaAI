# 项目对话「活动时间线」设计稿（harness 风格）

> 状态：设计稿，待评审 → 评审通过后再写代码。
> 日期：2026-05-28
> 目标：把项目对话(`/projects/:id/chat`)的复杂任务 / Skill 调用体验,统一成一条**真实事件驱动**的活动时间线(像 agent harness 那样:思考 → 调工具/Skill → 后台任务步骤 → 交付物),取代当前碎片化、部分写死的呈现。

## 1. 现状(已核实)

| 场景 | 当前呈现 | 问题 |
|---|---|---|
| 普通工具回合 | 实时工具卡(`tool_executing`/`tool_result`)+ 思考转圈 | OK,但工具卡零散堆叠,无"第几步"结构 |
| 调用 Skill | **不显示**用了哪个 Skill,无步骤 | 漂亮的 5 步 `skill_progress` 只在独立聊天页 `Chat.tsx` 渲染,项目对话从没接 |

| 步骤边界 | 后端发的 `agent_step` 被前端丢弃 | `streamingSteps` / `upsertStep` / `AgentStepView` 全是死代码 |

**相关代码锚点**
- 流式渲染:`ProjectChatMessages.tsx` → `ChatStreamingMessage`(正文+状态+工具卡)。
- 工具/步骤卡:`ProjectChatToolCallCard.tsx`(已能渲染两种形态:`step_index` 存在 = 工作流步骤;否则 = 工具卡)。
- 持久化渲染:`ProjectChatMessageBubble.tsx` → `workflowStepsFromToolCalls(metadata.tool_calls)`(本轮已改为真实步骤)。
- Store:`chatStreamStore.ts`(`streamingContent/Status/ToolCalls/Steps/Artifacts/References`)。
- 后端事件:`agent_loop.py` 发 `text` / `tool_executing` / `tool_result` / `agent_step` / `status`;durable 任务发 `task_run`。
- Skill 身份:`runtime.skill_name` / `prepare_metrics.effective_skill_name`,**仅持久化进 metadata,未在流式发出**。

## 2. 统一数据模型:ActivityTimeline

一个规范化结构,**流式与持久化共用同一渲染**:

```ts
type ActivityStatus = "pending" | "running" | "completed" | "error" | "confirmation_required";

interface ActivityItem {        // 时间线里的一个"工具/子动作"
  tool_name: string;            // 显示名(复用 readableToolName)
  status: ActivityStatus;
  message?: string;
  details?: string[];
  artifact?: GeneratedArtifact;
}

interface ActivityStep {        // 一个步骤(harness 的一格)
  index: number;
  title: string;                // 步骤标题
  status: ActivityStatus;
  duration_ms?: number;
  items: ActivityItem[];        // 该步下的工具调用
  truncated?: boolean;
}

interface ActivityTimeline {
  skill?: { name: string; id?: string };   // 顶部 Skill 横幅(有才显示)
  steps: ActivityStep[];
  artifacts: GeneratedArtifact[];           // 收尾交付物
  kind: "chat" | "durable_task";            // 来源(影响标题策略)
}
```

### 事件 → 时间线映射(流式)
- `skill_active`(**新增**,见 §4):设 `timeline.skill`。
- `tool_executing` / `tool_result`:upsert 一个 `ActivityItem` 到「当前步骤」。
- `agent_step`(序号/tool_names/耗时/截断):**封口当前步骤**(标记 completed、写 duration),开启下一步。即工具先实时出现在"进行中"的步骤里,`agent_step` 到达时把这一步定格。
- `task_run`(durable):用 `workflowStepsFromTask` 已有逻辑,把 TaskRun 的步骤直接灌进 `steps`(kind="durable_task")。
- 文本正文:仍由 `MarkdownRenderer` 流式渲染,在时间线**上方**。

### 步骤标题策略
- **chat 回合**:`agent_step` 只有 `tool_names`,没有人类标题 → 标题用 `根据 tool_names 生成`(如「读取项目文档、读取项目文件」)或退化为「第 N 步」。
- **durable 任务**:TaskRun 自带 `step_title`(收集上下文/生成大纲/…),直接用。

### 持久化(刷新后)
- 从 `message.metadata` 读:`steps`(若已序列化 agent steps)/ `tool_calls`(经 `workflowStepsFromToolCalls`)/ `skill_progress` / `task_run`,组装成同一个 `ActivityTimeline`,**与流式同一组件渲染**,保证直播和刷新一致。

## 3. 组件设计

```
ProjectChatActivityTimeline({ timeline, isZh, onOpenTasks, onOpen/DownloadArtifact })
├── SkillBanner(timeline.skill)            // 有 skill 才渲染
├── steps.map(ActivityStepRow)             // 复用/抽取自 ProjectChatToolCallCard
│     └── items.map(ActivityItemRow)        // 子工具行
└── artifacts.map(ProjectChatArtifactCard) // 已有组件
```

- 复用现有 `ProjectChatToolCallCard` 的视觉(它已支持 step 形态),抽出"步骤 + 子项分组"的容器即可,不重造样式。
- **默认折叠**为一行摘要(「✓ 3 步 · 已生成 X.pptx」),点击展开看每步日志(沿用现有"收起日志"交互)。
- `ChatStreamingMessage` 与 `ProjectChatMessageBubble` 都改为:正文 + `<ProjectChatActivityTimeline timeline={...} />`。

## 4. 后端改动(阶段 1 唯一后端改动,极小)

流式时发一次 Skill 身份事件,供顶部横幅:
- 位置:`agent_loop.run_agent_loop` 开头(或 runtime 准备后),若 `runtime.skill_name` → `yield sse_event({"type": "skill_active", "skill_name": runtime.skill_name, "skill_id": effective_skill_id})`。
- 前端 `useProjectChatComposer` 加 `skill_active` 分支 → `setStreamingSkill(...)`;store 加 `streamingSkill` 字段。
- 持久化侧已有 `metadata.skill_progress` / `effective_skill_name`,直接读。

> 不动路由、不动策略、不动生成逻辑——纯展示增量。

**贯穿(harness 模式)**:多步任务顶部可加一条 todo/计划条(已知步骤总数时显示"第 N / M 步")。
