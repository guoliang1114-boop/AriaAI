# 下一版本迭代计划

创建日期：2026-04-20
更新日期：2026-04-21

## 1. 版本目标

下一版本建议命名为 `vNext 工作流闭环与治理强化`。

版本目标不是继续堆单点功能，而是把已经落地的 AI 能力组织成更稳定、更可运营的业务闭环：

- Skill 从“可选模板”升级为“项目/客户空间动作”。
- 记忆从“可生成”升级为“可治理、可回滚、可审计”。
- 客户侧干系人从“文本备注”升级为“结构化关系资产”。
- Welcome 和项目概览从“信息展示”升级为“今日工作起点”。
- 运维从“出错后看日志”升级为“任务面板可定位、可建议、可处理”。

## 3. Sprint 1：Skill 工作流化

目标：让 Skill 真正进入项目/客户空间，而不是只存在于 Skill 列表或聊天里的选择器。

### 任务 1：项目空间启动 Skill

用户故事：

- 作为项目负责人，我在项目详情页可以直接选择一个 Skill，并让它基于当前项目上下文执行。

建议范围：

- 在项目 Chat 或 Overview 增加“使用 Skill”入口。
- 启动前显示当前将带入的上下文：
  - 项目记忆版本
  - 客户名称
  - 文件数量
  - 未完成待办
  - 里程碑
- 执行时默认带入项目 memory 和知识范围。

验收标准：

- 从项目页可选择 Skill。
- Skill 输入区自动预填项目上下文提示。
- 执行结果仍走现有聊天/结果展示链路。

### 任务 2：客户空间启动 Skill

用户故事：

- 作为客户负责人，我在客户空间可以让 AI 基于客户记忆生成关系策略、复盘、沟通建议或机会分析。

建议范围：

- 在客户详情或客户 Memory 页增加 Skill 入口。
- 默认带入客户记忆、关联项目、最近客户摘要。
- 支持快速切换 Skill 类型。

验收标准：

- 从客户页可选择 Skill。
- Skill 执行能感知客户名称和客户记忆。
- 执行结果可保存或继续追问。

### 任务 3：Skill 结果回流

用户故事：

- 作为顾问，我希望 Skill 输出不是一次性内容，而是能沉淀为项目/客户资产。

建议保存目标：

- 保存为项目文档。
- 保存为项目笔记。
- 保存为项目记忆 pinned 槽位。
- 保存为客户记忆沉淀。

验收标准：

- 至少完成“保存为项目文档”和“保存为项目笔记”。
- 保存后提示是否刷新项目记忆。
- 保存动作失败时有明确错误提示。

## 4. Sprint 2：记忆治理产品化

目标：让记忆系统具备更强的运营、审计和恢复能力。

### 任务 1：服务端失败统计接口

当前 Memory Operations 里有前端兜底分类。下一步建议由服务端提供聚合统计，减少前端推断。

建议接口：

- `GET /memory/operations/summary`
- 返回：
  - 按 scope 聚合：project / client
  - 按 category 聚合
  - 最近失败
  - 重试中任务
  - 预算状态
  - 需要人工处理数量

验收标准：

- 前端告警汇总不再完全依赖本地推断。
- database/data/unknown 能明确标记为 manual attention。

### 任务 2：Memory Operations 批量治理

建议范围：

- 失败记录多选。
- 批量重试。
- 批量忽略。
- 批量打开。
- 对 database/data/unknown 批量重试前要求确认。

验收标准：

- 可同时选择多条失败记录。
- 可批量处理 timeout/rate_limit/llm 类失败。
- 高风险失败不能误触重试。

### 任务 3：记忆历史版本设计

建议先设计，再实现。

候选表：

- `memory_snapshot`
- 字段：
  - `id`
  - `scope`
  - `entity_id`
  - `memory_version`
  - `payload_json`
  - `trigger`
  - `source`
  - `created_at`
  - `created_by_user_id`

验收标准：

- 形成迁移草案。
- 明确项目记忆与客户记忆共用还是分表。
- 明确回滚行为是否触发摘要缓存失效。

## 5. Sprint 3：今日工作起点

目标：让用户打开 AriaAI 后，马上知道今天要处理什么。

### Welcome 强化

建议模块：

- 今日到期 / 即将到期待办。
- 即将到期里程碑。
- 最近失败任务。
- 最近生成物。
- 最近活跃项目。
- 高风险项目记忆摘要。

验收标准：

- Welcome 首屏不只是入口，而能给出 3-5 个明确行动。
- 点击行动能直接进入项目、客户、任务面板或生成物。

### 项目概览强化

建议模块：

- 当前项目目标。
- 最新项目记忆摘要。
- 风险与开放问题。
- 下一步行动。
- 最近生成物。
- 客户记忆沉淀状态。

验收标准：

- Overview 能回答“这个项目现在最该做什么”。
- 可一键进入 Chat、Memory、Todos、Documents。

## 5A. Sprint 3.5：客户侧干系人结构化

目标：把当前客户侧干系人从 `client.contact` 文本线索和客户记忆 `key_contacts`，升级为可维护、可分析、可视化的结构化关系资产。

建议范围：

- 设计 `client_stakeholder` 表或客户记忆内结构化 schema。
- 字段建议：
  - 姓名
  - 角色
  - 组织层级
  - 影响类型
  - 关系状态
  - 关注点
  - 敏感点
  - 沟通偏好
  - 联系方式
  - 最近跟进动作
- 干系人页支持新增、编辑、删除、标记影响力。
- 关系图支持按决策、使用、采购、财务、法务、IT、安全等角色分类展示。

验收标准：

- 干系人页不再只依赖自由文本。
- AI 摘要和客户记忆能读取结构化干系人信息。
- 页面能回答“下一步应该找谁确认什么问题”。

## 7. 推荐开工顺序

1. 抽通用服务错误态组件，复用到 Welcome、ProjectDetail 等页面。
2. 拆 `ProjectStakeholdersTab.tsx`，为结构化干系人做组件边界。
3. 项目空间启动 Skill。
4. Skill 结果保存为项目文档/笔记/锚点。
5. 客户空间启动 Skill。
6. 客户侧干系人结构化 schema。
7. 服务端 Memory Operations summary 接口。
8. Memory Operations 批量治理。
9. 记忆历史版本设计。
10. Markdown/XSS 安全复核。

## 8. 每轮提交要求

- 小步提交，一个提交只解决一个闭环。
- 前端改动至少跑 `npm run build`。
- 后端迁移/治理改动至少跑相关 `py_compile` 和定向单测。
- 涉及迁移必须更新 `POSTGRESQL.md` 或本计划。
- 涉及用户工作流必须更新对应 docs。
