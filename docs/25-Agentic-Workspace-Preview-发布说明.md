## 用户可见变化

- 新版知识源支持可选的本地中文语义 embedding 与词法混合检索。同义表达可以召回资料；旧哈希向量不会被当成语义向量。默认仍为 `hash`，启用和重建流程见 [语义检索指南](24-知识语义检索与质量验收.md)。
- 同一显式资料范围的“这有什么依据”“那怎么实施”等受限追问可以补充最近用户主题。资料移除、换范围、元数据失效或新增写指令会中止继承，引用重新授权。
- 相同 Markdown 完整正文不再因文件工具回传而重复内联。不同数字、部分重叠与新段落保留，文件、审批和工具结果回执不丢失。
- Claude SDK/HTTP、Kimi、DeepSeek、BigModel、MiMo 均接入真实流阶段观测。隐藏思考也会关闭安全重试窗口；无进展超时和取消不重发模型请求。
- Skill 包补齐合成交付场景和验证材料。示例是测试输入与预期判断，不能视为真实客户案例或已完成业务验收。
- 前端设置页、个人偏好、周计划、分页与 Context 模块清理 lint 和生命周期问题，保留现有交互。发布检查要求零 lint 警告。
- 记忆运维页读取不再隐式安排客户记忆重建或清除失败时间；缺失的 queued/rebuilding 任务保留状态提示，恢复需使用原生写操作。

## 延迟诊断接口

管理员只读 `GET /chat/diagnostics/latency?days=7&limit=5000`，在生产 API 基址下为 `/api/chat/diagnostics/latency`。鉴权使用原生 `X-Auth-Token`，不能把 token 放在 URL 中。

| 字段 | 含义 |
| --- | --- |
| `days` / `sample_limit` | 近期 1–90 天，最近 1–10000 次 Run，默认 7 天 / 5000 次 |
| `run_count` / `truncated` | 实际采样数量，以及是否还有未纳入的较早 Run |
| `outcomes` | 实际 Run 状态计数，等待确认、失败、取消与成功分别统计 |
| `groups` | 按模型及状态分组的 `run_count` 和 `metrics` |
| `sample_count` / `p50_ms` / `p95_ms` | 每项指标独立计算有效样本与 nearest-rank 分位数；缺失值返回 null |

计时包括 `provider_headers_ms`、`provider_reasoning_ms`、`provider_text_ms`、`provider_tool_ms`、`model_first_event_ms`、`bounded_answer_ready_ms`、`total_stream_ms`、`run_duration_ms`。Provider 阶段是首个请求开始后的时刻，不能相加；后续重试或修正不会补进首个请求缺失的正文计时。Run 耗时可包含多步骤与工具等待，不能解释为纯模型生成耗时。

报表仅选取原生 ChatRun/ChatTrace 的模型、状态与计时列，不返回正文、思考、Prompt、来源、会话身份或原始 metadata。普通成员被拒绝；非法或缺失计时不混入有效分位数。报表不修改业务状态。

## 运维复核与剩余限制

2026-09-22 知识入库增量已随 `33df8e3` 发布：补齐 Word 表格、PPT 组合图形/表格/备注、完整 PDF/Excel 文本入库及超限显式失败；服务器 1,512 项、前端 693 项回归通过。支持范围、用户路径、实际资料副本结果和生产限制见 [29 验收](29-知识入库与真实资料验收.md)。扫描件 OCR 和复杂图表视觉理解不包含在本次文本入库范围。

2026-09-19 的已部署基线只读报告显示：1 份旧知识文档已经完成新版映射，新版有 14 个分块，cutover ready 为 true；旧 reader fallback 和显式旧库选择仍开启。映射就绪不等于可以删除旧库或禁用兼容入口，仍需验证历史会话/显式选择与回滚行为。

同次报告中，33 个项目有 24 个 stale 槽位，18 个客户有 16 个 stale 槽位；项目、客户各有 2 份原生 last_failure 状态。聚合记忆运行时回退已关闭，原生运维状态无缺失或分歧。这些是历史观测数量，需要在执行前重新读取，不能推断失败原因或宣称已修复。

处理入口为管理端记忆运维页和现有 `/projects/{id}/memory/status`、`/clients/{id}/memory/status`。核对 actor、对象、数据版本和失败原因后，通过原生 `/projects/{id}/memory/rebuild` 或 `/clients/{id}/memory/rebuild` 发起相应操作；AI 发起的 consequential writes 继续经过 HITAS 与最终授权。保留失败历史与快照，不直接清空标志、改聚合 JSON 或绕过审计。旧 GET 隐式恢复曾触发客户 3、4 的失败重建，现已修复；线上确认两者仍保留原版本与失败时间，读取不再安排任务。详见验收记录中的副作用说明。

一般语义指代、大规模真实语料质量、全站端到端 P50/P95、所有 Skill 的业务效果和 native pgvector 部署矩阵仍不由这批小样本验收覆盖。本机语义查询是在模型预热后运行，不包含权重下载。不同 Provider 的实测表现仍需按新部署版本采样。
