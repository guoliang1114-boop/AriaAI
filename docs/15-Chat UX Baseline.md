# Chat UX Baseline

> 生效日期：2026-05-20
> 适用范围：`aria-web/src/pages/projects/` 项目对话、`AriaAI/backend/app/services/chat/` 流式事件、任务编排与交付物展示。

## 目标

Chat 页面必须让用户清楚知道三件事：

1. 我的消息已经被收到。
2. AI 正在做什么，以及是否进入了可恢复任务。
3. 最终答复、步骤、工具和交付物分别是什么。

任何修复都不能把后端内部事件、调试状态或路由判断直接摊到聊天主体里。

## 展示分层

### 1. 轻量状态

以下状态只允许显示为当前回复下的一行轻量提示：

- `prepare`
- `thinking`
- `planning`
- `saving`
- `finalizing`
- 其他没有 `step_index` 的普通 `status` 事件

它们不能被渲染成工具卡片、任务卡片或交付物卡片。

推荐文案：

- `prepare`：正在整理项目上下文。
- `thinking`：正在理解你的需求。
- `planning`：正在判断是否需要调用工具。
- `saving`：正在保存本次回复。

不推荐展示：

- 已加载 3 个工具。
- Router 正在判断 direct/task/artifact。
- 模型仍在生成中，请稍候。
- 内部阶段名、函数名、调试 payload。

### 2. 编排步骤卡片

只有满足以下条件的事件才能展示为步骤卡片：

- 有明确 `step_index`。
- 有 `step_total` 或能从任务步骤推导。
- 表示用户可理解的任务阶段。

示例：

- 步骤 1/4：收集项目上下文
- 步骤 2/4：生成结构化大纲
- 步骤 3/4：执行 Skill / 工具
- 步骤 4/4：整理结果与链接

步骤卡片必须支持展开/收起日志。失败步骤必须说明下一步可做什么；只有存在真实 `TaskRun` 时才允许显示“打开任务面板处理”。

### 3. 工具调用卡片

只有真实工具调用才能展示为工具卡片，例如：

- `read_project_markdown_document`
- `write_project_office_document`
- `update_project_markdown_document`

工具卡片不负责展示普通状态进度。工具失败时必须显示具体错误和用户可采取的动作。

### 4. 交付物卡片

所有交付物统一使用文件卡片，不按文件类型单独写 UI 逻辑。

支持范围：

- Markdown：`md`
- Text：`txt`
- Word：`docx`
- PowerPoint：`pptx`
- Excel：`xlsx`
- PDF：`pdf`

卡片必须支持：

- 打开
- 下载
- 与项目空间中的文件逻辑一致

## 路由与编排基线

### 直接回答

满足以下情况时应直接回答，不应进入交付物任务：

- 用户要求简短摘要、判断、建议、解释。
- 用户没有要求“保存 / 导出 / 生成文件 / 生成 PPT / 生成 Excel / 生成 MD”。
- 用户明确要求基于结构化记忆做 5 条以内概览、风险判断、下一步建议。

### 可恢复任务

满足以下情况时应进入任务编排：

- 用户要求生成文件或交付物。
- 用户要求多步骤执行、可追踪进度或稍后查看。
- 操作需要写入项目空间或修改项目文档。
- 操作失败后需要从失败步骤重试。

### Skill / 工具

Skill 调用必须处于某个用户可理解的步骤中，不能孤立出现在聊天流里。

## 必须测试的回归场景

每次修改项目 Chat 功能，至少覆盖以下基线：

1. 普通 `status` 事件不会生成工具/任务卡片。
2. 有 `step_index` 的状态会生成步骤卡片。
3. 工具失败但没有 `TaskRun` 时，不显示“打开任务面板处理”。
4. 有真实 `TaskRun` 的失败步骤，才显示任务面板入口。
5. 交付物卡片对 `md/txt/docx/pptx/xlsx/pdf` 走同一套打开/下载逻辑。
6. 直接摘要类请求不会生成文件。
7. 文件生成类请求必须展示交付物卡片。

## 前端验收标准

- 发送消息后 300ms 内有轻量反馈。
- 页面不出现一串“理解需求 / 规划执行 / 处理进度 / 保存结果”的状态卡片。
- 聊天主体最多包含：正文、步骤卡片、工具卡片、交付物卡片。
- 刷新页面后，已持久化的最终回复和交付物仍能恢复。

## 后端验收标准

- SSE 事件必须明确区分普通状态、步骤状态、工具事件、交付物事件。
- 普通状态事件不得携带让前端误判为步骤或工具的字段。
- `done/error/truncated` 事件必须可靠 flush。
- 路由决策日志进入后端日志或任务详情，不默认展示在聊天主体。
