# 项目记忆架构与落地进度
更新日期：2026-04-19

## 1. 目标

项目记忆系统的目标，不是每次都把全量上下文直接喂给模型，而是把业务事实沉淀成可复用、可缓存、可后台化的长期资产。

当前总体方向：
- 项目级三层记忆：原始业务上下文 -> 结构化项目记忆 -> 多视角摘要
- 客户级第四层记忆：跨项目沉淀客户经验、偏好和关系信号
- 后台化：把重建、预热、缓存、队列和状态可视化做成系统能力

## 2. 分层架构

### 第一层：原始业务上下文
来源包括：
- 项目基础信息、成员、状态、阶段
- 文档、里程碑、待办、财务、笔记
- 项目聊天与生成物
- 客户资料与关联项目

这一层是事实源，不直接面向最终页面展示。

### 第二层：结构化项目记忆
存储位置：
- `Project.context_memory_json`

核心字段：
- `project_brief`
- `current_stage`
- `current_objective`
- `recent_progress`
- `key_risks`
- `open_questions`
- `next_actions`
- `important_documents`
- `financial_status`
- `delivery_signals`
- `stakeholder_notes`
- `memory_version`
- `last_updated_at`
- `stale`
- `rebuild_log`
- `_coverage`

扩展能力：
- 部分槽位支持 `ai + pinned` 双层结构
- 支持 `memory_stale / memory_version / memory_updated_at`
- 支持 `memory_rebuild_status / memory_rebuild_failed_at`

### 第三层：项目视图摘要
基于结构化项目记忆生成，按视角缓存。

当前已支持视角：
- `overview`
- `risk`
- `stakeholder`
- `delivery`
- `client-facing`
- `financial`
- `documents`

缓存维度：
- `project_id + memory_version + summary_type + language`

### 第四层：客户记忆
存储位置：
- `ClientRecord.client_memory_json`

核心字段：
- `client_profile`
- `decision_patterns`
- `key_contacts`
- `lessons_learned`
- `project_history`
- `sensitive_topics`
- `source_project_ids`
- `memory_version`
- `last_updated_at`
- `stale`
- `rebuild_log`

作用：
- 为客户范围聊天提供长期上下文
- 为新项目提供更强起点
- 沉淀跨项目客户经验

## 3. 当前落地状态

### 3.1 项目记忆
已完成：
- 结构化项目记忆生成与存储
- `stale / version / updated_at` 状态管理
- 异步重建状态：`idle / queued / rebuilding / failed`
- 项目记忆批量重建
- 项目摘要缓存
- 常用摘要自动预热
- 项目记忆任务队列查看、取消、立即执行
- 项目详情独立 `Memory` 页面
- `Project Memory Manager`

当前已覆盖页面：
- Overview
- Chat
- Settings
- Memory
- Milestones
- Todos
- Notes
- Financials
- Documents

### 3.2 客户记忆
已完成：
- 客户记忆重建与持久化
- 项目记忆手动提升到客户记忆
- 项目归档后自动沉淀到客户记忆
- 客户范围聊天注入客户记忆
- 客户记忆批量重建
- 客户记忆批量摘要预热
- 客户详情记忆入口
- 客户详情独立 `Memory` 页面
- `Client Memory Manager`
- 客户记忆异步状态字段
  - `client_memory_rebuild_status`
  - `client_memory_rebuild_failed_at`
- 客户记忆后台重建排队
  - `stale -> queued -> rebuilding -> idle/failed`
- 客户记忆任务队列接口
  - 查看任务
  - 取消任务
  - 立即执行
- 常用摘要预热
  - `overview`
  - `stakeholder`
  - `lessons`

### 3.3 后台任务与预热
项目记忆当前已具备：
- debounce 重建
- 摘要自动预热
- 限流、防重、预算、退避重试基础能力

客户记忆当前已具备：
- 重建排队
- 异步状态可视化
- 队列管理接口
- 摘要批量预热
- 管理页自动触发常用摘要预热
- 重建完成后自动排队预热常用摘要

项目/客户统一后台任务系统，仍在后续阶段。

## 5. 未完成项

### 高优先级
1. 客户记忆更多视角摘要与缓存扩展
2. 项目/客户统一任务队列和统一监控
3. 客户记忆失败重试与预算治理进一步产品化
4. 项目归档自动沉淀后的结果可视化补强

### 中优先级
1. 槽位级增量更新，而不是整包重建
2. 独立 memory 主表与历史版本回滚
3. 更完整的预算、限流、失败重试和告警

## 6. 建议的下一步

### Sprint A
1. 给客户记忆补齐更多视角摘要和缓存
2. 在 `Client Memory Manager` 中补充更完整的任务结果与失败原因展示
3. 把项目归档自动沉淀的结果和来源覆盖显式展示给业务用户

### Sprint B
1. 项目/客户统一后台任务面板
2. 加入任务失败原因与重试记录
3. 补强预算、限流和告警策略

### Sprint C
1. 槽位级增量更新
2. 独立历史版本与回滚
3. 更强的运维与治理能力

## 7. 当前结论

一句话概括：
- 项目级三层记忆已经进入可用 V1
- 客户级第四层记忆已经进入系统化管理阶段
- 当前重点已经从“能生成”转向“能后台化、可复用、可运营”
