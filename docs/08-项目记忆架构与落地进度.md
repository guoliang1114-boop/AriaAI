# 项目记忆架构与落地进度
更新日期：2026-04-19

## 1. 目标

项目记忆体系的目标，不是每次都把全量上下文直接喂给模型，而是把业务事实沉淀成可复用、可缓存、可异步处理、可运营的长期资产。

当前总体方向：
- 项目级三层记忆：原始业务上下文 -> 结构化项目记忆 -> 多视角摘要
- 客户级第四层记忆：跨项目沉淀客户经验、偏好与关系信号
- 后台任务化：把重建、预热、缓存、队列和状态可视化做成系统能力

## 2. 分层架构

### 第一层：原始业务上下文
来源包括：
- 项目基础信息、成员、状态、阶段
- 文档、里程碑、待办、财务、笔记
- 项目聊天与生成物
- 客户资料与关联项目

这一层是事实源，不直接面向业务用户展示。

### 第二层：结构化项目记忆
存储位置：
- `Project.context_memory_json`

核心字段：
- `project_brief`
- `current_stage`
- `current_objective`
- `recent_progress`
- `key_risks`
- `open_questions`
- `next_actions`
- `important_documents`
- `financial_status`
- `delivery_signals`
- `stakeholder_notes`
- `memory_version`
- `last_updated_at`
- `stale`
- `rebuild_log`
- `_coverage`
- `_client_promotion`

扩展能力：
- `key_risks / open_questions / stakeholder_notes` 支持 `ai + pinned` 双层结构
- 支持 `memory_stale / memory_version / memory_updated_at`
- 支持 `memory_rebuild_status / memory_rebuild_failed_at`
- 已支持槽位级增量更新接口

### 第三层：项目视图摘要
基于结构化项目记忆生成，并按视角缓存。

当前已支持视角：
- `overview`
- `risk`
- `stakeholder`
- `delivery`
- `client-facing`
- `financial`
- `documents`

缓存维度：
- `project_id + memory_version + summary_type + language`

### 第四层：客户记忆
存储位置：
- `ClientRecord.client_memory_json`

核心字段：
- `client_profile`
- `decision_patterns`
- `key_contacts`
- `lessons_learned`
- `project_history`
- `sensitive_topics`
- `source_project_ids`
- `memory_version`
- `last_updated_at`
- `stale`
- `rebuild_log`

当前已支持视角：
- `overview`
- `stakeholder`
- `lessons`
- `client-facing`
- `risk`
- `opportunity`

作用：
- 为客户范围聊天提供长期上下文
- 为新项目提供更强起点
- 沉淀跨项目客户经验

## 8. 2026-04-19 补充更新

### 8.1 统一任务面板
- `Memory Operations` 已支持同时查看项目记忆与客户记忆任务。
- 面板现在可以直接展示：
  - `rebuild / summary_warm`
  - 重试次数与最大重试次数
  - 触发来源 `trigger`
  - 预热摘要类型 `summary_types`
  - 项目 / 客户两套摘要预热预算
  - 最近失败记录与失败阶段

### 8.2 失败记录与重试治理
- 项目记忆与客户记忆现在都会把最近一次失败写入记忆 JSON：
  - `_last_failure.stage`
  - `_last_failure.message`
  - `_last_failure.retry_count`
  - `_last_failure.failed_at`
- 项目记忆与客户记忆的重建任务都会带 `retry_count / max_retries` 元数据进入调度器。
- 摘要预热任务同样会记录失败并在统一任务面板可见。

### 8.3 Alembic 迁移治理
- `/health/db` 现在除了基础数据库健康状态外，还会返回更完整的迁移治理信息：
  - `mode`: `bootstrap / lightweight / alembic`
  - `current_revision`
  - `latest_revision`
  - `known_revisions`
  - `pending_revisions`
  - `pending_count`
- 新增独立接口：
  - `GET /health/db/migrations`
- 当前策略仍然是稳妥优先：
  - 已有 `alembic_version` 的库走 Alembic
  - 历史轻量库保留 additive startup migration
  - 暂不做危险的自动 stamp
