# Agentic Workspace 产品 Gap 分析

## 1. 核心判断

AriaAI 当前已经具备 Agentic Workspace 的基础能力，但仍处在“模块化 AI 工作台”阶段，还没有完全收拢成“目标驱动的咨询交付 Agent 系统”。

当前产品更像是：

```text
工作台 + 项目 + 客户 + 联系人 + Skill + 知识库 + 对话 + 记忆 + 文件/任务模块
```

目标形态应是：

```text
用户给出咨询目标
  -> Aria 自动组织上下文
  -> 形成计划
  -> 调用工具或 Skill
  -> 生成交付物
  -> 沉淀项目/客户/用户/知识记忆
  -> 推动下一步行动
```

最大 Gap 不是“功能少”，而是功能之间还没有形成统一的 Agent 工作循环。

## 2. 当前能力与目标形态的差距

### 2.1 当前已有能力

AriaAI 已经有很多 Agent 产品所需的基础零件：

| 能力 | 当前体现 |
|---|---|
| 项目承载 | 项目详情、项目空间、项目聊天、任务、里程碑、财务、记忆 |
| 客户承载 | 客户列表、客户详情、客户记忆、客户项目历史 |
| 联系人承载 | 联系人列表、联系人详情、客户干系人信息 |
| Skill 能力 | Skill 列表、Skill 详情、内置咨询 Skill、文件型 Skill 包 |
| 对话能力 | 通用 Chat、项目 Chat、流式输出、工具调用 |
| 工具与交付物 | 文档/PPT 生成、项目文档、项目笔记、文件上传 |
| 记忆系统 | 项目记忆、客户记忆、用户偏好记忆、记忆任务中心 |
| 知识库 | 知识库页面、知识库开发方案、知识源/文档/索引设计 |
| 可控执行 | HITAS、Action Preview、部分任务进度和 Trace |

这些能力说明 Aria 已经不只是一个聊天产品，而是具备 Agentic Workspace 的雏形。

### 2.2 当前主要缺口

当前缺口集中在四个方面：

1. **执行没有统一收口**：Chat、Skill、Task、Artifact、Memory Update 仍是分散链路。
2. **Skill 还不够交付物化**：许多 Skill 更像能力说明或提示词，不像端到端交付工作流。
3. **知识与记忆闭环未完全打通**：知识库、项目文件、客户记忆、项目记忆之间还没有形成稳定来源链。
4. **产品入口仍偏功能导航**：用户看到的是模块，而不是“我要完成什么咨询工作”。

## 3. 六层 Gap 分析

### 3.1 Harness / Run 运行层

#### 当前基础

- 项目对话已有流式回复、工具调用和部分任务进度。
- 后端已有 `tool_executor`、`task_orchestrator`、HITAS、pending action、trace、task run 等能力。
- 前端已有 `ProjectChatActivityTimeline`、`ProjectChatToolCallCard`、`ProjectChatTracePanel` 等组件。

#### Gap

| Gap | 影响 |
|---|---|
| 缺少统一 `Run / Step / Tool / Artifact / Memory Update / Approval` 模型 | 不同 AI 工作流无法统一展示、追踪、恢复 |
| Chat、Skill、Task、Artifact 保存逻辑分散 | 用户体验和工程边界容易不一致 |
| Product Event 与 Internal Trace 边界仍需收敛 | 普通问答容易暴露不必要的内部进度 |
| Run 失败恢复和状态闭环不完整 | 用户看到“闪现、消失、卡住”等不稳定体验 |

#### 补足方向

- 建立统一 AI Run Contract。
- 普通问答创建轻量 Run，复杂工作创建完整 Run。
- 后端统一输出 Product Run Event，前端不直接消费底层 tool log。
- 所有交付物、记忆候选、任务、确认动作都挂到同一个 Run。

#### 优先级

P0。它是后续 Skill、知识库、记忆和交付物闭环的底座。

## 3.2 咨询 Skill 交付层

### 当前基础

- 已有 DB Skill、文件型 Skill 包和大量咨询 Skill。
- Skill 可从项目/客户上下文启动。
- 部分 Skill 已能生成结构化内容或交付物。

### Gap

| Gap | 影响 |
|---|---|
| Skill 更像“能力/提示词”，不完全是“交付工作流” | 用户使用后不一定得到可交付成果 |
| 缺少 Skill 运行记录 | 无法追踪输入、上下文版本、输出、保存结果 |
| 缺少 Skill 版本和发布状态 | 难以管理方法论迭代和回滚 |
| 缺少交付物验证清单 | 输出质量依赖模型即时表现 |
| 缺少明确沉淀位置 | 结果不一定进入项目资产或客户记忆 |

### 补足方向

核心咨询 Skill 应从“prompt”升级为“交付物产品单元”，每个 Skill 至少定义：

- 使用场景。
- 输入资料。
- 分析框架。
- 输出交付物。
- 验证清单。
- 保存位置。
- 失败/信息不足时的降级策略。

### 优先补的 Skill 类型

| 类型 | 原因 |
|---|---|
| 会前准备 | 最贴近北极星场景 |
| 方案建议 | 高频咨询交付场景 |
| 风险分析 | 适合结构化输出和记忆沉淀 |
| 项目复盘 | 强化跨项目经验沉淀 |
| FDD / 技术会计 / PMO / 变革管理 | 更贴近四大基础能力 |

### 优先级

P0-P1。先选 5-8 个高价值 Skill 做深，不急着所有 Skill 同时升级。

## 3.3 记忆与知识库层

### 当前基础

- 已有项目记忆、客户记忆、用户偏好记忆。
- 已有客户、项目、联系人三个业务对象。
- 已有知识库页面和 v0.0.5 知识库方案。
- 项目记忆可以支撑项目对话、概览和简报。

### Gap

| Gap | 影响 |
|---|---|
| 知识库、项目文件、记忆之间的来源链不够稳定 | AI 结论可解释性不足 |
| 知识库功能仍在建设，测试存在失败 | 还不能作为稳定生产底座 |
| 联系人记忆与客户/项目记忆的联动还不够深 | 干系人洞察不能充分进入会前准备 |
| 用户记忆主要偏偏好层 | 尚未充分影响 Agent 工作方式 |
| 记忆更新缺少候选确认和来源审计闭环 | 容易产生“记忆污染”风险 |

### 补足方向

建立一条清晰闭环：

```text
知识/文件/聊天/业务动作
  -> 来源识别
  -> AI 使用并引用
  -> 形成候选记忆
  -> 用户确认或系统规则确认
  -> 写入项目/客户/联系人记忆
  -> 后续 Run 自动召回
```

### 关键原则

- 知识可以作为记忆来源，但不能自动污染记忆。
- 每条重要记忆应有来源、时间、触发动作和责任边界。
- 项目、客户、联系人和知识库应共享同一套权限判断。
- 知识库不是独立文档聊天工具，而是服务项目、客户、Skill 和交付物。

### 优先级

P0-P1。知识库和记忆闭环决定 Aria 的长期壁垒。

## 3.4 交付物工作流层

### 当前基础

- 项目空间支持文档、笔记和文件。
- Chat 结果可保存到项目文档或项目笔记。
- 已有 PPT/Office 文档生成工具。
- 项目页已有任务、里程碑、财务、文档、记忆等模块。

### Gap

| Gap | 影响 |
|---|---|
| 交付物生成和项目资产管理仍偏分散 | 用户需要在多个 tab 中自行组织结果 |
| AI 产出后不总是自然转成项目资产 | “回答”没有稳定变成“交付” |
| 缺少端到端咨询工作流模板 | 用户看到功能，不一定知道如何完成工作 |
| 交付物与 Run、上下文版本、来源引用关联不足 | 后续复用和审计能力弱 |

### 补足方向

优先做端到端工作流，而不是继续堆单点功能：

| 工作流 | 应包含 |
|---|---|
| 会前准备 | 客户背景、关键人、历史经验、风险提醒、会议议程、待确认问题 |
| 方案生成 | 目标定义、现状判断、方案路径、收益假设、风险、下一步 |
| 风险分析 | 风险清单、影响评估、证据来源、缓解动作、责任人 |
| 项目复盘 | 项目成果、踩坑、客户偏好、复用模板、后续机会 |
| 客户机会分析 | 历史项目、联系人状态、业务痛点、潜在服务机会 |

### 优先级

P1。需要在 Run 和 Skill 收敛后逐步产品化。

## 3.5 质量与可控性层

### 当前基础

- 已有 HITAS、Action Preview、pending action。
- 已有 Trace 和部分 Activity Timeline。
- 已有前后端测试体系。
- 后端覆盖率较高，前端已有基础覆盖。

### Gap

| Gap | 影响 |
|---|---|
| 缺少交付物 QA 流程 | 生成内容质量无法稳定达标 |
| 缺少统一引用来源标准 | 用户难判断结论可信度 |
| Run 失败恢复、回滚和重试策略不完整 | 长任务和写入动作不够可控 |
| Skill golden cases 不足 | 方法论升级难以评估效果 |
| 前端项目页/对话页覆盖率偏低 | 高频核心体验回归风险大 |

### 补足方向

- 建立核心 Skill 的 golden case 测试集。
- 对会前简报、方案、风险分析、PPT/Word 输出增加 QA checklist。
- 对重要写入和记忆更新支持回滚。
- 对复杂 Run 增加失败恢复和用户可理解状态。
- 把引用来源作为知识库、记忆和交付物的共同标准。

### 优先级

P1。质量层会决定用户是否敢把真实工作交给 Aria。

## 3.6 产品形态层

### 当前基础

- 顶部导航已有工作台、对话、Skill、项目空间、客户、联系人、知识库。
- 项目详情页模块完整。
- 客户与联系人页面已开始重构为更专业的业务界面。

### Gap

| Gap | 影响 |
|---|---|
| 导航仍偏功能模块 | 用户先看到“功能”，不是“我要完成什么” |
| 工作台任务导向还不够强 | Agentic Workspace 的价值没有第一屏显性表达 |
| 项目页 tab 很多，工作流入口不够聚焦 | 用户需要自己判断下一步去哪里 |
| Skill、知识库、记忆、交付物之间缺少统一启动入口 | 产品像一组模块，而不是一个 Agent 系统 |

### 补足方向

产品入口应从“模块导航”逐步升级为“咨询目标入口”：

| 当前入口 | 建议增强 |
|---|---|
| 工作台 | 今日该推进什么、准备哪场会议、哪个客户有风险 |
| 项目页 | 准备会议、生成方案、风险分析、复盘项目、沉淀客户经验 |
| 客户页 | 识别机会、准备拜访、查看关系风险、复用历史案例 |
| Skill 页 | 从 Skill 市场转向“交付物能力库” |
| 知识库 | 从文件管理转向“团队经验资产” |

### 优先级

P1-P2。产品形态升级应跟随 Run、Skill 和知识闭环逐步落地。

## 4. 最关键的 4 个优先补足项

### 4.1 统一 Run 模型

这是最大底座 Gap。没有统一 Run，Chat、Skill、Task、Artifact、Memory 仍会各自为政。

交付目标：

- 每次 AI 工作都有 run id。
- Run 能记录 step、tool、artifact、memory candidate、approval。
- 前端能用统一组件展示复杂任务进度。
- 普通问答保持轻量，不展示内部细节。

### 4.2 核心 Skill 交付物化

先选少数高价值 Skill 做深，而不是平均升级所有 Skill。

交付目标：

- 每个核心 Skill 有输入清单、输出标准、验证清单。
- Skill 输出默认建议保存到项目资产。
- Skill run 可追踪上下文版本和生成结果。
- Skill 产出能形成候选项目/客户记忆。

### 4.3 知识库与记忆闭环

这是 Aria 的组织壁垒。

交付目标：

- 知识检索结果可引用。
- AI 回答能展示来源。
- 重要结论可进入候选记忆。
- 用户确认后沉淀到项目/客户/联系人记忆。

### 4.4 工作台/项目页变成咨询任务入口

这是产品形态 Gap 的核心。

交付目标：

- 工作台展示“今日该完成什么咨询任务”。
- 项目页提供明确任务入口：会前准备、方案生成、风险分析、复盘项目。
- 用户不需要理解所有模块，也能完成一条完整工作流。

## 5. 分阶段路线建议

### Phase 1：收口执行底座

- 定义 AI Run Contract。
- 项目对话、Skill、长任务统一挂到 Run。
- Activity Timeline 消费 Product Run Event。
- 普通问答隐藏内部工具细节。

### Phase 2：做深核心咨询 Skill

- 选 5-8 个四大/咨询核心 Skill。
- 补输入、输出、验证、沉淀、失败策略。
- 建立 Skill run 记录和 golden cases。

### Phase 3：打通知识库和记忆

- 知识来源可引用。
- 记忆候选可确认。
- 客户、项目、联系人记忆联动。
- 知识库服务 Skill 和交付物，而不是只做文档问答。

### Phase 4：产品形态升级

- 工作台升级为咨询任务入口。
- 项目页突出“下一步 Agent 工作”。
- 客户页突出“关系判断、机会、风险和复用经验”。
- Skill 页升级为交付物能力库。

## 6. 判断总结

AriaAI 当前不是方向错误，而是处在从“模块化 AI 工作台”向“咨询交付 Agent 系统”过渡的中间态。

已经具备的优势：

- 业务对象完整：项目、客户、联系人、Skill、知识库、记忆。
- 对话和工具链已有可运行基础。
- 项目和客户上下文已经形成差异化。
- 文档和交付物能力已有雏形。

最需要补的不是更多页面，而是让这些能力形成闭环：

```text
目标驱动
  -> 统一 Run
  -> 上下文组织
  -> Skill / Tool 执行
  -> 交付物生成
  -> 记忆沉淀
  -> 下一步行动
```

当这个闭环跑通后，Aria 才会真正从“有 AI 的项目/客户工作台”升级为“专业咨询顾问的 Agentic Workspace”。
