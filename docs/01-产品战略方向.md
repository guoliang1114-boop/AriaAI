# AriaAI 产品战略方向

> 更新日期：2026-05-31  
> 关联文档：[00-项目总览](./00-项目总览.md)

## 1. 核心判断

AriaAI 不应把自己定义为“AI 协作工作台”或“更懂咨询的 ChatGPT”。这些表达会把产品拖入通用 AI 工具竞争，而通用 AI 厂商正在快速补齐文档问答、个人记忆、文件夹上下文和多模态生成。

AriaAI 真正有机会建立壁垒的地方，是咨询团队的客户关系智能：

- 客户关系不是事实列表，而是长期互动中形成的判断。
- 咨询项目不是孤立文件夹，而是客户关系资产的一次增量。
- 顾问经验不应停留在个人脑子里，而应成为团队可继承的组织记忆。
- 有价值的上下文常常在更新项目、记录会议、维护干系人、生成交付物时产生，而不是只在聊天框里产生。

一句话定位：

> AriaAI 是咨询团队的客户关系智能系统：它把每一次项目交互、干系人观察和交付经验沉淀成可复用的客户上下文，让下一次见客户时 AI 已经知道该说什么、该避什么、该推进什么。

从 Agent 产品视角看，这个定位可以进一步表达为：

> AriaAI 是面向专业咨询顾问的 Agentic Workspace。它不是通用 Agent 开发平台，也不是单纯聊天助手，而是把客户、项目、知识、Skill、交付物和记忆组织成一套可追踪、可复用、可沉淀的咨询交付 Agent 系统。

这一定调带来三个产品边界：

- 用户来到 Aria，不是为了配置 Agent，而是为了完成咨询工作。
- Aria 的 Agent 能力不追求通用自动化，而追求咨询交付链路的确定性、上下文深度和交付质量。
- 底层模型、SDK 或托管 Agent 能力可以替换，但客户关系、项目记忆、知识资产、咨询 Skill 和交付物标准必须由 Aria 掌握。

## 2. 不要竞争的领域

这些方向会被大厂快速解决，不应成为 AriaAI 的主战场：

| 领域 | 原因 |
|---|---|
| 通用文档问答 | 模型厂商和办公套件会持续强化 |
| 个人偏好记忆 | ChatGPT/Claude 等个人记忆会越来越好 |
| 单文件夹项目上下文 | 通用 AI Projects 已经覆盖基本体验 |
| 通用写作和总结 | 没有垂直上下文壁垒 |
| 单次交付物生成 | 模型能力提升会降低差异化 |

这些能力仍然要做，但只能作为基础设施，不是护城河。

## 3. 应该押注的领域

### 3.1 关系性判断

“张总对价格敏感”是一条事实；“张总真正担心的是向上汇报时缺少依据，下次应先给他一个可讲清楚的收益逻辑”是关系判断。

后者来自长期互动、会议反馈、项目推进和团队观察。通用 AI 很难凭一个文件夹自动形成这种判断，因为它缺少业务对象、项目阶段、干系人状态和组织协作场景。

### 3.2 组织记忆

客户属于公司，不属于某个顾问账号。AriaAI 应该帮助团队做到：

- 新顾问接手项目时继承客户背景。
- 不同顾问对同一客户的观察可以汇总。
- 客户跨项目经验可以复用。
- 离职、换岗、项目移交不会让上下文断裂。

### 3.3 跨项目经验沉淀

同一客户的多个项目之间必须互相学习：

- 第一期项目的踩坑应影响第二期的风险提示。
- 已验证有效的沟通策略应进入客户记忆。
- 历史交付物、承诺和决策链应成为新项目起点。

### 3.4 行为触发捕获

系统应在业务行为发生时捕获上下文：

- 新增或修改干系人。
- 完成里程碑或待办。
- 上传、生成或删除交付物。
- 聊天中出现客户偏好、敏感点、决策模式。
- 项目归档或阶段切换。

如果所有记忆都依赖用户手动点击“刷新”，产品只是在换一种方式做笔记。

## 4. 北极星场景

顾问在客户会议前 30 秒打开 AriaAI，应看到一张可直接行动的会前卡：

```text
客户：某集团
项目：数字化转型二期

关键人：
- 张总：决策人，关注向上汇报依据，对价格细节敏感。
- 李总监：业务侧推动者，关注效率和落地节奏。
- 王经理：采购流程节点，关注合规和材料完整性。

建议说什么：
- 先用量化收益解释本阶段价值。
- 把一期开销和二期预算的边界讲清楚。

避免什么：
- 不在全体会上展开价格细节。
- 不承诺超出当前范围的系统改造。

必须确认：
- 安全合规问题是否已由客户内部确认。
- 下一阶段决策会是否已有时间窗口。

历史经验：
- 一期延期来自业务侧频繁变更，本期需要提前锁定变更流程。
- 客户内部决策链长，方案变更至少提前三周预警。
```

这个场景需要项目记忆、客户记忆、结构化干系人、待办、里程碑、文档和聊天历史共同支撑。它不是 CRM、Notion 或通用 AI 单独能自然完成的任务。

## 5. 产品原则

### 5.1 场景深于功能全

优先回答“会议前 30 秒还缺什么”，而不是“还能加什么功能”。项目、客户、Skill、RAG、对话、审批都应服务于客户关系智能和交付闭环。

### 5.2 默认沉淀

每次使用都应让系统变得更懂客户：

- Chat 结果可保存为项目笔记或项目文档。
- Skill 输出可沉淀为项目资产。
- 项目记忆可提升到客户记忆。
- 干系人候选可从聊天和文本中识别。
- 关键工具动作应触发记忆 stale 标记。

### 5.3 先确定性，后智能化

确定性聚合先于 AI 生成。会前简报、项目概览、任务面板和 HITAS 都应先有可解释、可回退、可审计的 deterministic 版本，再叠加 AI refine。

### 5.4 低摩擦捕获

维护客户关系上下文不能靠长表单。系统应优先从用户已经在做的事情里提取信息，再让用户确认。

### 5.5 团队共享

组织记忆必须具备来源、权限、责任和继承机制。个人观察可以贡献到团队资产，但敏感操作和删除动作必须可追踪。

### 5.6 少配置，多完成工作

Aria 不应把主要体验做成“搭建 Agent”。顾问用户更需要的是系统自动带入客户、项目、历史案例、团队知识和当前任务，直接完成会前准备、方案建议、风险分析、交付物生成和项目复盘。

产品设计应优先提供内置高质量咨询 Agent / Skill，而不是让用户从空白配置开始。

### 5.7 可追踪的 Agent 循环

一次 AI 工作不应只是一段回复，而应形成闭环：

```text
目标 → 上下文 → 计划 → 工具执行 → 交付物 → 记忆沉淀 → 下一步行动
```

这个循环是 Aria 从“AI 功能集合”升级为“咨询交付 Agent 系统”的核心。

## 6. 当前代码对战略的支撑

| 战略能力 | 当前代码支撑 | 差距 |
|---|---|---|
| 项目上下文 | 项目详情、文件、待办、里程碑、财务、笔记、聊天 | 仍需更强的行为触发更新 |
| 客户长期记忆 | `ClientRecord.client_memory_json`、客户摘要、项目记忆提升 | 自动捕获仍不够 |
| 结构化干系人 | `ClientStakeholder`、候选识别、历史表、上下文注入 | 来源追踪和时间趋势可加强 |
| 会前简报 | `/projects/{id}/briefing`、AI refine、前端 Briefing Tab、`Consulting Turn Frame` | 来源引用和自动行动剧本仍可加强 |
| Skill 交付 | DB Skill、文件包 Skill、自动 Skill 路由、生成物保存 | 版本、运行记录、验证闭环未完善 |
| 风险治理 | HITAS、Action Preview、批次审批、reaper | 低风险自动批准策略可探索 |

### 6.1 对话能力的技术取向

AriaAI 可以学习 Codex 的 Agent 引擎，但不应学习 Codex 的产品赛道。当前对话系统的技术方向是：

- `IntentRouter` 判断 mode、权限和副作用边界。
- `Consulting Turn Frame` 判断咨询业务场景，例如会前简报、提案、风险诊断、干系人判断、会议智能。
- `Skill Router` 把明确的咨询工作流自动接到组织方法论，而不是只依赖用户手动点击。
- `P0-P4` 执行 observe -> reason -> act -> verify，但所有动作受 HITAS 和 ActionPolicy 控制。

战略边界：技术上追求 Codex-level Agent，产品上坚持客户关系智能系统。聊天不是目的，聊天应成为客户记忆、项目上下文、咨询方法论和交付物生产之间的统一入口。

### 6.2 Agentic Workspace 的六层能力

围绕“咨询交付 Agent 系统”这一方向，后续产品建设应收敛到六层能力：

| 层级 | 目标 | 当前基础 | 需要补足 |
|---|---|---|---|
| Harness / Run 运行层 | 让每次 AI 工作可追踪、可恢复、可审计 | 对话 runtime、tool executor、task orchestration、HITAS | 统一 `Run / Step / Tool / Artifact / Memory Update / Approval` 模型 |
| 咨询 Skill 交付层 | 把方法论变成交付物能力 | DB Skill、文件型 Skill 包、顾问能力目录 | 每个 Skill 明确输入、判断逻辑、交付物、验证清单和沉淀位置 |
| 记忆与知识库层 | 形成 Aria 的组织上下文壁垒 | 项目记忆、客户记忆、用户记忆雏形、知识库方案 | 用户/客户/项目/联系人/案例/方法论知识的权限、来源和召回机制 |
| 交付物工作流层 | 从“回答”升级为“完成交付” | 文档/PPT 生成、项目文件、项目笔记 | 会前简报、方案、风险清单、SOW、项目复盘等工作流模板化 |
| 质量与可控性层 | 让 Agent 可靠，而不是只显得聪明 | HITAS、trace、测试集、Run Activity Timeline | 引用来源、交付物 QA、失败恢复、回滚、评测集和 Partner Review |
| 产品形态层 | 少配置，多完成工作 | 工作台、项目、客户、Skill、知识库入口 | 以内置咨询 Agent/Skill 为主，用户轻量选择目标和资料 |

## 7. 近期优先级

### P0：把会前简报做成主入口

目标：让不了解系统的顾问在会议前打开简报，30 秒内获得明确行动。

验收：

- 一屏看到“说什么、避什么、确认什么、历史经验”。
- 干系人和项目/客户记忆都被聚合。
- 能一键带入 Chat 生成会议议程、开场话术或会后行动清单。
- 每条关键信息尽量有来源或数据依据。

### P0：降低干系人捕获摩擦

目标：让干系人维护从“填表”变成“系统建议，用户确认”。

已具备基础：

- `/projects/{id}/stakeholder-candidates`
- `/projects/{id}/stakeholder-candidates/apply`
- `ClientStakeholderHistory`

下一步：

- 从用户消息、会议纪要、项目笔记中识别候选。
- 识别已有干系人的字段更新，而不仅是新增人名。
- 把变更原因写入 history。

### P1：跨项目经验自动捕获

目标：项目推进中自动识别可沉淀到客户记忆的经验。

候选信号：

- 客户敏感话题。
- 决策链和审批节奏。
- 过往项目踩坑。
- 有效沟通策略。
- 反复出现的风险和约束。

### P1：Skill 结果资产化

目标：Skill 不只是一次输出，而是项目资产生产线。

下一步：

- Skill 运行记录。
- Skill 输出保存路径和命名规则。
- 交付物验证步骤。
- 版本和 diff。

## 8. 护城河总结

| 能力 | 大厂趋势 | AriaAI 策略 |
|---|---|---|
| 文档问答 | 会越来越强 | 做基础能力，不作为壁垒 |
| 单次聊天 | 会越来越强 | 做入口，不作为壁垒 |
| 个人记忆 | 会被平台化 | 只做用户体验补充 |
| 客户关系判断 | 通用平台难深入 | 核心壁垒 |
| 组织记忆 | 通用平台不会垂直到咨询团队 | 核心壁垒 |
| 跨项目经验 | 通用 Projects 多为孤立空间 | 核心壁垒 |
| 行为触发捕获 | 依赖垂直业务流 | 核心壁垒 |

AriaAI 的长期价值不是“单次生成更好”，而是“越用越懂这个客户”。客户上下文积累得越深、越准、越自动，产品壁垒就越强。
