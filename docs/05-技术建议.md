# AriaAI 技术建议

> 更新日期：2026-04-12
> 目标：给当前代码库提供一套务实的技术收敛方向

---

## 1. 总体判断

当前项目的主要问题不是“技术栈不够强”，而是：

- 配置来源分裂
- 模块边界逐渐模糊
- 工程卫生滞后于功能扩张
- 多端产品在共享语义上还不够统一

因此技术工作的优先级应是：

> 先保证核心链路稳定，再追求更高级的平台化。

---

## 2. 第一优先级建议

### 2.1 统一配置入口

建议统一管理：

- API base URL
- 数据库 URL
- provider
- selected model
- language

现状问题：

- 后端会读 `.env`
- Web 端部分读环境变量，部分读 localStorage，部分根本不读设置

### 2.2 修复异步边界

当前最典型的问题是 `task_runner.py`。

建议：

- 把所有 LLM 入口统一定义为 async
- 同步场景通过适配层调用
- 避免在业务层直接假设模型调用是同步的

### 2.3 规范仓库边界

建议明确：

- `data/` 默认不进库
- `uploads/` 默认不进库
- 仅保留 fixtures / sample assets

---

## 3. 第二优先级建议

### 3.1 提炼 Context Builder

当前 `chat.py` 同时承担：

- 选择 provider
- 读取设置
- 拼接 skill prompt
- 注入项目上下文
- 注入文件内容
- RAG 检索
- 流式输出

建议抽出单独的 `context_builder`，把 prompt 上下文组装独立出来。

### 3.2 提炼 Config / Enum 模块

把当前散落在多处的枚举和值集中：

- 项目状态
- provider 名称
- 默认模型
- 文档状态
- 技能类别

### 3.3 缓存策略标准化

当前有多个 TTL cache。

建议统一：

- key 命名规则
- bust 时机
- 过期策略

---

## 4. 第三优先级建议

### 4.1 RAG 升级

方向：

- embedding 存储与检索解耦
- 引入向量索引
- 增加 metadata filter
- 增加 query rewrite / rerank

### 4.2 生成物管理升级

方向：

- 生成物与对话、项目、技能建立更强关联
- 补 metadata
- 支持预览与版本信息

### 4.3 观测性

建议补：

- 请求级 tracing
- 工具调用日志
- 模型耗时与 token 统计
- scheduler 执行结果结构化日志

---

## 5. 具体实施建议

### Sprint A

- 乱码治理
- API base URL 统一
- 修复 `task_runner.py`
- 清理仓库运行产物

### Sprint B

- 抽 `context_builder`
- 统一枚举与类型
- 收敛 Settings 读写逻辑

### Sprint C

- RAG 升级
- 生成物管理增强
- 监控与日志补齐

---

## 6. 成功标准

当下面几项成立时，说明技术收敛开始生效：

- Web 与后端配置来源明确
- 定时任务真正可运行
- 乱码问题基本消失
- 核心 API 和 UI 状态语义一致
- 仓库不再混入运行态数据
