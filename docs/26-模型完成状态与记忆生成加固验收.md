# 模型完成状态与记忆生成加固验收

日期：2026-09-20。前置运行版本：`1bb53c1`；前置文档版本：`52c5485`。

## 问题与修复

- Kimi、DeepSeek、MiMo 的非流式响应原先在最终正文为空时回退到 `reasoning_content`，可能让内部推理进入摘要或记忆。现在只接受最终正文或完整工具调用；BigModel 一并使用相同校验。
- 所有非流式路径原先缺少明确的截断检查。现在供应商声明达到输出上限时立即失败，即使正文表面上是完整 JSON。Claude HTTP 与 SDK 同时接入，并统一多文本块、工具调用返回方式。
- 损坏的工具参数原先可能静默变成 `{}`。现在拒绝非对象参数、重复 JSON 键、非有限数值、无效调用身份与重复调用 ID；任一调用无效则整份响应失败。
- 客户记忆提示未明确 `client_profile` 的字符串类型。项目四个标量槽位同样补齐类型约束；项目到客户的记忆晋升复用完整客户类型规则。
- 完整/局部重建、完整回退及两种晋升路径使用固定 system 指令。资料、名称和已有记忆以转义 JSON 进入来源区块，不能通过原始结束标签跳出区块。

## 边界

此改动不新增数据库迁移，不改变 Product Run Event 或流式协议。来源编码与提示是注入防御的一层，不能单独保证语义注入免疫；原生来源 ACL、严格业务解析、最终授权与 HITAS 仍是执行边界。缺省完成原因的旧代理仍允许返回合法最终内容，未报告的截断继续依赖下游结构校验。

本次未自动重建客户/项目记忆，也未启用新的知识索引配置。历史生产失败记录不能据代码修复直接宣告恢复；实际重建需要走原生业务流程。
