# AriaAI 产品方向建议

更新时间：2026-04-20

## 1. 当前产品判断

AriaAI 已经具备较完整的 AI 协作工作台基础能力。下一阶段的产品重点不应是继续增加孤立页面，而是把 AI 能力嵌入真实项目/客户工作流。

当前最有价值的主线：

- 项目空间成为顾问和交付团队的日常工作容器。
- 客户空间沉淀跨项目经验和关系资产。
- Skill 成为可执行的方法论模块。
- 记忆系统成为可运营、可审计的长期资产。
- 任务治理和迁移治理降低生产环境不确定性。

## 2. 已形成的产品资产

### 项目资产

- 项目详情多 Tab。
- 项目聊天。
- 项目文档、笔记、待办、里程碑、财务。
- 项目记忆与多视角摘要。
- 项目生成物和引用来源。

### 客户资产

- 客户详情与关联项目。
- 客户长期记忆。
- 客户多视角摘要。
- 项目归档自动沉淀。
- 项目记忆手动提升到客户记忆。

### AI 工作流资产

- Skill CRUD。
- Skill 模板。
- 工具调用。
- 生成物。
- 结果保存。
- 记忆刷新。

### 治理资产

- Memory Operations。
- 失败分类与失败明细。
- 预算与重试。
- 告警汇总。
- Migration Status。
- Alembic 迁移治理脚本和部署流。

## 3. 下一阶段产品机会

### 3.1 Skill 工作流化

当前 Skill 已经可用，但还没有完全成为“工作流入口”。

建议方向：

- 项目页直接启动 Skill。
- 客户页直接启动 Skill。
- Skill 自动携带项目/客户上下文。
- Skill 输出能保存为项目文档、项目笔记、客户记忆。
- Skill 运行记录可追踪。

为什么优先：

- 后端 Skill 体系和项目/客户记忆都已具备。
- 这是把 AI 能力从“能用”推向“每天会用”的关键路径。
- 业务价值直观，适合下一版本主线。

### 3.2 今日工作起点

当前 Welcome 已经是入口，但还不够像“今天的工作台”。

建议方向：

- 今日到期事项。
- 即将到期里程碑。
- 最近失败任务。
- 最近生成物。
- 高风险项目。
- 最近活跃客户/项目。

为什么优先：

- 能提升日常打开频率。
- 能把记忆、任务、生成物、项目都串到一个起点。

### 3.3 记忆治理产品化

当前记忆系统已经可用，但还缺少历史、审计和回滚。

建议方向：

- 独立 memory snapshot 表。
- 版本 diff。
- 回滚。
- 记忆来源覆盖。
- 触发来源审计。
- 失败统计服务端聚合。

为什么优先：

- 记忆会越来越像核心资产，必须能解释、能恢复、能运营。

### 3.4 安全与可信

建议方向：

- Markdown/XSS 全链路复核。
- 文件下载路径复核。
- 管理员接口权限复核。
- 迁移失败告警和回滚 SOP。
- 测试分层和 CI 稳定性。

为什么优先：

- 产品已经接近可持续迭代阶段，安全与可靠性要成为默认基线。

## 4. 下一版本建议路线

### 第一阶段：把 Skill 接到项目/客户空间

目标：用户能从项目或客户出发使用 Skill，而不是先去 Skill 列表寻找模板。

交付物：

- 项目页 Skill 启动入口。
- 客户页 Skill 启动入口。
- 上下文预览。
- 结果保存到项目文档/笔记。

### 第二阶段：把 Skill 结果沉淀为资产

目标：Skill 输出不止是聊天内容，而是可以进入项目/客户记忆。

交付物：

- 保存到项目记忆 pinned 槽位。
- 保存到客户记忆沉淀。
- 保存后触发刷新/预热。
- Skill 运行记录。

### 第三阶段：把工作台变成每日入口

目标：用户打开系统就知道今天要做什么。

交付物：

- Welcome 今日行动。
- 项目概览行动卡。
- 失败告警入口。
- 最近生成物入口。

### 第四阶段：记忆治理升级

目标：记忆系统具备审计和恢复能力。

交付物：

- memory snapshot 设计。
- 版本列表。
- diff 与回滚。
- 服务端失败统计。

## 5. 产品原则

- 项目优先：高价值能力优先挂在项目上下文中。
- 客户复用：跨项目经验必须回流到客户空间。
- 沉淀优先：AI 结果要能变成文档、笔记、记忆或生成物。
- 治理优先：异步任务、迁移、失败和预算要可见、可处理。
- 小步快跑：每一轮交付一个可部署闭环。
