# AriaAI 产品方向建议

> 更新日期：2026-04-16
> 目标：基于当前代码状态，为下一阶段产品取舍提供判断依据。

---

## 1. 结论先行

下一阶段最值得投入的方向，是把"项目内持续协作"做深，并让 AI 的工作过程和产出变得**可见、可管、可复用**：

```text
客户 / 项目资料进入系统
-> AI 理解上下文（项目隔离 + 知识范围切换）
-> 顾问在项目空间内持续协作（聊天 / 笔记 / 待办联动）
-> AI 调用工具、生成文件
-> 交付物管理（GeneratedFile）
-> 结果沉淀回项目知识库
```

**Phase 1（收敛主闭环）已基本完成。**
当前的关键转变：技术基础设施已经具备 function calling 和文件生成管理能力，但这条链路的产品表达还没有做到位——AI 在做什么、产出了什么、能再用什么，对用户仍然不够透明。

---

## 2. 当前产品现状评估

### 已经做到位的

- 项目空间主链路（概览 / 聊天 / 笔记 / 待办 / 里程碑 / 财务）
- 项目聊天知识范围切换（当前项目 / 当前客户 / 全局知识库）
- 项目上下文隔离（file_ids、client scope 均有边界保护）
- 项目文档工作区（Markdown 树 + AI 润色 + 聊天沉淀）
- 全局聊天与项目聊天分离
- 多 LLM provider 支持（Claude / Kimi / BigModel，DeepSeek 预留）

### 技术上已具备但产品表达不足的

- **Function Calling**：`ToolCall` 数据库模型已落地，`Skill.tools_definition_json` 支持标准格式，但前端没有工具调用过程的可视化表达
- **生成文件管理**：`GeneratedFile` 模型已落地，但前端没有统一的"生成物"入口，用户看不到 AI 产出了什么文件
- **Skill 作为场景入口**：Skill 已支持 user_template，但与项目空间的联动还很弱

### 仍然偏弱的

- Welcome 工作台价值感不足（仅展示待办，缺少项目动态感）
- 知识库的引用可解释性弱（RAG 来源标注不够显眼）
- 客户-项目-知识的联动表达薄弱

---

## 3. 下一阶段最值得投入的三个主线

### 3.1 让 AI 工作过程可见（透明化）

当前 AI 生成回答，用户只看到文字流。工具调用、检索引用、文件生成都在后台发生，用户没有感知。

建议强化：

- 聊天中的 RAG 引用来源展示（已有数据，需要前端表达）
- 工具调用状态提示（"AI 正在查询项目文件..."）
- 生成文件的在线预览与下载入口
- `ToolCall` 历史可查

**价值**：顾问在和客户沟通时，能解释 AI 基于什么做出建议——这是 AI 工作台区别于普通聊天工具的核心感知。

### 3.2 让产出物更易管理（沉淀）

当前生成的内容要么停留在聊天消息里，要么手动保存到文档，缺乏统一的"生成物视图"。

建议强化：

- 项目生成物列表（PPT / Word / PDF / Markdown，按时间或类型聚合）
- 一键从聊天消息生成 / 追加到项目文档（已有接口，需要更低门槛的交互）
- 生成物与项目笔记的双向关联

**价值**：让"AI 生成"变成"可交付的资产"，而不是一次性的消耗。

### 3.3 让项目工作台更有"今日感"（即时性）

Welcome 和项目页目前偏向静态数据展示，缺少"今天该做什么"的聚焦感。

建议强化：

- Welcome：今日到期/即将到期的里程碑与待办，最近更新的项目，快速进入项目聊天
- 项目概览：突出未完成的关键里程碑 / 待办，最近 AI 生成物，项目对话摘要
- 待办 → 里程碑 → 交付物的顺序感知（项目进展不只是 status 字段）

**价值**：让顾问每天打开产品有明确的"工作起点"，而不是在一堆标签页里自己找。

---

## 4. 当前不建议优先做的方向

- 再新增大量平行功能页（当前深度优先于广度）
- 复杂权限中心（多成员的访问控制目前够用）
- 插件市场（过早）
- 多 agent 编排（function calling 单轮调用稳了再说）
- 大幅重写 RAG（先提升引用可见性，再优化检索质量）

---

## 5. 近期具体产品机会（按优先级）

### 5.1 生成物管理入口（高价值 / 技术已就绪）

`GeneratedFile` 模型已有，缺的是产品入口：

- 项目页新增"生成物"Tab 或在 Documents Tab 内整合
- 列出所有 AI 生成的 PPT / Word / PDF，支持下载和预览
- 聊天消息中生成文件时显示文件卡片，而不仅是文字

### 5.2 引用来源展示（高价值 / 中等工作量）

聊天回答中 RAG 检索来源已有后端数据（`references` SSE event），前端需要更完整的表达：

- 回答底部显示引用文档/文件名
- 点击跳转到知识库或项目文件详情
- 项目文档工作区中标注该段内容来自哪次对话

### 5.3 Welcome 强化（中等价值 / 低工作量）

- 增加"今日到期待办"和"近期里程碑"两个 widget
- 快速进入"最近活跃项目"的聊天
- 展示最近生成物（如果 5.1 完成）

### 5.4 Skill 与项目的绑定（中等价值 / 中等工作量）

- 项目聊天界面可以直接选择 Skill 作为对话模式
- Skill 执行时自动带入当前项目上下文
- 支持将 Skill 执行结果保存为项目文档

## 6. 路线建议（更新版）

### Phase 1：收敛主闭环 ✅ 基本完成（2026-04-16）

- ~~拆分过大的项目页与项目路由~~ ✅
- ~~修复乱码与统一 API 配置残留~~ ✅
- ~~补项目主链路测试~~ ✅（项目域关键路径已覆盖）

### Phase 2：增强交付链路（当前阶段）

- **生成物管理**：`GeneratedFile` 前端接入，建立项目生成物视图
- **引用可见性**：RAG 来源在聊天中显性展示
- **聊天沉淀更顺滑**：一键消息转文档，降低操作门槛
- **Welcome 工作台**：增加今日感和项目动态

### Phase 3：升级知识复用与 AI 能力

- 提升 RAG 检索质量（分块策略、rerank）
- 知识回流：AI 生成的洞察可主动写回知识库
- Function calling 多步执行与前端可视化
- DeepSeek provider 接入与模型对比

---

## 7. 一句话产品方向

> 不是让 AI 说更多，而是让 AI 的工作**可见**、让产出**可管**、让顾问的工作**更聚焦**。
