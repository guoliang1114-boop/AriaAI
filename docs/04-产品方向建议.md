# AriaAI 产品方向建议

> 更新日期：2026-04-16（第二轮）
> 目标：基于当前代码状态，为下一阶段产品取舍提供判断依据。

---

## 1. 结论先行

**Phase 1（收敛主闭环）已完成。Phase 2（增强交付链路）正式开始。**

当前最关键的产品判断：

> AriaAI 的技术基础设施已经超前于产品表达。
> 工具调用、生成物管理、RAG 引用、15 个专业 Skill——这些能力都已经落地，但用户感知不到。
> 下一阶段的核心任务不是继续堆能力，而是**让已有能力对用户可见**。

交付链路应该是这样的：

```
项目资料进入系统
→ AI 理解上下文（项目隔离 + 知识范围切换）
→ 顾问在项目空间持续协作（聊天 / 笔记 / 待办）
→ AI 调用工具、生成可交付文件
→ 生成物可见、可管、可复用
→ 结果沉淀回项目文档 / 知识库
```

当前这条链路的前四个环节已经有技术支撑，最后两个环节（生成物可见 + 沉淀）是产品表达的缺口。

## 3. 下一阶段最值得投入的三个主线

### 3.1 让 AI 产出物可见（生成物管理）

**当前问题：** AI 可以生成 PPT / Word / PDF，但用户看不到、找不到、也管不了这些文件。

**建议动作：**
- 项目页 Documents Tab 内整合生成文件列表（与上传文件区分显示）
- 聊天中 AI 生成文件时渲染文件卡片（名称 + 类型图标 + 下载按钮）
- 生成物支持直接预览（Markdown）或下载（PPT / Word / PDF）

**为什么现在做：** 后端 `artifacts` 路由完整，是纯前端接入工作，ROI 极高。

---

### 3.2 让 AI 工作过程透明（引用 + 工具调用可视化）

**当前问题：** 用户只看到回答，看不到 AI 引用了哪些文档、调用了哪些工具——这让 AI 的建议显得不可解释。

**建议动作（分优先级）：**

**P0 — RAG 引用展示：**
- 回答底部渲染来源文档 / 文件名列表（数据已有，纯 UI 工作）
- 点击可跳转到对应知识库文档或项目文件

**P1 — 工具调用可视化：**
- 聊天流中工具执行时显示状态气泡（"正在生成 PPT..."）
- 工具完成后在气泡下方展示结果摘要或文件卡片

**为什么这件事很重要：** 咨询行业的核心价值是"可信赖的专业建议"。如果顾问无法解释 AI 基于什么得出结论，这个建议就不能拿给客户。

---

### 3.3 让顾问有更强的"工作起点"（Welcome + 项目概览强化）

**当前问题：** Welcome 页偏向静态数据展示，顾问打开后不知道今天该先做什么。

**建议动作：**
- Welcome：增加"今日到期/即将到期里程碑"、"最近活跃项目快速入口"、"最近生成物"
- 项目概览 Tab：突出未完成里程碑和待办，以时间轴形式展示项目进度感
- 项目概览可展示该项目的 AI 生成物摘要（"上次生成了什么"）

## 5. 当前不建议优先做的方向

- **再新增大量平行功能页**：当前深度优先于广度
- **复杂权限中心**：多成员访问控制当前够用
- **插件市场**：过早
- **多 agent 编排**：function calling 单轮调用稳了再说
- **大幅重写 RAG**：先让引用可见，再优化检索质量

## 7. 一句话产品方向

> 不是让 AI 说更多，而是让 AI 的工作**可见**、让产出**可管**、让顾问每天来都有明确的**工作起点**。
