# AriaAI 产品方向建议

> 更新日期：2026-04-14
> 目标：基于当前代码状态，为下一阶段产品取舍提供判断依据。

---

## 1. 结论先行

下一阶段最值得投入的方向，不是继续横向铺更多页面，而是把“项目内持续协作”做深：

```text
客户 / 项目资料进入系统
-> AI 理解上下文
-> 顾问在项目空间内持续协作
-> 形成可交付物
-> 结果沉淀回项目、知识和待办
```

AriaAI 现在已经有这个闭环的大部分零件，接下来更需要的是稳定性、顺滑度和沉淀能力。

---

## 2. 当前最值得强化的主线

### 2.1 项目空间继续产品化

项目页已经不再只是“详情页”，而是在向工作空间演进。建议继续强化：

- 项目概览
- 项目聊天
- 项目笔记
- 项目待办
- 文件与上下文摘要之间的联动

### 2.2 输出更接近交付物

比“回答更长”更重要的是“更容易直接交付”。优先级最高的产物类型仍然是：

- 管理层摘要
- 客户邮件
- 项目周报
- 提案/PPT 大纲
- 风险清单与行动项

### 2.3 客户-项目-知识三者联动

当前三者都已存在，但还缺少足够强的联动表达。建议强化：

- 客户页展示正在进行的项目
- 项目页突出关联客户与知识来源
- 知识库支持更明确的项目/客户归属语义

---

## 3. 当前不建议优先做的方向

- 再新增大量平行功能页
- 复杂权限中心
- 插件市场
- 过早的多 agent 编排

这些方向应该建立在项目主工作流稳定之后。

---

## 4. 近期产品机会

### 4.1 把 Welcome 做成真正的工作台

Welcome 已经能读项目、会话、技能和“我的待办”，下一步可以继续增强：

- 今日重点项目
- 即将到期里程碑
- 最近生成物
- 快速创建项目内对话

### 4.2 把 Skill 做成“场景模板库”

Skill 当前更像配置对象，下一步建议强化：

- 标签与适用阶段
- 输入模板预览
- 推荐输出样例
- 支持从项目中直接套用 Skill

### 4.3 把聊天做成“项目协作界面”

聊天最重要的价值不在消息列表，而在于承载：

- 项目上下文引用
- 知识与文件引用
- 工具调用
- 导出与继续编辑

---

## 5. 路线建议

### Phase 1：收敛主闭环

- 拆分过大的项目页与项目路由
- 修复乱码与统一 API 配置残留
- 补项目主链路测试

### Phase 2：增强交付链路

- 强化导出与生成物管理
- 让项目笔记、待办、聊天更自然联动
- 强化 Welcome 工作台价值

### Phase 3：升级知识复用

- 提升检索质量
- 强化知识回流
- 建立更可解释的引用体验
