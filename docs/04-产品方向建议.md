# AriaAI 产品方向建议

> 更新日期：2026-04-12
> 目标：基于当前代码状态，给下一阶段产品方向做取舍

---

## 1. 结论先行

下一阶段最重要的方向不是继续横向铺页面，而是把下面这个闭环做深：

```text
客户 / 项目资料进入系统
-> AI 理解项目上下文
-> 顾问在项目内持续协作
-> 生成可交付物
-> 产物与结论沉淀回项目与知识库
```

AriaAI 已经具备这个闭环的大部分零件，但仍缺少“稳定、顺滑、可复用”的整合。

---

## 2. 当前最值得强化的产品主线

### 2.1 项目内工作流

把项目作为第一入口，而不是只把它当成一个数据容器。

建议强化：

- 项目主页摘要
- 项目最近对话
- 项目关键风险
- 项目待办与里程碑提醒
- 项目内文件引用与推荐提问

### 2.2 生成可交付物

要把“能回答”升级为“能交付”。

优先级最高的交付物类型：

- 管理层摘要
- 客户邮件
- 项目周报
- 提案/PPT 大纲
- 风险清单与行动项

### 2.3 客户-项目-知识联动

当前三者都已存在，但联动还不够强。

建议：

- 客户页突出正在进行的项目
- 项目页展示关联客户知识
- 知识库支持更显式地回到项目或客户

---

## 3. 不建议优先做的方向

- 再新增大量平行功能模块
- 复杂权限中心
- 高级协作系统
- 插件市场
- 过早的自动化 agent 流程编排

这些能力要建立在主工作流稳定之后。

---

## 4. 近期产品机会

### 4.1 把 Welcome 做成真正的工作台

当前 Welcome 已经有基础模块，但还可以继续强化：

- 今日重点项目
- 即将到期里程碑
- 最近生成物
- 快速创建“项目内对话”

### 4.2 把 Skill 做成“场景模板库”

当前 Skill 更像配置对象。

下一步建议：

- 给 Skill 增加标签与适用阶段
- 展示输入模板预览
- 展示推荐输出物
- 支持从项目直接套用 Skill

### 4.3 把聊天做成“项目协作界面”

聊天应该承载：

- 项目上下文引用
- 文件与知识引用
- 结构化工具调用
- 输出物下载与继续编辑

而不是只做一个漂亮的消息列表。

---

## 5. 建议的产品路线

### Phase 1：收敛主闭环

- 修复乱码与配置问题
- 统一项目内聊天体验
- 强化项目详情与上下文沉淀

### Phase 2：提升交付物能力

- 丰富 Skill 与模板联动
- 提升生成物管理与预览
- 引入更多项目导向场景

### Phase 3：增强知识复用

- 强化客户/项目/知识关联
- 提升检索质量
- 增加结论沉淀与复用能力

---

## 6. 方向判断标准

接下来评估一个功能值不值得做，建议只问三件事：

1. 它是否提升了项目内真实工作效率？
2. 它是否让输出更接近可交付物？
3. 它是否能沉淀为下一次可复用资产？

如果三者都不能明显提升，优先级就应该往后放。
