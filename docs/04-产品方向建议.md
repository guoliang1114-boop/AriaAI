# AriaAI 产品方向建议

> 更新日期：2026-04-17
> 目标：基于当前代码状态，为下一阶段产品取舍提供判断依据。

---

## 1. 结论先行

**Phase 1（收敛主闭环）已完成。Phase 2（增强交付链路）正式开始。**

当前最关键的产品判断：

> AriaAI 的技术基础设施已经超前于产品表达。
> 工具调用、生成物管理、RAG 引用、15 个专业 Skill——这些能力都已经落地，但用户感知不到。
> 下一阶段的核心任务不是继续堆能力，而是**让已有能力对用户可见**。

交付链路应该是这样的：

```
项目资料进入系统
→ AI 理解上下文（项目隔离 + 知识范围切换）
→ 顾问在项目空间持续协作（聊天 / 笔记 / 待办）
→ AI 调用工具、生成可交付文件
→ 生成物可见、可管、可复用
→ 结果沉淀回项目文档 / 知识库
```

当前这条链路的前四个环节已经有技术支撑，最后两个环节（生成物可见 + 沉淀）是产品表达的缺口。

## 3. 下一阶段最值得投入的三个主线

### 3.1 Skills 与项目空间联动

**当前状态：** 生成物管理、RAG 引用展示、工具调用可视化均已完成。Skill 与项目联动是 Phase 2 剩余最高价值的单一工作。

**建议动作：**
- 项目聊天页增加 Skill 选择入口（类似通用聊天页的 Skill selector）
- Skill 执行默认携带当前项目上下文（文件 + 里程碑 + 摘要）
- Skill 生成结果一键沉淀为项目文档或笔记

**为什么优先：** 后端 Skill 体系已完整（21 个模板），前端项目聊天页已支持 SSE 工具调用，联动是最后一段路。

---

### 3.2 部署可靠性加固（Alembic + 健康检查）

**当前风险：** 真实数据库结构与 Alembic 版本存在历史不一致，部署迁移失败不会被显式拦截。

**建议动作：**
- 迁移脚本关键操作加 `IF NOT EXISTS` / `IF EXISTS` 保护
- CI/CD 加迁移失败中断
- 提供发布后数据库结构健康检查脚本

**为什么现在做：** 当前是 P0 风险项，影响所有用户的数据安全性。

---

### 3.3 让顾问有更强的"工作起点"（Welcome + 项目概览强化）

**当前状态：** Welcome 页有待办和项目列表，但缺乏"今天最紧迫的事情是什么"的强引导。

**建议动作：**
- Welcome：增加今日到期/即将到期里程碑 widget + 最近生成物快速访问
- 项目概览 Tab：突出未完成里程碑和待办，使用时间轴展示项目进度
- 项目概览展示项目最近 AI 生成物（"上次 AI 帮你做了什么"）

## 5. 当前不建议优先做的方向

- **再新增大量平行功能页**：当前深度优先于广度
- **复杂权限中心**：多成员访问控制当前够用
- **插件市场**：过早
- **多 agent 编排**：function calling 单轮调用稳了再说
- **大幅重写 RAG**：先让引用可见，再优化检索质量
