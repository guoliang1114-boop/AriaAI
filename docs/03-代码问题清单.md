# AriaAI 代码问题清单

> 更新日期：2026-04-12
> 范围：`AriaAI/backend`、`aria-web`、`AriaAI/AriaAI`
> 原则：只记录当前代码中仍然可观察到的真实问题

---

## 1. 最高优先级问题

### 1.1 调度任务把异步 LLM 调用当同步函数使用

位置：

- `AriaAI/backend/app/services/task_runner.py`

问题：

- `run_task()` 直接调用 `complete(messages, system=system)`
- `complete` 来自 `app.services.claude`，是 `async` 能力
- 当前没有 `await`，也没有事件循环桥接

影响：

- 定时任务结果可能是 coroutine 对象
- 调度链路极可能没有真正跑通

建议：

- 把 `run_task` 改成 async 版本，或者使用 `asyncio.run`/统一任务执行器包装

### 1.2 Web API 地址配置存在多套来源

位置：

- `aria-web/src/api/client.ts`
- `aria-web/src/pages/chat/Chat.tsx`
- `aria-web/src/pages/settings/ServerSettings.tsx`

问题：

- `api client` 默认走 `VITE_API_URL || /api`
- Chat 页流式请求单独走 `VITE_API_URL || http://127.0.0.1:8000`
- 设置页尝试保存 `api_base_url` 和 `localStorage.serverUrl`
- 但 `api client` 并不会读取 `serverUrl`

影响：

- 设置页保存服务器地址后，大部分请求未必生效
- 普通 API 请求和聊天流式请求可能打到不同后端

建议：

- 抽一个统一的 `getApiBaseUrl()`，所有请求共用

### 1.3 源码与 UI 文案存在大量乱码

位置：

- `aria-web/src/pages/chat/Chat.tsx`
- `aria-web/src/pages/settings/ServerSettings.tsx`
- `AriaAI/backend/app/models/db.py`
- `AriaAI/backend/app/routers/projects.py`
- 多个旧文档和注释

问题：

- 中文字符串和注释出现明显 mojibake

影响：

- 直接损伤用户体验
- 降低可维护性
- 文案无法稳定进入 i18n 体系

建议：

- 统一 UTF-8 编码
- 先清 UI 文案，再清注释和文档

### 1.4 仓库混入数据库、上传文件和生成物

位置：

- `AriaAI/backend/data/ariaai.db`
- `AriaAI/backend/data/uploads/...`

问题：

- 运行时数据库和文件产物进入版本库

影响：

- 仓库体积膨胀
- 数据与代码耦合
- 容易引入隐私与冲突风险

建议：

- 调整 `.gitignore`
- 保留样例数据时单独做 fixtures

## 2. 中优先级问题

### 2.1 CORS 配置过宽

位置：

- `AriaAI/backend/main.py`

问题：

- `allow_origins=["*"]`
- `allow_credentials=True`

影响：

- 生产配置不安全
- 某些浏览器场景下表现不一致

建议：

- 区分开发与生产白名单

### 2.2 项目状态语义不一致

位置：

- `AriaAI/backend/app/models/db.py`
- `aria-web/src/types/api.ts`

问题：

- 模型注释里提到 `lead | opportunity | won | delivering | archived`
- Web 类型中定义为 `lead | active | completed | archived`

影响：

- 前后端契约存在漂移

建议：

- 统一枚举并集中定义

### 2.3 RAG 仍采用 JSON embedding + 全量相似度计算

位置：

- `AriaAI/backend/app/models/db.py`
- `AriaAI/backend/app/services/rag.py`

问题：

- embedding 存在 `embedding_json`
- 检索方式偏向全量扫描 baseline

影响：

- 规模稍大后性能与质量都受限

建议：

- 引入专门向量索引或外部向量库

### 2.4 缓存失效策略仍较分散

位置：

- `chat.py`
- `projects.py`
- `settings.py`
- `skills.py`

问题：

- 各 router 各自维护 TTL 与 bust 逻辑

影响：

- 后续容易出现漏失效

建议：

- 抽统一缓存策略与 key 命名约定

## 3. 低优先级但应尽快处理的问题

### 3.1 Web 中仍有旧页面和新页面并存

例子：

- `aria-web/src/pages/Projects.tsx`
- `aria-web/src/pages/Chat.tsx`
- 同时存在 `pages/projects/*` 与 `pages/chat/*`

影响：

- 提高认知负担

### 3.2 日志较多且偏调试态

位置：

- `aria-web/src/api/client.ts`
- `aria-web/src/pages/Login.tsx`

影响：

- 生产噪音较大

### 3.3 category、language、provider 等枚举未集中

影响：

- 类型漂移
- i18n 难以统一

---

## 4. 已确认但暂不建议现在处理的事项

- 更复杂的 agent 编排
- 多租户权限体系
- 重度插件系统
- 大规模任务编排平台化

这些问题重要，但不是当前最阻塞产品演进的矛盾。

---

## 5. 建议处理顺序

1. 修复乱码
2. 统一 Web API base URL 来源
3. 修复 `task_runner.py` 异步调用
4. 清理仓库运行产物
5. 统一状态枚举和配置枚举
6. 再推进 RAG 与上下文组装重构
