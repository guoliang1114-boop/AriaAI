## 1. 当前判断

当前项目的主要矛盾已经从“页面和文件过大”转向：

- 核心能力是否真正被业务用户看见并用起来
- AI 相关链路是否足够稳定、低成本、可缓存、可运营
- 安全和部署链路是否足够稳
- 项目记忆与客户记忆是否真正形成长期资产

已经基本完成的部分：

- `projects` 目录的大型页面已经完成多轮结构化重构
- 项目聊天、概览、设置、待办、文档等页面都已模块化
- `artifacts / tool calls / references` 前后端链路已贯通
- 项目级三层记忆已落地，客户级第四层记忆已进入系统化管理阶段

---

### 3.6 Alembic 迁移幂等性与真实库状态一致性

状态：待完成

当前风险：

- 历史上出现过真实数据库结构已存在，但 Alembic 版本未同步的问题
- 部分迁移脚本仍缺少更稳妥的保护性判断
- 部署后的数据库健康检查还没有固化

建议目标：

- 迁移脚本关键操作具备幂等保护
- 部署流程显式中断迁移失败
- 发布后提供数据库健康检查脚本或步骤

---

### 3.7 Skills 与项目空间联动

状态：待完成

当前现状：

- 通用聊天页已有 Skill 选择逻辑
- 项目聊天页还没有同等完整的 Skill 选择器与模板联动
- 项目上下文虽然已经可注入聊天，但还没形成“项目页直接选 Skill 执行”的完整体验

建议目标：

- 项目聊天页支持 Skill 选择
- Skill 执行默认携带当前项目上下文
- Skill 结果可一键沉淀到项目文档或项目记忆
