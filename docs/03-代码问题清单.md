## 1. 当前判断

当前项目的主要矛盾，已经从“页面和文件过大”转向：

- 核心能力是否真正被用户看见并用起来
- 聊天、引用、生成物等关键链路是否可验证、可追踪
- 安全与部署防线是否足够稳

已经基本完成的部分：

- `projects` 目录的大型页面已经完成多轮结构化重构，核心页面不再依赖超大单文件
- 项目聊天、项目概览、项目设置、项目待办、项目文档等页面都已经拆成更稳定的组件和 Hook
- `GeneratedFile / artifacts`、`ToolCall`、RAG `references` 等底层能力已经贯通前后端

接下来最重要的工作，不再是继续机械拆文件，而是把剩余的产品表达层、可靠性和安全项补齐。

- 项目概览页新增项目级生成物列表
- 后端消息元数据会持久化 `artifacts`，刷新后仍可恢复展示

### 3.4 Alembic 迁移幂等性与真实库状态一致性

状态：待完成

当前风险：

- 历史上出现过真实数据库结构已存在，但 Alembic 版本未同步的问题
- 部分迁移脚本仍缺少更稳妥的保护性判断
- 部署后的数据库健康检查还没有标准化固化

建议目标：

- 迁移脚本关键操作具备幂等保护
- 部署流程显式中断迁移失败
- 发布后提供数据库结构健康检查步骤或脚本

### 3.5 Skills 与项目空间联动

状态：待完成

当前现状：

- 通用聊天页已有 Skill 选择逻辑
- 项目聊天页还没有同等完整的 Skill 选择器与模板联动
- 项目上下文已经可以注入聊天，但还没有形成“项目页直接选 Skill 并执行”的完整体验

建议目标：

- 项目聊天页支持 Skill 选择
- Skill 执行默认携带当前项目上下文
- Skill 结果可一键沉淀为项目文档或项目笔记

### 3.6 安全项

状态：进行中

已完成：

- API Key 通过 keyring 管理，不再直接明文落库
- 生成物下载路径已加边界校验
- 多设备 Token 管理已支持
- 登录接口已增加失败限流
- 弱默认 `JWT_SECRET` 已增加启动拦截

待完成：

- Markdown 渲染链路的 XSS 防护再做一轮系统复核
- 生产环境继续确认 `ALLOW_INSECURE_JWT_SECRET` 未被误开启
