# AriaAI 代码问题清单

更新时间：2026-04-21

## 1. 当前判断

当前主要问题已经不是“功能缺口太大”，而是“已经落地的 AI 能力如何稳定进入用户工作流”。

近期已完成的关键收口：

- 项目/客户记忆进入可运营 V1。
- 统一任务面板补齐失败分类、失败明细、重试、预算和告警汇总。
- Alembic 迁移治理从文档进入脚本和部署流程。
- 项目记忆可以手动提升到客户记忆。
- Skill 结果保存后可以刷新项目记忆，形成基本回流闭环。
- 客户侧干系人已从项目成员概念中拆出，新增独立 Tab、可视化和锚点治理页。
- 部署中 502/503/504 的首页和项目详情错误态已改为服务恢复提示，避免误判为项目不存在。

下一阶段要重点关注：

- Skill 是否能成为项目/客户空间的一等工作流入口。
- 记忆系统是否具备历史版本、回滚、审计能力。
- 任务治理是否能从“查看与重试”升级到“策略化运营”。
- 前端复杂页面和后端大路由是否继续收敛。
- 安全、Markdown、部署链路是否经得起生产复核。

## 3. 关键问题现状

### 3.1 记忆系统

已完成：

- 项目结构化记忆。
- 项目多视角摘要缓存。
- 客户长期记忆。
- 客户多视角摘要。
- 项目记忆手动提升到客户记忆。
- 项目归档自动沉淀到客户记忆。
- 失败记录、失败分类、重试元数据。
- 统一任务面板与告警汇总。

仍需推进：

- 独立 memory 主表。
- 历史版本与回滚。
- 更细的预算策略与服务端统计接口。
- 失败分类从前端兜底推断升级为服务端枚举和聚合。

### 3.2 Skill 工作流

已完成：

- Skill CRUD。
- Skill 分类与模板。
- 聊天链路可使用 Skill。
- 项目聊天中可表达当前项目/客户上下文。
- Skill 结果保存后可刷新项目记忆。

仍需推进：

- 从项目页/客户页直接启动 Skill。
- Skill 执行默认携带项目/客户上下文。
- Skill 结果一键保存到项目笔记、项目文档、客户记忆。
- Skill 运行记录、版本、验证机制。

### 3.3 部署与迁移

已完成：

- `migration_governance.py report/json/check/ensure/upgrade/current`。
- `ensure_db.py` 幂等补齐。
- Alembic revision 读取使用 Alembic revision map。
- 历史短号 alias 修复，例如 `005` 归一化为 `005_v1_5`。
- 部署脚本接入治理流程。
- 设置页迁移状态可视化。

仍需推进：

- 线上部署后自动健康回读和告警。
- 迁移失败时的更明确 runbook 输出。
- 后续新迁移必须包含幂等检查与回滚说明。

### 3.4 前端与性能

已完成：

- 项目详情页模块化拆分。
- 路由懒加载。
- Welcome 首屏减负。
- Skills 页面轻量接口。
- 项目聊天交互与保存动作优化。

仍需推进：

- `ProjectDetail` 相关子页面继续瘦身。
- `ProjectMemoryTab.tsx`、`ProjectStakeholdersTab.tsx`、`ProjectChatMainPanel.tsx` 拆分。
- `MemoryOperationsSettings` 后续可拆成子组件。
- Markdown 依赖和安全链路继续复核。
- 项目/客户列表轻量摘要接口。

### 3.5 后端复杂度

当前复杂度中心：

- `projects.py`
- `clients.py`
- `skills.py`

仍需推进：

- `projects.py` 拆成项目 CRUD、项目记忆、项目摘要、项目文档、项目任务等子路由。
- `clients.py` 拆成客户 CRUD、客户记忆、客户摘要、客户任务治理。
- `skills.py` 拆出 Skill CRUD、Skill 执行、Skill 结果沉淀。
- 记忆任务治理逻辑沉到服务层，减少 router 混合调度和失败处理逻辑。

## 4. 下一版本建议顺序

### Sprint 1：Skill 工作流化

1. 项目页和客户页提供“用 Skill 处理当前上下文”的入口。
2. Skill 执行默认带入项目/客户记忆、文件、里程碑、待办摘要。
3. Skill 结果可保存为项目文档、项目笔记、客户记忆沉淀。
4. 补 Skill 运行记录和失败反馈。

### Sprint 1.5：客户侧干系人结构化

1. 设计客户侧干系人结构化 schema。
2. 干系人页从自由文本维护升级为结构化表单。
3. 关系图按决策、使用、采购、财务、法务、IT、安全等影响类型展示。
4. AI 摘要和客户记忆读取结构化干系人。

### Sprint 2：记忆治理产品化

1. 服务端提供失败统计和分类聚合接口。
2. Memory Operations 支持批量处理和更明确的安全重试策略。
3. 设计 memory 历史版本表。
4. 项目/客户记忆支持版本查看与回滚。

### Sprint 3：工作台体验强化

1. Welcome 今日工作起点。
2. 项目概览突出风险、待办、里程碑、最近生成物。
3. 客户空间展示跨项目经验和最近活动。
4. 首页到项目/客户/Skill 的路径继续缩短。

### Sprint 4：质量与安全基线

1. Markdown/XSS 系统复核。
2. 项目域和客户域主链路测试补齐。
3. 前端 lint 与构建警告收敛。
4. 迁移新增规范和部署后健康验证。
