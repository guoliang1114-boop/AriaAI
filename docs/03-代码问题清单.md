## 1. 当前判断

当前项目的主要矛盾，已经从“页面和文件过大”转向“能力是否真正被用户看见、是否可验证、是否足够安全”。

已经基本完成的事情：

- `projects` 域前后端结构性重构已经完成，核心页面不再依赖超大文件。
- 项目聊天、项目笔记、项目详情的主流程已经拆分为更稳定的组件与 Hook。
- `GeneratedFile / artifacts`、`ToolCall`、RAG `references` 等底层能力都已经落地。

接下来最重要的，不再是继续拆文件，而是把剩余的产品表达层、安全项、部署可靠性补齐。

## 3. 核心问题状态

### 3.1 生成物前端接入

状态：已完成

已落地：

- 项目聊天中，文件生成类工具结果会渲染为生成物卡片。
- 卡片支持直接下载。
- 项目概览页增加了项目级生成物列表。
- 后端消息元数据会持久化 `artifacts`，刷新后仍可见。

涉及：

- `aria-web/src/pages/projects/ProjectChatArtifactCard.tsx`
- `aria-web/src/pages/projects/ProjectOverviewArtifactsCard.tsx`
- `aria-web/src/pages/projects/downloadArtifact.ts`
- `AriaAI/backend/app/services/chat_streaming.py`

### 3.2 RAG 引用来源展示

状态：已完成

已落地：

- 项目聊天消费 SSE `references` 事件。
- 流式回答中即可看到引用来源。
- 最终消息会把 `references` 写入 `metadata_json`。
- 引用来源支持跳转到项目文档或里程碑相关页面。

涉及：

- `aria-web/src/pages/projects/useProjectChatComposer.ts`
- `aria-web/src/pages/projects/ProjectChatMessages.tsx`
- `aria-web/src/pages/projects/ProjectChatMessageBubble.tsx`

### 3.3 工具调用过程可视化

状态：已完成

已落地：

- 项目聊天消费 `tool_executing` / `tool_result` 流事件。
- 前端渲染工具执行状态卡片。
- 执行完成后展示结果摘要。
- 文件生成类工具会同步显示生成物卡片。
- 工具执行记录会持久化进消息元数据 `tool_calls`。

涉及：

- `aria-web/src/pages/projects/ProjectChatToolCallCard.tsx`
- `aria-web/src/pages/projects/useProjectChatComposer.ts`
- `AriaAI/backend/app/services/chat_streaming.py`
- `AriaAI/backend/app/services/chat_store.py`

### 3.4 Alembic 迁移幂等性与真实库状态一致性

状态：待完成

当前风险：

- 历史上出现过真实库结构已存在但 Alembic 版本未同步的问题。
- 部分迁移仍缺少更稳妥的保护性判断。
- 部署后数据库健康检查目前还未标准化固化。

建议目标：

- 迁移脚本关键操作具备幂等保护。
- 部署流程显式中断迁移失败。
- 发布后提供数据库结构健康检查步骤或脚本。

### 3.5 Skills 与项目空间联动

状态：待完成

当前现状：

- 通用聊天页已有 Skills 选择逻辑。
- 项目聊天页目前还没有等价的 Skill 选择器与模板联动。
- 项目上下文已经可以注入聊天，但还没有形成“项目页直接选 Skill 并执行”的完整体验。

建议目标：

- 项目聊天页支持 Skill 选择。
- Skill 执行默认携带当前项目上下文。
- Skill 结果可一键保存为项目文档或笔记。

### 3.6 安全项

状态：进行中

已完成：

- API Key 通过 keyring 管理，不再直接明文落库。
- 生成物下载路径具备边界校验。
- 多设备 Token 管理已支持。
- 登录接口限流已完成。

待完成：

- 默认弱 `JWT_SECRET` 启动拒绝已完成。
- Markdown 渲染链路的 XSS 防护再确认一轮。
