# AriaAI 代码问题清单与优化方案

更新日期：2026-04-15

范围：基于当前 `main` 分支代码重新核对，按真实风险与收益排序。  
这份文档不只列问题，也给出建议的优化方向，方便直接进入排期和执行。

## 1. 总体判断

当前代码并不是“不可维护”，而是进入了典型的第二阶段：

1. 主链路已经可用
2. 项目域功能增长很快
3. 结构债务开始集中暴露

现在最核心的问题不是单个 bug，而是三类系统性风险：

1. 项目域前后端复杂度持续集中
2. 数据库迁移与部署流程还不够稳
3. 自动化测试与编码治理跟不上迭代速度

此外，本轮复盘也确认了一批需要持续跟进的安全项。

## 2. 安全风险

### 2.1 JWT 密钥与 API Key 存储风险

位置：

1. `AriaAI/backend/app/core/security.py`
2. `AriaAI/backend/app/models/` 中的 LLM provider 配置

现状：

1. `SECRET_KEY` 仍依赖环境配置，若使用默认值会产生高风险
2. 用户配置的 LLM API Key 仍是明文入库
3. 数据库泄露会直接暴露用户密钥

建议：

1. 启动时检测默认 `SECRET_KEY`，命中则拒绝启动
2. API Key 改为对称加密存储，调用时解密
3. 为后续密钥轮换预留机制

优先级：最高

### 2.2 文件路径遍历风险

位置：

1. `AriaAI/backend/app/routers/projects.py`

现状：

1. 文件上传和下载链路仍需依赖路径拼接
2. 如果没有统一收口，会存在目录穿越风险

建议：

1. 所有文件路径统一用 `Path.resolve()` 校验边界
2. 下载前校验文件是否属于当前项目
3. 不向前端暴露真实服务器绝对路径

优先级：高

### 2.3 认证接口缺少速率限制

位置：

1. `AriaAI/backend/app/routers/auth.py`

现状：

1. 登录与注册接口没有速率限制
2. 密码复杂度要求偏弱

建议：

1. 给 `/auth/login` 增加限流
2. 提升密码规则
3. 增加连续失败的临时锁定机制

优先级：高

### 2.4 Markdown 渲染的 XSS 风险

位置：

1. `aria-web/src/components/MarkdownRenderer.tsx`

现状：

1. Markdown 渲染能力已经较轻量
2. 但 AI 输出进入富文本渲染链路时，仍应明确防御策略

建议：

1. 明确禁止原始 HTML 直通渲染
2. 如果未来恢复更复杂的富文本能力，优先加 `DOMPurify`
3. 在 Nginx 层补充 CSP

优先级：高

## 3. P0：优先立即优化的问题

### 3.1 `ProjectDetail.tsx` 仍是前端复杂度中心

位置：

1. `aria-web/src/pages/projects/ProjectDetail.tsx`

现状：

1. 已经完成第一轮拆分
2. 新增了 `ProjectDetailLayout.tsx`
3. 新增了 `useProjectDetailData.ts`
4. 但主文件仍然偏大，历史结构仍未完全退出

风险：

1. 每加一个项目功能，回归面继续扩大
2. 阅读与修改门槛仍然偏高

目标状态：

1. `ProjectDetail.tsx` 只负责页面框架、路由与共享状态
2. `overview / documents / milestones / financials / settings` 继续下沉

建议：

1. 继续拆详情页子域
2. 清理历史遗留的重复结构
3. 逐步把页面装配逻辑迁到 hook 或容器组件

优先级：最高

### 3.2 `projects.py` 承担过多项目域职责

位置：

1. `AriaAI/backend/app/routers/projects.py`

现状：

1. 项目 CRUD、详情聚合、文档、待办、摘要等都还在一个 router 里

风险：

1. 回归面大
2. service 边界不清晰
3. 单文件持续膨胀

目标状态：

1. router 只处理输入输出
2. 项目域按子域拆到 service 或子路由

建议：

1. 先拆 `project_notes`
2. 再拆 `project_todos`
3. 再拆 `project_files`
4. 把 `_todo_dict`、模板初始化、文档读写等逻辑下沉

优先级：最高

### 3.3 PostgreSQL 迁移与真实库状态容易脱节

位置：

1. `AriaAI/backend/alembic/versions/*.py`
2. `.github/workflows/deploy.yml`
3. `DEPLOY.md`

现状：

1. 线上已经出现过结构存在但 Alembic 版本落后的情况
2. 新字段未迁移会直接导致接口 500

风险：

1. 部署看似成功，功能实际不可用
2. 排障依赖人工经验

建议：

1. 迁移失败即中断部署
2. 固化 `ensure_db.py + alembic upgrade head`
3. 发布后增加数据库健康检查

优先级：最高

### 3.4 项目域自动化测试覆盖仍不足

位置：

1. `AriaAI/backend/tests/`

现状：

1. 现有测试仍偏向聊天主链路
2. 项目文档、待办、详情聚合的覆盖还不够

建议：

1. 补项目详情聚合测试
2. 补 todos `due_date` 测试
3. 补 notes CRUD 测试
4. 补项目级知识范围隔离测试

优先级：最高

## 4. P1：本阶段建议完成的优化

### 4.1 N+1 查询与缺失索引

位置：

1. `AriaAI/backend/app/routers/projects.py`
2. `AriaAI/backend/app/models/*.py`

现状：

1. 项目列表和详情聚合仍有 N+1 风险
2. 部分高频外键字段缺少索引

建议：

1. 用 `selectinload()` 或 `joinedload()` 优化查询
2. 为 `project_id`、`user_id`、`client_id` 等补索引

优先级：高

### 4.2 前端依赖和包体治理

位置：

1. `aria-web/vite.config.ts`
2. `aria-web/src/components/MarkdownRenderer.tsx`
3. `aria-web/package.json`

现状：

1. 已完成第一轮分包
2. 已移除未使用的 `react-syntax-highlighter`
3. 但仍需继续关注 chunk 体积与懒加载边界

建议：

1. 保持 vendor 分包策略
2. 后续按页面粒度补动态加载
3. 定期检查未使用依赖

优先级：高

### 4.3 编码与文档污染治理

位置：

1. `DEPLOY.md`
2. `docs/03-代码问题清单.md`
3. 项目页相关组件

现状：

1. 已经清理一部分页面乱码
2. 仍需继续检查其他历史文档和注释

建议：

1. 统一保持 UTF-8
2. 清理历史乱码文案
3. 保证文档与代码真实状态同步

优先级：高

## 6. 成功标准

如果下面几件事成立，可以认为工程进入更稳阶段：

1. 项目前后端不再由两个超大文件承载主逻辑
2. 项目主链路具备最小回归保护
3. 部署失败不会被误判为成功
4. 文档与代码状态基本一致
5. 高风险安全问题进入明确治理路径
