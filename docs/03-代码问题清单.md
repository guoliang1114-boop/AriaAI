# AriaAI 代码问题清单与优化方案

更新日期：2026-04-15

范围：基于当前 `main` 分支代码、近期线上问题与最近几轮优化结果整理，按真实风险与收益排序。

这份文档不只记录问题，也用于指导后续持续优化与提交节奏。

## 1. 总体判断

当前工程已经具备稳定可用的主链路，但项目域的功能增长很快，代码结构、数据库迁移和自动化保障还需要继续补强。

现在最值得持续投入的不是“再堆新功能”，而是以下三类工程化工作：

1. 降低项目页前后端的复杂度
2. 收紧项目上下文隔离与数据边界
3. 用测试和部署校验减少线上回归

## 2. 优先级排序

### P0

1. 继续拆分 `ProjectDetail.tsx`，逐步清理历史遗留内联实现
2. 继续拆分 `AriaAI/backend/app/routers/projects.py`
3. 加固 PostgreSQL / Alembic 迁移的一致性与幂等性
4. 为项目域关键行为补最小回归测试

### P1

1. 修复项目页历史乱码与编码污染
2. 优化项目域查询性能与索引
3. 补齐安全项，包括密钥存储、路径边界、认证限流
4. 清理跨页面复用但仍耦合在业务页面内的组件

## 3. 核心问题

### 3.1 `ProjectDetail.tsx` 仍然过大

位置：

1. `aria-web/src/pages/projects/ProjectDetail.tsx`

现状：

1. 已完成多轮拆分，但主文件仍保留部分历史实现
2. 旧逻辑、页面装配逻辑和遗留组件仍混在一起
3. 该文件过去还受过编码污染影响，粗暴清理风险较高

风险：

1. 每次新增项目页功能都容易扩大回归面
2. 小改动也需要阅读大段不再真实生效的历史代码
3. 机械删除容易引入构建失败

目标状态：

1. `ProjectDetail.tsx` 只负责路由、页面装配与共享状态
2. 真实 UI 全部沉到独立 Tab 组件
3. 旧内联实现按小批次逐步删除，不做一次性大手术

### 3.2 `projects.py` 承担过多项目域职责

位置：

1. `AriaAI/backend/app/routers/projects.py`

现状：

1. 项目 CRUD、详情聚合、待办、笔记、文件、里程碑等逻辑仍集中在一个 router
2. 业务规则与接口层耦合较深

风险：

1. 文件持续膨胀
2. 难以做清晰的项目域边界
3. 回归测试难以围绕子域组织

目标状态：

1. router 只处理输入输出
2. 待办、笔记、文件、上下文拼装下沉到 service 或独立子路由

### 3.3 数据库迁移与真实库状态容易脱节

位置：

1. `AriaAI/backend/alembic/versions/*.py`
2. `.github/workflows/deploy.yml`
3. `DEPLOY.md`

现状：

1. 近期已经出现过表存在但 Alembic 版本未同步、列已存在但迁移仍尝试新增的情况
2. 一旦迁移失败，接口容易直接报 500

风险：

1. 部署表面成功，但业务接口不可用
2. 排查依赖人工经验，恢复成本高

目标状态：

1. 迁移脚本尽量具备幂等性
2. 部署时迁移失败应明确中断
3. 发布后增加数据库结构健康检查

### 3.4 项目上下文隔离需要持续加固

位置：

1. `AriaAI/backend/app/services/context_builder.py`
2. `AriaAI/backend/tests/test_chat_flow.py`

现状：

1. 项目级对话与摘要理论上应以当前项目为主
2. 历史上同客户多项目场景出现过跨项目内容混入
3. 最近已经补了关键边界，但还需要继续守住

风险：

1. AI 回答引用到其他项目上下文，造成误导
2. 项目级文件或检索范围如果控制不严，会出现越权感知

目标状态：

1. `project` scope 只使用当前项目上下文
2. `client` scope 只能在明确客户映射成立时扩展
3. 显式传入文档 ID 时保持可解释且可测试

### 3.5 项目页仍有历史编码污染

位置：

1. `aria-web/src/pages/projects/ProjectDetailLayout.tsx`
2. `aria-web/src/pages/projects/ProjectTodosTab.tsx`
3. 其他历史文档与页面局部文案

现状：

1. 已清理部分中文乱码
2. 仍需持续检查项目页和文档中的历史污染

风险：

1. 用户直接看到乱码，影响专业感
2. 后续修改时很难精确替换，容易扩大改动面

目标状态：

1. 页面文案统一 UTF-8
2. 文档与代码文件不再混入历史乱码

## 4. 安全与稳定性问题

### 4.1 JWT 与 API Key 存储

位置：

1. `AriaAI/backend/app/core/security.py`
2. LLM provider 相关模型与配置

建议：

1. 启动时拒绝默认弱 `SECRET_KEY`
2. 用户 API Key 改为加密存储
3. 预留密钥轮换能力

### 4.2 文件路径边界

位置：

1. `AriaAI/backend/app/routers/projects.py`

建议：

1. 所有文件路径统一通过 `Path.resolve()` 校验
2. 下载前验证文件归属当前项目
3. 不向前端暴露服务端真实绝对路径

### 4.3 认证限流

位置：

1. `AriaAI/backend/app/routers/auth.py`

建议：

1. 为登录接口增加限流
2. 提升密码规则与失败保护机制

### 4.4 Markdown / 富文本渲染

位置：

1. `aria-web/src/components/MarkdownRenderer.tsx`

建议：

1. 明确禁止原始 HTML 直通
2. 若恢复更强富文本能力，优先引入 `DOMPurify`
3. 在 Nginx 层补 CSP

1. 项目页前后端不再依赖两个超大文件承载主逻辑

5. 安全高风险项进入明确治理路径
