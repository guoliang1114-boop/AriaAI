# AriaAI 代码问题清单

> 更新日期：2026-04-13
> 范围：基于当前 `main` 分支最新重构结果重新核对

---

## 1. 最高优先级问题

### 1.1 聊天链路已拆分，但仍缺少回归测试

位置：

- `AriaAI/backend/app/routers/chat.py`
- `AriaAI/backend/app/routers/chat_conversations.py`
- `AriaAI/backend/app/routers/chat_export.py`
- `AriaAI/backend/app/routers/chat_diagnostics.py`
- `AriaAI/backend/app/services/chat_streaming.py`
- `AriaAI/backend/app/services/chat_store.py`

现状：

- `chat.py` 已从原来的超大文件拆到约 32 行
- 会话 CRUD、导出、诊断、流式编排已经分散到独立 router/service
- 当前主要风险已经从“结构过重”转为“拆分后缺少自动化保护”

影响：

- 后续继续改工具调用、SSE、标题生成、导出时，容易出现跨模块回归
- 现在的重构收益还没有被测试体系稳住

建议：

- 优先为聊天主链路补最小回归测试
- 至少覆盖会话创建、流式成功、工具调用续轮、导出、错误提示

### 1.2 RAG 仍然是可用但偏基础的 baseline

位置：

- `AriaAI/backend/app/services/rag.py`
- `AriaAI/backend/app/services/context_builder.py`

现状：

- 已支持结构化引用结果，能把来源返回给前端
- 仍然使用本地 embedding + cosine similarity + top-k 检索
- `embedding` 仍保存在 JSON 字段中，缺少更强的检索索引和过滤能力

影响：

- 数据量上来后检索效率、可解释性和扩展性都会受限
- 很难继续做 metadata filter、rerank、混合检索等增强

建议：

- 后续引入 metadata filter、rerank、向量索引或独立向量库

### 1.3 导出能力已统一到后端，但前端交互仍是重复实现

位置：

- `AriaAI/backend/app/routers/chat_export.py`
- `aria-web/src/pages/chat/Chat.tsx`
- `aria-web/src/pages/projects/ProjectDetail.tsx`

问题：

- 后端导出接口已经统一
- Web 端在聊天页和项目页仍分别维护导出触发与下载反馈逻辑

影响：

- 后续改导出体验时需要多点同步
- 错误提示、loading、下载完成反馈容易继续漂移

建议：

- 抽出共享导出 hook 或 service
- 统一按钮文案、错误提示和下载完成反馈
