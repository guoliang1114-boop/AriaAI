# AriaAI 代码问题清单与优化方案

更新日期：2026-04-16（第二轮）

范围：基于当前 `main` 分支代码、历史线上问题与最近两轮优化结果整理，按真实风险与收益排序。

---

## 1. 总体判断

当前工程已经完成主闭环收敛。前后端结构拆分都已到位：
- 前端：`ProjectDetail.tsx` 已是纯路由壳，`ProjectChatTab` 和 `ProjectNotesTab` 也已深度拆分为 Hook + 子组件
- 后端：项目域 15 个独立 service 模块，`projects.py` 已是薄接口层

**现在的核心问题不再是"代码太大"，而是：**
1. 技术基础设施（生成物、工具调用、RAG 引用）已经就位，但产品表达层还没跟上
2. 部署和运维可靠性（迁移幂等性、数据库健康检查）仍需加固
3. 安全项（API Key 加密、认证限流）进入治理路径但未完成

## 3. 核心问题详述

### 3.1 生成物前端接入缺失

**位置：** `aria-web/src/pages/projects/`、`AriaAI/backend/app/routers/artifacts.py`

**现状：**
- 后端 `GeneratedFile` 模型、`artifacts` router 完整落地
- `GET /artifacts`、`GET /artifacts/{id}/download`、`DELETE /artifacts/{id}` 均可用
- 前端无任何入口，用户无法看到 AI 生成了什么文件

**风险：**
- Function calling 能力无法对用户呈现价值
- 生成的 PPT / Word / PDF 无处可查

**目标状态：**
- 项目页（Documents Tab 或新 Generated Tab）展示生成文件列表
- 聊天消息中 AI 生成文件时渲染文件卡片（名称 + 类型 + 下载）

---

### 3.2 RAG 引用来源展示薄弱

**位置：** `aria-web/src/pages/projects/ProjectChatTab.tsx`、`aria-web/src/pages/chat/Chat.tsx`

**现状：**
- SSE `references` event 已有结构化数据（type / id / title）
- 前端收到后仅简单展示或忽略，没有可点击的来源卡片

**风险：**
- 顾问无法解释 AI 依据了哪些文档，可信度低
- RAG 能力存在但对用户不可见

**目标状态：**
- 回答底部展示引用文档 / 文件名列表
- 点击可跳转到知识库文档详情或项目文件

---

### 3.3 工具调用过程无前端可视化

**位置：** `aria-web/src/pages/projects/ProjectChatTab.tsx`

**现状：**
- `ToolCall` 历史已持久化到数据库
- 聊天流中工具执行过程对用户不可见
- 用户只看到最终回答，不知道 AI 中间调用了什么工具

**目标状态：**
- 聊天流中工具调用时显示状态气泡（"正在调用 generate_pptx..."）
- 工具执行完成后显示结果摘要

---

### 3.4 数据库迁移与真实库状态一致性

**位置：** `AriaAI/backend/alembic/versions/`

**现状：**
- 历史上出现过表结构已存在但 Alembic 版本未同步的情况
- 迁移脚本部分操作未加 `IF NOT EXISTS` 保护
- 迁移失败时部署流没有明确中断

**风险：**
- 部署表面成功，业务接口实际不可用
- 排查依赖人工经验

**目标状态：**
- 迁移脚本幂等（关键操作加保护）
- 部署流加迁移失败中断
- 发布后增加数据库结构健康检查

---

### 3.5 Skills 与项目空间联动弱

**位置：** `aria-web/src/pages/projects/ProjectChatTab.tsx`、`aria-web/src/pages/skills/Skills.tsx`

**现状：**
- 15 个专业咨询 Skill 已落地（根因分析 / 提案挑战 / 财务健康诊断等）
- 从项目聊天直接选择 Skill 的交互路径不流畅
- 项目上下文无法自动注入 Skill 执行

**目标状态：**
- 项目聊天界面支持 Skill 选择器
- Skill 执行时自动带入当前项目上下文
- Skill 执行结果可一键保存为项目文档
