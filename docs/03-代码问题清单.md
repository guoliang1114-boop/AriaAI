# AriaAI 代码问题清单与优化方案

更新日期：2026-04-16

范围：基于当前 `main` 分支代码、近期线上问题与最近几轮优化结果整理，按真实风险与收益排序。

这份文档不只记录问题，也用于指导后续持续优化与提交节奏。

## 1. 总体判断

当前工程已经具备稳定可用的主链路，但项目域的功能增长很快，代码结构、数据库迁移和自动化保障还需要继续补强。

现在最值得持续投入的不是“再堆新功能”，而是以下三类工程化工作：

1. 降低项目页前后端的复杂度
2. 收紧项目上下文隔离与数据边界
3. 用测试和部署校验减少线上回归

## 3. 核心问题

### 3.1 `ProjectDetail.tsx` ✅ 已完成清理（2026-04-16）

历次拆分后，`ProjectDetail.tsx` 已缩减为约 125 行的纯路由壳：
- 调用 `useProjectDetailData(id)` 拉取数据
- 通过 `<ProjectDetailLayout>` 渲染 Header 与 Tab 导航
- 通过 React Router `<Routes>` 分发 Overview / Documents / Milestones / Financials / Settings 子页面
- Chat / Notes / Todos 三个 Tab 通过 `ProjectDetailLayout` 中的 `PersistentProjectTabs` 持久化渲染

所有历史遗留内联实现、旧导航配置、EditProjectModal、旧版 OverviewTab 等均已删除。

### 3.2 `projects.py` 仍有部分接口层与业务逻辑耦合

位置：

1. `AriaAI/backend/app/routers/projects.py`

现状：

1. 项目域的主要子模块（todos / notes / files / folders / financials / members / milestones / contexts / deletion / details / documents）已全部下沉为独立 service
2. `projects.py` 目前仍保留部分内联的数据库查询和格式化逻辑
3. AI 润色、文件上传触发摘要生成等流程仍在 router 层编排

风险：

1. router 层仍会膨胀
2. 少数路由的业务规则仍与接口层耦合

目标状态：

1. router 只处理输入校验和响应格式化
2. 所有数据库访问和业务规则通过 service 调用

### 3.3 数据库迁移与真实库状态容易脱节

位置：

1. `AriaAI/backend/alembic/versions/*.py`
2. `.github/workflows/deploy.yml`
3. `DEPLOY.md`

现状：

1. 近期已经出现过表存在但 Alembic 版本未同步、列已存在但迁移仍尝试新增的情况
2. 一旦迁移失败，接口容易直接报 500

风险：

1. 部署表面成功，但业务接口不可用
2. 排查依赖人工经验，恢复成本高

目标状态：

1. 迁移脚本尽量具备幂等性
2. 部署时迁移失败应明确中断
3. 发布后增加数据库结构健康检查

### 3.4 项目上下文隔离需要持续加固

位置：

1. `AriaAI/backend/app/services/context_builder.py`
2. `AriaAI/backend/tests/test_chat_flow.py`

现状：

1. 项目级对话与摘要理论上应以当前项目为主
2. 历史上同客户多项目场景出现过跨项目内容混入
3. 最近已经补了关键边界，但还需要继续守住

风险：

1. AI 回答引用到其他项目上下文，造成误导
2. 项目级文件或检索范围如果控制不严，会出现越权感知

目标状态：

1. `project` scope 只使用当前项目上下文
2. `client` scope 只能在明确客户映射成立时扩展
3. 显式传入文档 ID 时保持可解释且可测试

### 3.5 项目页历史编码污染 ✅ 已完成清理（2026-04-16）

已修复范围：
- `ProjectDetailLayout.tsx`：项目空间页头、导航标签乱码
- `ProjectTodosTab.tsx`：负责人选择器、标题、空态、错误提示、删除确认弹窗
- `ProjectSettingsTab.tsx`：成员操作、AI 助手、危险操作区、删除确认弹窗中文文案

- `projects.py`：咨询售前模板目录、文件名、摘要和 Markdown 正文乱码

## 4. 安全与稳定性问题

### 4.1 JWT 与 API Key 存储

位置：

1. `AriaAI/backend/app/core/security.py`
2. LLM provider 相关模型与配置

建议：

1. 启动时拒绝默认弱 `SECRET_KEY`
2. 用户 API Key 改为加密存储
3. 预留密钥轮换能力

### 4.2 文件路径边界

位置：

1. `AriaAI/backend/app/routers/projects.py`

建议：

1. 所有文件路径统一通过 `Path.resolve()` 校验
2. 下载前验证文件归属当前项目
3. 不向前端暴露服务端真实绝对路径

### 4.3 认证限流

位置：

1. `AriaAI/backend/app/routers/auth.py`

建议：

1. 为登录接口增加限流
2. 提升密码规则与失败保护机制

### 4.4 Markdown / 富文本渲染

位置：

1. `aria-web/src/components/MarkdownRenderer.tsx`

建议：

1. 明确禁止原始 HTML 直通
2. 若恢复更强富文本能力，优先引入 `DOMPurify`
3. 在 Nginx 层补 CSP
