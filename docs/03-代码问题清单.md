# AriaAI 代码问题清单

> 更新日期：2026-04-13
> 范围：基于当前 `main` 分支代码重新核对

---

## 1. 最高优先级问题

### 1.1 `chat.py` 仍然是过重的核心路由

位置：

- `AriaAI/backend/app/routers/chat.py`

现状：

- 文件约 788 行
- 同时承担会话 CRUD、消息持久化、SSE 流式编排、工具调用续轮、模型测试、导出接口等职责
- 虽然 `context_builder.py`、`provider_selector.py`、`title_generator.py` 已拆出，但主路由仍然聚合了太多运行时分支

影响：

- 聊天链路回归风险高
- 流式、工具调用、导出等能力耦合在一起，排查问题成本高
- 后续新增 provider 或消息能力时，改动面仍然会集中落在单文件

建议：

- 继续把 `chat.py` 拆成 `stream orchestration`、`message persistence/history`、`export`、`diagnostics/test` 等子职责

### 1.2 知识库 `vector_status` 前后端契约仍未对齐

位置：

- `AriaAI/backend/app/models/db.py`
- `AriaAI/backend/app/services/rag.py`
- `aria-web/src/types/api.ts`
- `aria-web/src/types/enums.ts`
- `aria-web/src/pages/knowledge/Knowledge.tsx`

问题：

- 后端实际状态是 `pending | processing | synced | failed`
- 前端类型和页面仍按 `pending | indexed | failed` 渲染
- `Knowledge.tsx` 的统计和状态映射没有覆盖 `processing` / `synced`

影响：

- 知识库页面状态展示和统计会失真
- 类型定义已经不能准确描述真实 API 返回
- 这类状态漂移会继续扩散到筛选、统计、国际化文案

建议：

- 统一以一套后端枚举为准
- 前端仅维护展示映射，不再自造并行状态名

### 1.3 项目阶段模型仍有重复定义

位置：

- `aria-web/src/types/enums.ts`
- `aria-web/src/pages/projects/ProjectDetail.tsx`
- `aria-web/src/pages/projects/NewProject.tsx`

问题：

- `types/enums.ts` 已经定义了后端状态和 UI 子阶段映射
- 但 `ProjectDetail.tsx`、`NewProject.tsx` 仍各自维护一套 `PROJECT_STAGES`
- 页面层继续保留 `LEGACY_STAGE_MAP` 和本地 `ProjectStage` 类型

影响：

- 项目状态/阶段的展示、创建、编辑逻辑仍有漂移风险
- 后续若新增阶段或调整映射，需要多点同步

建议：

- 把项目阶段配置收敛到共享类型模块
- 页面只消费统一配置，不再各自声明阶段字典

### 1.4 设置体系已有分层说明，但 Web 端“生效来源”仍然分裂

位置：

- `AriaAI/backend/app/routers/settings.py`
- `AriaAI/backend/app/config.py`
- `aria-web/src/config/api.ts`
- `aria-web/src/pages/settings/ServerSettings.tsx`

问题：

- 后端已经有三层配置说明：运行时设置、环境变量、代码默认值
- Web 端服务器地址仍同时依赖 `localStorage.serverUrl`、`/settings/api_base_url`、`VITE_API_URL`
- `ServerSettings.tsx` 的未保存判断也主要基于本地存储与环境变量，而不是统一的“当前生效值”

影响：

- 用户看到的“当前地址”和真正请求使用的地址容易出现理解偏差
- 设置层级虽已落地在文档，但尚未完整落地到 Web 的交互模型

建议：

- 明确 Web 端 API URL 的唯一生效来源
- 在设置页直接展示“当前值来自 localStorage / DB / env / default”

## 2. 中优先级问题

### 2.1 RAG 仍然是可用但偏基础的 baseline

位置：

- `AriaAI/backend/app/services/rag.py`
- `AriaAI/backend/app/services/context_builder.py`

现状：

- 已支持结构化引用结果，能把来源返回给前端
- 仍然使用本地 embedding + cosine similarity + top-k 检索
- `embedding` 仍保存在 JSON 字段中，缺少更强的检索索引和过滤能力

建议：

- 后续引入 metadata filter、rerank、向量索引或独立向量库

### 2.2 导出能力已落地，但前端交互仍是重复实现

位置：

- `AriaAI/backend/app/routers/chat.py`
- `aria-web/src/pages/chat/Chat.tsx`
- `aria-web/src/pages/projects/ProjectDetail.tsx`

问题：

- 后端导出接口已经统一
- 但 Web 端在聊天页和项目页分别维护导出触发与下载反馈逻辑

建议：

- 抽出共享导出 hook 或 service
- 统一按钮文案、错误提示和下载完成反馈
