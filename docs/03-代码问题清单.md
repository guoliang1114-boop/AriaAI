# AriaAI 代码问题清单

> 更新日期：2026-04-14
> 范围：基于当前 `main` 分支代码重新核对，按真实风险排序。

---

## 1. 最高优先级问题

### 1.1 `ProjectDetail.tsx` 仍是新的超大前端文件

位置：

- `aria-web/src/pages/projects/ProjectDetail.tsx`

现状：

- 文件体量约 4550 行
- 同时承载项目详情布局、路由子页面、文件管理、项目聊天、导出交互、财务、里程碑、设置等大量职责

影响：

- 迭代项目页时极易引入跨区域回归
- 阅读、定位和复用成本很高
- 新增 notes / todos 后，这个页面继续膨胀

建议：

- 继续按标签页或能力域拆分
- 优先把项目聊天、文件管理、财务设置分别抽成更独立的容器组件

### 1.2 `projects.py` 已成为新的重路由

位置：

- `AriaAI/backend/app/routers/projects.py`

现状：

- 文件体量约 794 行
- 同时处理项目 CRUD、详情聚合、文件上传、里程碑、财务、待办、笔记 AI 润色、我的待办等职责

影响：

- 项目功能继续增加时，会重复经历 `chat.py` 早期的问题
- 测试与维护边界模糊

建议：

- 尽早按 `projects_core / project_files / project_notes / project_todos / project_financials` 拆分 router 或 service

### 1.3 项目聊天仍存在“统一 API 配置未完全收口”的残留点

位置：

- `aria-web/src/pages/projects/ProjectDetail.tsx`

现状：

- 大部分 Web 请求已走统一 API 配置
- 但项目页聊天流式请求仍直接写死 `fetch("/api/chat/send")`

影响：

- 会绕过 `src/config/api.ts` 的统一来源控制
- 在自定义后端地址、反向代理差异或多环境部署下容易出现行为不一致

建议：

- 将项目页聊天 SSE 请求也收口到统一 API 基址获取逻辑
- 最好与聊天页共享同一套发送封装

### 1.4 自动化测试覆盖仍然偏窄

位置：

- `AriaAI/backend/tests/test_chat_flow.py`

现状：

- 当前明确存在的后端回归测试主要集中在聊天主链路
- 新增的项目 notes / todos、项目详情聚合、知识库、设置来源等没有相应回归测试

影响：

- 近几轮重构后的收益还没有被完整测试体系保护
- 项目工作台继续演化时，容易出现“局部可用、整体回退”

建议：

- 下一批优先补项目详情聚合、todos CRUD、notes AI 润色与知识库状态流转测试

## 2. 中优先级问题

### 2.1 可见文案仍有明显乱码残留

位置：

- `aria-web/src/pages/Welcome.tsx`
- `aria-web/src/pages/projects/ProjectDetail.tsx`
- `aria-web/src/pages/projects/ProjectNotesTab.tsx`
- `aria-web/src/pages/projects/ProjectTodosTab.tsx`
- `AriaAI/backend/app/routers/projects.py`

现状：

- 代码结构已经比之前整洁
- 但多处中文常量、注释、默认文案仍有编码历史遗留

影响：

- 直接影响产品专业感与内部维护效率
- 文案、注释和默认值难以可靠复用

建议：

- 单独开一轮“编码与文案治理”
- 先修可见文案，再修注释和默认数据

### 2.2 RAG 仍是可用但偏基础的 baseline

位置：

- `AriaAI/backend/app/services/rag.py`
- `AriaAI/backend/app/services/context_builder.py`

现状：

- 已支持结构化引用回传
- 仍使用本地 embedding + cosine similarity + top-k 检索
- 向量数据仍保存在 JSON 字段中

影响：

- 数据规模上来后，检索质量、过滤能力和扩展性会成为瓶颈

建议：

- 后续引入 metadata filter、rerank 与更清晰的向量索引方案

### 2.3 文档需要持续跟随代码演进

位置：

- `docs/*.md`

现状：

- 本轮已经重新同步主要文档
- 但当前项目变化频率较高，文档再次滞后的风险依然存在

建议：

- 后续把“更新 docs”作为每轮较大重构的收尾动作
