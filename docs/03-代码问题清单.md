# AriaAI 代码问题清单

> 更新日期：2026-04-12
> 范围：按最新主线代码重新整理

---

## 1. 最高优先级问题

### 1.1 残余乱码仍然广泛存在

位置：

- `aria-web/src/pages/chat/Chat.tsx`
- `aria-web/src/pages/settings/AISettings.tsx`
- `aria-web/src/types/enums.ts`
- `AriaAI/backend/app/models/db.py`
- `AriaAI/backend/app/services/context_builder.py`

问题：

- 部分用户可见文案和注释仍存在 mojibake

影响：

- 用户体验受损
- i18n 与枚举标签难以收敛
- 文档和代码理解成本升高

建议：

- 优先清理 UI 文案与枚举标签
- 再逐步清理注释和历史字符串

### 1.2 默认 API 策略仍偏开发环境

位置：

- `aria-web/src/config/api.ts`

问题：

- 虽然 API 地址已经统一，但默认值仍是 `http://127.0.0.1:8000`

影响：

- 对远程部署和共享环境不够友好
- 容易让用户误判当前实际连接目标

建议：

- 区分开发默认值与生产默认值
- 在设置页显示“当前生效来源”

### 1.3 枚举和值还没有完全前后端对齐

位置：

- `aria-web/src/types/enums.ts`
- `aria-web/src/types/api.ts`
- `AriaAI/backend/app/models/db.py`

问题：

- 前端开始收敛枚举是好事
- 但仍有标签乱码，且部分状态值与后端实现未完全统一

影响：

- 组件行为和展示标签可能出现偏差

建议：

- 建立以后端为准的枚举定义源
- 前端只做展示层映射

### 1.4 RAG 仍然是 baseline 实现

位置：

- `AriaAI/backend/app/models/db.py`
- `AriaAI/backend/app/services/rag.py`

问题：

- embedding 仍存为 JSON
- 检索仍以简单相似度 top-k 为主

影响：

- 规模和性能上限明显
- 引用解释性有限

建议：

- 后续引入 metadata filter、rerank 和向量索引能力

## 2. 中优先级问题

### 2.1 `chat.py` 仍然过重

位置：

- `AriaAI/backend/app/routers/chat.py`

现状：

- 本轮已经把上下文组装拆到 `context_builder.py`
- 但 provider 选择、SSE、消息持久化、标题生成等仍集中在 `chat.py`

建议：

- 继续下沉 provider 选择与消息编排逻辑

### 2.2 CORS 默认仍较宽松

位置：

- `AriaAI/backend/app/config.py`
- `AriaAI/backend/main.py`

问题：

- 已支持通过 env 配置
- 但默认仍偏向开发模式

建议：

- 区分 dev/prod 配置模板

### 2.3 后端配置虽然统一，但设置体系还未完全产品化

位置：

- `AriaAI/backend/app/config.py`
- `AriaAI/backend/app/routers/settings.py`
- `aria-web/src/pages/settings/*`

问题：

- 配置项正在收敛
- 但环境变量、数据库设置和前端设置页之间仍有多层来源

建议：

- 明确哪些配置属于部署期
- 哪些配置属于运行期

## 3. 已经修复、应从旧清单移除的问题

以下问题在这轮代码中已明显改善，不应再作为主问题继续保留：

- `task_runner.py` 把 async LLM 调用当同步函数使用
- Web API 地址多处硬编码且不统一
- 仓库持续提交 `backend/data` 运行产物
