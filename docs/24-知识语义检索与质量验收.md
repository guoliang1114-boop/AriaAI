# 知识语义检索与质量验收

日期：2026-09-19。适用于新版 Source-scoped 知识库；旧 RAG 的 Provider、原生 ACL 和 HITAS 不变。

## 向量身份与混合检索

新增本地 FastEmbed 适配，默认模型 `BAAI/bge-small-zh-v1.5`。Query 和 Passage 分别通过模型对应接口编码；资料正文不发送到外部 embedding API。首次使用需要下载公开模型权重，生产建议预热后启用。

`KNOWLEDGE_EMBEDDING_PROVIDER=hash` 保持离线基线；配置为 `fastembed` 后，新建/重建索引使用语义向量。哈希身份为 `aria-hash-v1:1536`，语义身份为 `fastembed-v1:<model>:pad1536`。历史误标为 `all-MiniLM-L6-v2` 的哈希分块只参与词法匹配，绝不当作真实语义向量。模型或身份变更必须重建索引。

现有 pgvector 列固定 1536 维，本地短向量归一化后补零到 1536，保持余弦相似度不变；无需数据库迁移。拒绝非有限值、空/零向量、数量不匹配和超过存储维度的结果。索引失败不静默换算法；新向量生成后仍在原生最终授权和来源 SHA-256 复核事务中提交。

语义模式缩小中文分块为最多 384 字符、64 字符重叠，减少 512-token 模型窗口截断的风险；这是字符上限，并非精确 tokenizer 保证。检索在 Source ACL、状态、精确范围与文档过滤通过后才调用模型。只比较完全一致的向量身份，语义相似度达到配置阈值（默认 0.5）才能独立召回；哈希相似度只用于词法候选的微量排序。语义服务故障保留授权范围内的词法结果，返回 `embedding_status=unavailable`。

搜索响应增加 `retrieval_mode`、`embedding_status`、`embedding_coverage`。只读权威报告增加模型配置有效性、兼容/需重建/语义/哈希分块数，不记录正文。

## 启用与回滚

1. 在目标环境先运行 `python scripts/knowledge_retrieval_eval.py --semantic --enforce`，预热模型并检查中文样例。
2. 设置 `KNOWLEDGE_EMBEDDING_PROVIDER=fastembed`，按机器容量设置 `KNOWLEDGE_EMBEDDING_THREADS`（默认 2，上限 8）和模型缓存目录；重启后通过原生 `POST /knowledge/sources/{source_id}/documents/{document_id}/reindex` 逐文档重建。该入口要求写权限，使用现有耐久任务/重试机制，不直接批量改数据库。
3. 查看只读 `knowledge_read_authority_report.py` 的 embedding 覆盖度，并验收真实业务问题、来源引用与无关问题排除。
4. 回滚配置为 `hash` 时，语义索引仍能提供词法结果，不会被错误地按哈希相似度比较；需要恢复哈希索引时仍走原生重建。原文、Source 和文档身份保持不变。

### 可追踪的配置切换

2026-09-23 起，生产配置使用独立的 `Knowledge Provider Switch` Actions 工作流，输入 `provider=fastembed` 或 `hash`。工作流与正常部署共用维护锁，先执行对应模式的合成检索预检和只读权威报告，再生成经过验证的 PostgreSQL 备份。`scripts/knowledge_provider_switch.py` 以 0600 权限备份 `.env`，保留其余配置，原子替换 Provider 并重启已有 PM2 进程；健康检查必须看到新 PID 和 `/health` 成功。它不重建业务索引，模型缓存配置仍沿用 `config.py`。

如果 PM2 或调用进程环境中已存在 Provider 覆盖，工具在修改前拒绝执行，避免 `.env` 与有效配置不同。启动失败会恢复原配置并再次验证健康；若期间 `.env` 被其他操作者修改，则保留该修改和私有备份并明确报告回滚未完成。备份不提交仓库、不输出正文。手动回滚使用同一工作流的 `hash` 输入；不会撤销已经完成的索引任务。

## 评测边界

`tests/fixtures/knowledge_retrieval_zh.json` 是完全合成的 12 个中文场景，覆盖精确问法、同义表达与无关问题。脚本在独立内存 SQLite 中运行实际检索路径，无生产写入。离线模式检查词法子集，`--semantic` 检查全部场景。固定样例用于回归，不代表真实知识库的召回率；正式上线仍须用业务资料验收并记录 P50/P95 耗时。

报告同时记录模型/资料 embedding 准备耗时和检索 P50/P95（nearest-rank）。检索是在 passage embedding 预热模型后执行，包含查询 embedding 与实际检索；准备耗时单列。2026-09-19 至 20 日续验：词法子集 5/5，语义场景 12/12；本机预热检索 P50 6 ms、P95 8 ms，embedding 准备 185.10 ms。仅为固定小样本与已有模型缓存下的开发机结果，不能推断大库、首次模型下载或线上对话端到端耗时。可导入评测函数在成功或失败后都会恢复调用方 Provider 配置。

上游接口说明：[FastEmbed Retrieval](https://qdrant.github.io/fastembed/qdrant/Retrieval_with_FastEmbed/)。运行依赖沿用仓库既有 `fastembed==0.4.2`，不复制外部实现，不引入 Codex 运行依赖。
