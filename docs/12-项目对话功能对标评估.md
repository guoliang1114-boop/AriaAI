# 项目对话（Project Chat）功能对标评估

> 评估日期：2026-05-14
> 对标对象：GitHub Copilot Codex / Cloud Code / Cursor / Claude Code 客户端（2026 Q1）
> 评估前提：AriaAI 是远程部署的 Web 应用，非本地 IDE/编辑器插件

---

## 一、对标对象的功能基准（2026 年一线 AI 客户端）

2026 年，顶级 AI 编程/工作助手的核心能力已收敛到以下 6 个维度：

| 维度 | Codex (OpenAI) | Cursor | Claude Code | Copilot Agent |
|------|----------------|--------|-------------|---------------|
| **形态** | Terminal CLI | VS Code Fork IDE | Terminal CLI | IDE Plugin + GitHub Cloud |
| **Agent 模式** | 全自主（计划→执行→验证→迭代） | Composer + Agent（多文件编辑+终端） | 全自主（1M 上下文） | 多文件编辑 + 自修复 + PR 自动化 |
| **上下文控制** | `@file` / `@folder` / `@symbol` | `@` 提及 + 代码库语义索引 | 全代码库读取 | 代码库索引 + `@` 提及 |
| **Diff / 审阅** | 终端 diff | 可视化 Diff + 接受/拒绝 | 终端 diff + Git 自动提交 | PR 内联审阅 |
| **模型切换** | GPT-5.4 固定 | Claude / GPT / Gemini / 自定义 | Claude Opus 固定 | GPT / Claude / Gemini 切换 |
| **后台任务** | Agent Teams（并行） | Cloud Agents（后台沙箱） | 后台持续运行 | Coding Agent（Issue→PR） |
| **MCP 生态** | ✅ Agents SDK | ✅ MCP Server | ✅ MCP | ✅ GitHub MCP |
| **终端执行** | 完整 shell | 完整 shell | 完整 shell | GitHub Actions VM |

**关键共识**：2026 年的 AI 客户端已从"聊天问答"进化为"自主 Agent"——用户说"做这件事"，AI 自主计划、执行多步骤、调用工具、处理错误、返回结果。

## 二、AriaAI 项目对话当前功能全景

### 2.1 已实现的能力（值得肯定的）

#### 聊天基础层
- ✅ **SSE 流式输出**：`chat_streaming.py` 完整的流式编排，支持 text/status/tool_result/timing/done 事件
- ✅ **停止生成**：`AbortController` 中断 SSE 流，前端红色停止按钮
- ✅ **Markdown 渲染**：`react-markdown` + `remark-gfm`，代码块带复制按钮
- ✅ **多轮对话**：24 条历史消息窗口，对话持久化到 PostgreSQL
- ✅ **对话管理**：新建、重命名、删除、按今天/昨天/本周/更早分组
- ✅ **全屏模式**：支持 Escape 退出，body overflow 锁定
- ✅ **文件预览侧边栏**：Markdown 文件右侧预览，可拖拽调整宽度
- ✅ **国际化**：中英文完整覆盖

#### 上下文管理层（AriaAI 的核心优势）
- ✅ **项目记忆注入**：结构化 `context_memory_json` → 项目简报/阶段/目标/风险/待办/里程碑/财务
- ✅ **客户记忆注入**：决策模式、敏感话题、关键联系人
- ✅ **结构化干系人**：`ClientStakeholder` 实体注入 AI 上下文，聊天中一键识别并捕获
- ✅ **RAG 知识库**：project / client / global 三级范围切换，自动触发检索
- ✅ **文件内容注入**：用户询问文件时自动提取文本（PDF/DOCX/TXT/MD 等）
- ✅ **工作台全局上下文**："全部项目情况"等查询自动注入全项目清单
- ✅ **记忆同步状态**：头部显示记忆版本/同步状态/自动刷新

#### 工具调用层
- ✅ **Markdown 文档工具**：`read_project_markdown_document` / `update_project_markdown_document`
- ✅ **Office 文档工具**：`write_project_office_document`（PPT/DOCX/XLSX/PDF）
- ✅ **工具执行可视化**：`ProjectChatToolCallCard`，4 色状态（pending/running/completed/error）
- ✅ **工作流步骤可视化**：4 步工作流（判断→准备→执行→整理），带步骤序号和日志展开
- ✅ **生成物展示**：`ProjectChatArtifactCard`，支持打开/下载
- ✅ **工具调用循环**：P1（模型规划）→ P2（工具执行）→ P3（整理回复），支持 continuation

#### Skill 系统层
- ✅ **Skill 选择器**：下拉菜单按 category 分组
- ✅ **Skill 模板变量**：用户填写模板变量后发送
- ✅ **Skill 自动判断**：`_should_apply_skill()` 根据关键词/长度/意图自动触发
- ✅ **Skill 结果沉淀**：顶部"沉淀结果/沉淀对话"按钮，保存为项目文档/笔记
- ✅ **PPT 自动兜底**：`digital-strategy` Skill 未生成 PPT 时自动补充

#### 记忆与干系人层
- ✅ **会前简报一键带入**：`/projects/:id/briefing` → Chat 自动填充 prompt
- ✅ **干系人自动检测**：AI 回复结束后自动检测干系人候选，底部 Banner 一键添加
- ✅ **消息保存到笔记**：每条 assistant 消息可保存到项目空间
- ✅ **Pending Markdown Save**：工具写入后二次确认，防止误覆盖

#### 工程鲁棒性
- ✅ **心跳机制**：`_iter_with_heartbeat()` 防止长时间无输出导致代理超时
- ✅ **截断续写**：输出超长时自动 continuation，提示用户发送"继续"
- ✅ **模型路由**：根据查询类型自动切换轻量/重模型（Fast Path / Portfolio / Inventory）
- ✅ **错误降级**：空回复时返回友好提示，工具失败时返回可恢复信息
- ✅ **Title 自动生成**：对话首次回复后后台生成标题

### 2.2 已具备但可优化的能力

| 能力 | 现状 | 优化空间 |
|------|------|----------|
| 引用链接 | `Reference` 类型显示为标签 | 缺乏 @提及 的交互式选择器 |
| 文件预览 | 仅 Markdown | 应支持 PDF/图片等更多格式 |
| 工具调用循环 | P1→P2→P3，最多 1 轮 follow-up + 1 轮 re-follow-up | 不支持多轮自主迭代 |
| 上下文窗口 | 40000 字符文件注入上限 | 未利用 1M token 长上下文 |
| 代码块 | 仅复制按钮 | 缺乏"应用到项目文件"按钮 |

## 三、功能维度对比矩阵

> 评分：★ = 缺失/差距大，★★ = 有基础需加强，★★★ = 良好，★★★★ = 优秀，★★★★★ = 对标一线

| 维度 | AriaAI | Codex/Cursor | 差距说明 |
|------|--------|--------------|----------|
| **聊天交互** | ★★★★ | ★★★★★ | 流式、Markdown、代码块复制均具备，差距在"编辑体验" |
| **上下文控制** | ★★★ | ★★★★★ | 系统自动注入，用户无法 `@file` 精准控制 |
| **Agent 自主能力** | ★★ | ★★★★★ | 最大差距。AI 不能自主计划多步骤、不能迭代修复 |
| **Diff / 审阅** | ★ | ★★★★★ | 完全没有 Diff 视图，直接写入无确认 |
| **工具生态** | ★★★ | ★★★★★ | 内置 4 个工具，无 MCP 扩展能力 |
| **多模型切换** | ★★ | ★★★★★ | 系统配置模型，用户不能切换 |
| **后台任务** | ★ | ★★★★ | 无后台 Agent，所有操作同步阻塞 |
| **代码库索引** | ★★ | ★★★★ | RAG 仅覆盖知识文档，未索引项目文件 |

| **记忆系统** | ★★★★★ | ★★★ | **AriaAI 领先**——结构化记忆、干系人、会前简报是垂直领域优势 |
| **Skill 工作流** | ★★★★ | ★★★ | **AriaAI 领先**——Skill→Chat→沉淀→记忆刷新闭环成熟 |

## 四、根因分析：为什么存在差距？

### 4.1 架构层面的根因

| 差距 | 根因 | 修复难度 |
|------|------|----------|
| 无 Agent 自主计划 | 当前是"单轮请求-响应"模式，无计划-执行-验证循环的持久化状态机 | 高——需引入 Agent Runtime |
| 无 Diff 视图 | Web 应用没有 Monaco/Diff Editor，且写入是直接调用工具 | 中——可集成 Monaco Diff |
| 无 @提及 | 输入框是简单 textarea，没有富文本/mention 组件 | 低——可引入 Tiptap/Slate |
| 无 MCP | 工具注册表是硬编码的 `app/tools/registry.py` | 中——需实现 MCP Client |
| 无后台任务 | SSE 连接断开即终止，无持久化任务队列 | 高——需引入 Celery/RQ + 任务状态轮询 |
| 上下文窗口小 | 担心 token 成本，手动限制 40000 字符 | 低——可调大并监控成本 |

### 4.2 产品定位的根因

Codex / Cursor 是**通用编程助手**，目标是"替代开发者写代码"。
AriaAI 是**垂直咨询助手**，目标是"替代顾问查资料、写材料、管干系人"。

这意味着：
- **不必复制全部 IDE 功能**（如 Tab 补全、语法检查）
- **必须强化垂直场景**（会前准备、客户画像、交付物生成）
- **Agent 能力在咨询场景同样关键**（"帮我准备下周的客户汇报"需要自主计划）

## 五、可行路径与优先级建议

### P0（3-4 周）—— 补齐"对话体验"短板

1. **@提及上下文选择器**
   - 输入框从 textarea 升级为 Tiptap/Slate，支持 `@文件`、`@干系人`、`@里程碑`
   - 被提及的文件自动加入 `file_ids`，干系人聚焦上下文
   - 工作量：前端 3-4 天，后端 1-2 天

2. **Diff 预览（Markdown 文件修改）**
   - 集成 `monaco-editor` 或 `react-diff-viewer`
   - `update_project_markdown_document` 工具返回 diff，用户确认后才写入
   - 工作量：前端 5-7 天，后端 2-3 天

3. **续写按钮**
   - 截断时不再仅提示文字，而是显示"继续生成"按钮
   - 点击后自动发送 `"继续"` 并衔接上下文
   - 工作量：前端 1-2 天

### P1（6-8 周）—— 引入"轻量 Agent"能力

4. **持久化任务队列（后台 Agent 基础）**
   - 引入 Celery + Redis（或 APScheduler 扩展）
   - 聊天中可发送"长耗时任务"，SSE 返回 `task_id` 后断开
   - 前端轮询任务状态，完成后推送通知
   - 工作量：后端 2-3 周

5. **计划模式（Plan Mode）**
   - 用户输入复杂请求时，AI 先返回执行计划（不执行）
   - 用户确认/修改计划后，再进入 P1→P2→P3 执行
   - 参考：Copilot CLI 的 `Shift+Tab` Plan Mode
   - 工作量：后端 1 周，前端 3-4 天

6. **多模型切换（用户级）**
   - 头部或设置面板增加模型选择器（Claude / Kimi / DeepSeek）
   - 不同查询类型自动路由 + 用户手动覆盖
   - 工作量：前端 2-3 天，后端 3-4 天

### P2（10-12 周）—— 架构升级

7. **MCP Client 支持**
   - 实现 Model Context Protocol 客户端
   - 可连接外部 MCP Server（如数据库查询、邮件发送、日历查询）
   - 这是"开放工具生态"的关键一步
   - 工作量：后端 3-4 周

8. **项目文件向量索引**
   - 将项目空间的上传文件也纳入向量索引
   - 支持 `@文件` 语义检索，不只是文件名匹配
   - 工作量：后端 2-3 周

9. **Agent Runtime（状态机）**
   - 引入 `AgentState` 实体：plan → executing → verifying → completed/failed
   - 支持多轮工具调用循环（P1→P2→P3→P4→...）
   - 支持错误自恢复（重试、降级、人工介入）
   - 工作量：后端 4-6 周

## 六、结论

### 6.1 当前水平定性

AriaAI 项目对话在**垂直咨询场景**中已达到 **可用级（Production-Ready）**，在**通用 AI Agent 体验**中处于 **初级（Early-Stage）**。

| 场景 | 当前水平 | 对标 Codex |
|------|----------|-----------|
| 会前准备（查记忆、看干系人、列风险） | ★★★★★ | ★★★（无垂直记忆） |
| 生成 PPT/方案/访谈表 | ★★★★ | ★★★★ |
| 多文件编辑（修改项目文档） | ★★ | ★★★★★ |
| 自主计划复杂任务 | ★★ | ★★★★★ |
| 后台长时任务 | ★ | ★★★★ |
| 开放工具生态 | ★★ | ★★★★★ |

### 6.2 关键判断

> **"远程 Web 应用"这个约束不是根本障碍，但确实限制了部分体验。**

- **可以达到的**：流式聊天、工具调用可视化、生成物展示、计划确认、后台任务状态追踪
- **天然受限的**：本地终端执行、IDE 内联编辑、文件系统直接操作
- **可以弥补的**：Monaco Diff 编辑器、远程命令执行（通过 SSH/容器）、浏览器本地文件读写（File System Access API）

### 6.3 一句话总结

> AriaAI 的项目对话在"顾问助手"这个定位上已经跑通了从聊天到交付物的完整闭环，**核心差距不是 UI 层，而是 Agent 层的自主能力**——AI 还不能像 Codex 那样"你交代一件事，它自主做完并汇报"。补齐这个差距需要 2-3 个月的架构投入，但 ROI 最高。
