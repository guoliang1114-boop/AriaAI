## 2. 当前产品状态

### 已经形成的主线能力

- 项目详情已经具备概览、聊天、笔记、待办、里程碑、文档、财务、项目记忆、客户侧干系人、设置等核心工作区。
- 项目记忆支持结构化生成、多视角摘要、缓存、预热、重建、固定槽位、手动提升到客户记忆。
- 客户记忆支持跨项目沉淀、客户画像、关键联系人、决策模式、敏感议题、多视角摘要。
- 客户侧干系人已经从“项目成员”概念中拆出，形成独立 Tab 和关系可视化。
- AI 记忆锚点已经拆出独立治理页，概览和聊天可直接跳转管理。
- 部署中 502/503/504 的前端提示已从“找不到项目/加载失败”改为“服务更新中/工作台恢复中”。
- 部署流已经包含前端 build、后端依赖安装、迁移治理、PM2 启动兜底、Nginx reload。

### 当前体验短板

- 首页和项目详情虽然已有错误态，但部署后仍需要更强的健康回读，避免用户刷新时撞到后端恢复窗口。
- 干系人页面目前使用客户 `contact` 字段和客户记忆 `key_contacts` 组合维护，尚未结构化为独立联系人实体。
- 项目记忆、客户记忆仍存储在 JSON 字段中，缺少版本表、diff、回滚和审计。
- Skill 已能在聊天链路中使用，但还没有成为项目/客户空间的一等动作入口。
- Memory Operations 已能查看和处理任务，但服务端聚合统计、批量治理、告警策略配置化仍未完成。

## 4. 下一阶段推荐主题

建议下一阶段命名为：

`vNext 工作流闭环与治理强化`

目标不是继续加入口，而是把已经有的入口组织成稳定闭环：

- Skill 能从项目/客户上下文启动。
- Skill 结果能保存为项目/客户资产。
- 记忆能版本化、回滚、审计。
- 干系人能从文本线索升级为结构化客户关系网络。
- 部署和任务失败能被产品化地解释、告警和处理。

## 5. 推荐 Sprint

### Sprint 1：Skill 工作流闭环

目标：让 Skill 成为项目和客户空间的一等动作。

任务：

- 项目详情新增“使用 Skill”入口，默认带入项目记忆、客户、文件、待办、里程碑。
- 客户详情/客户记忆新增“使用 Skill”入口，默认带入客户记忆和关联项目。
- Skill 输出支持保存为项目文档、项目笔记、固定锚点、客户记忆沉淀。
- 保存后明确提示是否刷新项目/客户记忆。

验收：

- 用户可以从项目/客户页面直接启动 Skill。
- 用户不需要手动复制上下文。
- Skill 输出可以沉淀，不只是一次性聊天内容。

### Sprint 2：客户侧干系人结构化

目标：把客户侧干系人从文本线索升级为结构化关系资产。

任务：

- 设计 `client_stakeholder` 或 memory 内结构化 schema。
- 字段建议：姓名、角色、组织层级、影响类型、关系状态、关注点、敏感点、沟通偏好、联系方式、最近动作。
- 干系人页面支持新增、编辑、删除、标记影响力和关系状态。
- 关系图支持按决策/使用/采购/财务/法务/IT/安全分类展示。

验收：

- 干系人页面不再只维护 `client.contact` 文本。
- AI 摘要和客户记忆能读取结构化干系人。
- 页面能回答“下一步应该找谁确认什么问题”。

### Sprint 3：记忆版本化与审计

目标：让项目/客户记忆可回滚、可审计、可对比。

任务：

- 设计 `memory_snapshot` 表。
- 每次项目/客户记忆重建保存 snapshot。
- 支持查看历史版本、触发来源、创建人、diff。
- 支持回滚，并让摘要缓存失效。

验收：

- 用户能看到记忆历史。
- 误生成或坏数据可以回滚。
- 运维可以定位某次记忆变化由哪个动作触发。

### Sprint 4：运维健康与部署体验

目标：减少部署中 502 对用户的困扰，并让异常可定位。

任务：

- 部署脚本在 reload 后增加后端 `/health` 和 `/health/db` 回读。
- GitHub Actions 输出 PM2 状态和最近日志摘要。
- 前端统一服务错误态组件。
- Welcome、ProjectDetail、ClientDetail、Settings 复用统一错误态。

验收：

- 部署完成前不误提示成功。
- 502/503/504 能被用户理解为服务恢复窗口。
- 管理员能快速看到后端是否启动、数据库是否可用、迁移是否正常。

### Sprint 5：质量与安全基线

目标：为后续更大功能迭代降低回归风险。

任务：

- 拆分后端测试 target：auth、project、client、memory、migration。
- 给项目详情、干系人、锚点、Welcome 补最小前端 smoke test。
- Markdown/XSS、文件下载路径、管理员接口权限复核。
- 项目详情接口 N+1 和列表轻量接口复核。

验收：

- 核心链路有可运行的定向测试。
- 部署前至少覆盖前端 build、迁移治理、核心后端定向测试。
- 高风险安全点有文档化结论。
