# AriaAI Web 版本开发计划

> 更新日期：2026-04-12
> 说明：按当前 `aria-web` 实际代码状态重写

---

## 1. 当前状态判断

`aria-web` 已经不是规划稿，也不是单页原型，而是第一版完整工作台。

当前已经落地：

- 登录与鉴权守卫
- Welcome 工作台
- Chat
- Projects / ProjectDetail / NewProject
- Clients / ClientDetail
- Knowledge
- Skills / SkillForm
- Settings 多子页
- AuthContext / ToastContext / ThemeContext
- i18n 中英语言包

因此，当前 Web 端所处阶段应定义为：

> UI 打磨 + 多模块收敛 + 配置统一阶段

---

## 2. 当前优先级最高的工作

### 2.1 修复 API base URL 分裂

当前有三套逻辑：

- axios client
- Chat 页流式 fetch
- ServerSettings 保存逻辑

这会直接影响远程环境切换体验。

### 2.2 清理乱码

`Chat.tsx`、`ServerSettings.tsx` 等页面中仍有大量乱码字符串，优先级很高。

### 2.3 收敛页面和组件层次

当前仍有旧页面和新目录并存，需要明确：

- 哪些页面还在使用
- 哪些页面是遗留物

### 2.4 建立统一状态语义

例如：

- 项目状态
- provider 选项
- 语言选项
- 错误提示风格

---

## 3. 功能层面的下一步

### 3.1 Chat

- 统一上下文来源与错误处理
- 提升工具调用结果展示
- 支持更明确的引用来源展示
- 优化项目/技能选择交互

### 3.2 ProjectDetail

- 做强“项目工作台”入口
- 统一文件、里程碑、财务、对话体验
- 增加项目上下文的可见性

### 3.3 Welcome

- 更强的“今日工作入口”
- 汇总即将到期事项
- 更好展示最近对话和最近项目

### 3.4 Skills

- 展示模板化输入
- 展示适用场景
- 更好的分类与搜索

---

## 4. 工程层面的下一步

### 4.1 单一配置源

抽一个共享配置模块，统一：

- API base URL
- 默认 server URL
- 语言
- provider 选项

### 4.2 类型收敛

把前后端关键枚举集中化：

- 项目状态
- 技能分类
- 消息角色
- 文档状态

### 4.3 文案收敛

所有可见文本逐步进入 `i18n/locales/*.json`。

---

## 5. 建议实施顺序

1. 修乱码
2. 统一 API 地址配置
3. 清理遗留页面
4. 收敛关键类型和枚举
5. 再做新的交互增强

---

## 6. 完成标志

当以下条件成立时，可以认为 Web 端完成“第一阶段收敛”：

- 所有页面文案无乱码
- 服务器切换对所有请求生效
- 主要页面均使用统一设计语言
- 页面目录结构和路由一一对应
- 项目与聊天链路可稳定演示
