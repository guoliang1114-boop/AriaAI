# AriaAI 网页版本开发计划

> 日期：2026-04-08
> 目的：按当前代码真实状态更新 Web 端进度判断，并明确下一阶段重点
> 原则：先收敛主链路，再补工程卫生，再做更多页面扩张

---

## 1. 当前状态判断

`aria-web` 已经不是规划稿，也不是单纯 UI 原型。

当前仓库里已经有：

- 登录页与鉴权守卫
- 欢迎页
- 聊天页
- 项目列表 / 新建项目 / 项目详情
- 知识库页
- 技能页
- 设置页多子页面
- Axios API 客户端
- Markdown 渲染组件
- 基础布局与主题样式

因此更准确的判断是：

> **Web 端已经完成第一版工作台骨架，当前进入“聊天体验打磨 + 工程收敛”阶段。**

---

## 2. 最近代码反映出的真实进展

这轮从远端同步下来的改动，重点集中在聊天体验：

- `aria-web/src/pages/chat/Chat.tsx`
- `aria-web/src/components/MarkdownRenderer.tsx`
- `aria-web/src/index.css`

目前 Web 聊天页已经具备：

- 会话分组展示
- 会话搜索
- 历史消息分页加载
- 流式输出
- 中断生成
- 项目 / 技能上下文选择
- Markdown 代码块复制
- 侧边栏折叠与展开

这说明 Web 端已经从“能不能聊”进入“聊得顺不顺、稳不稳”的阶段。

---

## 3. 当前最需要正视的问题

### 3.1 源码级乱码已经进入 Web 主页面

当前 `aria-web/src/pages/chat/Chat.tsx` 中存在真实乱码字符，已经不只是终端显示问题。

这会影响：

- UI 文案质量
- 代码可读性
- 后续页面继续开发时的复制扩散风险

### 3.2 Web 文档已明显落后且部分损坏

当前这些文件已经和真实实现不一致，甚至已乱码：

- `aria-web/README.md`
- `docs/04-网页版本开发计划.md`（本文件已重写）

### 3.3 Web 端已不是“缺页面”，而是“缺收敛”

现在更大的问题不是继续快速加页，而是：

- API 契约是否稳定
- 错误态是否一致
- 分页与加载策略是否统一
- 与 macOS 端是否共用同一套业务语义

---

## 4. 下一阶段目标

## 4.1 目标一：把聊天主链路做稳

优先跑顺这条链：

1. 登录
2. 打开聊天
3. 选择项目 / 技能
4. 发送消息
5. 流式接收回复
6. 向上加载历史消息
7. 中断生成

如果这条链不稳，Web 端的其他页面价值会被明显稀释。

## 4.2 目标二：和 macOS 端共享同一套工作台语义

必须优先统一这些对象：

- 项目
- 会话
- 消息
- 技能
- 知识文档
- 设置

必须优先统一这些行为：

- 鉴权
- 分页
- 首屏加载
- 错误提示
- 数据刷新策略

## 4.3 目标三：完成工程卫生收敛

Web 端现在必须补一条工程线：

- 清理源码乱码
- 修复 README
- 统一编码规范
- 稳定构建配置
- 避免运行产物和文档继续污染仓库

---

---

## 6. 与后端协作的重点要求

当前最需要后端稳定下来的接口：

- `/auth/*`
- `/chat/conversations`
- `/chat/conversations/{id}/messages`
- `/chat/send`
- `/projects`
- `/projects/{id}/detail`
- `/settings/*`

协作原则：

- 分页参数变更时，两端同步更新
- 新增字段时，先更新 `aria-web/src/types/api.ts`
- 不让 Web 和 macOS 各自推动后端长出不同返回结构

---

## 7. 一句话结论

> **Web 端现在最重要的不是“再做几个页面”，而是把已经做出来的聊天和项目工作台入口收敛成一个稳定、可持续迭代的第二端。**
