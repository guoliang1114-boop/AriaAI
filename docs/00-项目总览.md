> 版本：v3.0

## 1. 项目定位

AriaAI 是一个面向咨询顾问与专业服务团队的 AI 工作台。它不是单纯的聊天产品，而是围绕项目、客户、知识、技能、模板、定时任务和交付物组织完整工作流。

当前仓库包含三部分主系统：

- `AriaAI/AriaAI`：SwiftUI macOS 客户端
- `aria-web`：React + TypeScript Web 客户端
- `AriaAI/backend`：FastAPI + SQLModel 后端

产品主线已经从“单端原型”进入“多端工作台收敛期”，其中 Web 端在最近一轮更新中明显强化了 UI、一致性和 i18n 能力。

## 2. 当前已经落地的能力

### 2.1 认证与用户

- 邮箱 + 密码登录
- `UserToken` 多设备 token 表
- 中间件统一校验 `X-Auth-Token`
- `/auth/me`、用户管理、重置密码、修改密码
- 后端启动时自动 seed 默认管理员

### 2.2 项目工作台

- 项目列表、创建、编辑、删除
- 默认项目文件夹自动初始化
- 项目详情聚合接口 `/projects/{id}/detail`
- 里程碑管理
- 项目文件上传、下载、删除、摘要
- 项目财务记录与汇总
- 项目上下文生成 `/projects/{id}/generate-context`
- 项目笔记沉淀 `/projects/{id}/notes`
- AI 项目建议 `/projects/ai-suggest`

### 2.3 客户与知识

- 客户 CRUD
- 客户与知识文档关联
- 客户关联项目查询
- 知识文档上传、删除、统计、检索
- 文档切块与 embedding 存储

### 2.4 聊天与生成

- 会话列表、创建、删除、分页消息历史
- SSE 流式输出 `/chat/send`
- 项目上下文、技能 prompt、RAG 文档、项目文件上下文拼接
- Claude / Kimi 双 provider 入口
- 工具执行链路与工具结果回写
- 生成 PPT、Word、Excel、PDF、文本、JSON
- 生成物查询与下载 `/artifacts`

### 2.5 技能与设置

- Skill CRUD
- 默认技能 seed、Pro 技能 seed、模板 seed
- 工具 schema 浏览、校验、测试
- API Key 管理：Claude、Kimi、OpenAI、DeepSeek
- 通用设置表 `Setting`
- Web/i18n 语言切换

### 2.6 定时任务与模板

- APScheduler 启动与关闭
- 定时任务 CRUD、手动运行
- 模板上传、状态更新、删除

## 3. 仓库结构

```text
AriaAI/
├─ AriaAI/                    # SwiftUI macOS app
├─ backend/                   # FastAPI backend
│  ├─ app/
│  │  ├─ routers/             # 业务接口
│  │  ├─ services/            # Claude / RAG / Scheduler / Parser
│  │  ├─ tools/               # Tool registry + file generators
│  │  ├─ models/              # SQLModel 数据模型
│  │  └─ core/                # 安全与 key 管理
│  ├─ data/                   # 本地 SQLite 与上传文件
│  ├─ alembic/                # DB migration
│  └─ start*.sh/ps1/cmd       # 启动脚本
├─ aria-web/                  # React Web app
│  ├─ src/
│  │  ├─ pages/               # 登录、欢迎、聊天、项目、客户、知识、设置
│  │  ├─ components/          # Layout / MarkdownRenderer / Sidebar 等
│  │  ├─ contexts/            # Auth / Toast / Theme
│  │  ├─ i18n/                # 中英文本地化
│  │  └─ api/                 # axios client
└─ docs/                      # 项目文档
```

## 4. 技术栈

| 层 | 当前技术 |
|---|---|
| macOS 客户端 | SwiftUI, AppKit, Swift Package Manager |
| Web 客户端 | React 19, TypeScript 5.9, Vite 8, React Router 7, i18next |

| 调度 | APScheduler |
| 密钥存储 | keyring |
| 密码安全 | bcrypt |

## 5. 数据模型总览

当前核心表主要有：

- `User`, `UserToken`
- `Project`, `ProjectFolder`, `ProjectFile`, `Milestone`, `ProjectPayment`
- `Conversation`, `Message`
- `ClientRecord`
- `KnowledgeDocument`, `DocumentChunk`
- `Skill`
- `ToolCall`, `GeneratedFile`
- `ScheduledTask`
- `Template`
- `Setting`

建模特点：

- `Project` 已经承担“工作台主上下文”的角色
- `Conversation` 可挂在 `project_id` 和 `skill_id`
- `Skill` 目前以数据库记录为主，不是单独的 DSL
- `DocumentChunk.embedding_json` 仍然采用 JSON 存储 embedding

## 6. 真实运行方式

### 6.1 后端

当前后端会在 `app/config.py` 中：

- 自动读取 `backend/.env`
- 默认回退到 `sqlite:///./data/ariaai.db`

`start.sh` 也会优先 `source .env`。因此现在仓库里“远程库优先”的正确做法不是改代码，而是提供 `.env` 中的 `DATABASE_URL`。

### 6.2 Web

`aria-web/src/api/client.ts` 当前仍默认使用：

- `import.meta.env.VITE_API_URL`
- 否则回退 `/api`

而聊天页 `aria-web/src/pages/chat/Chat.tsx` 的流式请求又单独读取：

- `import.meta.env.VITE_API_URL`
- 否则回退 `http://127.0.0.1:8000`

这意味着当前 Web 端的 API 地址不是单一来源，详见问题清单。

## 8. 当前代码状态判断

项目整体状态可以概括为：

> 主功能骨架已经齐全，当前最主要矛盾不再是“没有模块”，而是“多端一致性、配置统一、工程卫生和核心链路稳定性”。

最值得优先关注的现实问题：

- 大量源码和文案存在乱码
- Web 端 API 基地址存在多套来源
- 调度任务存在异步调用错误
- 仓库提交了数据库、上传文件和生成物
- RAG 和生成链路已经可用，但还偏 baseline
