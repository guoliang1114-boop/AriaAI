# AriaAI 项目总览

更新日期：2026-04-16（第二轮）

## 1. 项目定位

AriaAI 是一套面向咨询类团队的 AI 协作工作台。

它不是单纯的聊天应用，而是把以下几类能力组织到同一套工作流里：
- 项目工作台（概览 / 聊天 / 笔记 / 待办 / 里程碑 / 财务 / 文件 / 文档）
- 客户管理与知识库
- Skills 与场景模板（含15个专业咨询场景）
- 生成物管理（Artifacts）
- 调度任务

当前日常开发主线：
- Web 客户端：`aria-web`
- Python 后端：`AriaAI/backend`
- PostgreSQL 数据库

## 2. 当前已经落地的能力

### 2.1 认证与用户

- 邮箱密码登录
- `X-Auth-Token` 鉴权
- 多设备 Token 管理（`UserToken` 表）+ 旧版 `auth_token` 向下兼容
- 用户列表、启停用、密码重置
- 三层配置体系（DB runtime → 代码默认 → 环境变量）

### 2.2 项目工作台

- 项目 CRUD，状态流转（lead / opportunity / won / delivering / archived）
- 项目详情聚合接口 `GET /projects/{id}/detail`（单次查询返回全量数据）
- 项目成员、文件夹、文件（含 AI 自动摘要）、里程碑
- 财务管理（收款 / 支出 / 里程碑付款，汇总计算）
- 项目概述与 AI 生成上下文摘要
- 项目域各子模块已下沉独立 service（11 个以上独立模块）

### 2.3 项目聊天

- 项目对话与普通工作台对话分离
- SSE 流式输出 + 工具调用支持
- 标题生成
- Markdown / PDF 导出
- 项目上下文注入（文件 + 里程碑 + 项目摘要）
- 知识范围切换（当前项目 / 当前客户 / 全局知识库）
- 项目聊天 UI 已拆分为独立 Hook 和子组件（sidebar / header / input / message pane / composer hook / conversation hook / export dropdown）

### 2.4 项目文档工作区

- 左侧 Markdown 文档树
- 右侧编辑 / 预览 / 分栏
- 默认预览模式
- 新建、重命名、删除（站内弹窗）
- AI 润色（普通 + 流式）
- 咨询类售前模板初始化（9 个预置文档）
- 聊天内容可沉淀为 Markdown 文档（新建 or merge 追加）
- Notes UI 已拆分为独立 Hook 和子组件（layout / dialogs / AI modal / document hook / actions hook / AI hook / document actions）

### 2.5 项目待办

- 项目内待办 CRUD
- 指派负责人
- 截止日期
- "我的待办"跨项目聚合
- 仪表盘显示截止日期

### 2.6 客户与知识库

- 客户 CRUD + AI 客户画像建议
- 客户详情与关联项目
- 知识文档上传、向量化、检索（fastembed + 余弦相似度）
- `KnowledgeDocument.client_id` / `project_id` 双维度归属
- 项目级知识隔离

### 2.7 Skills 与生成能力

- Skill CRUD（支持 Claude 标准 tools 格式）
- 默认咨询 Skill（6 个）+ 专业引导工作流（15 个）
  - 涵盖：根因分析、提案挑战、项目启动、项目复盘、财务健康诊断、ROI 分析、AI 用例矩阵、风险评估、OKR 设计、GTM 策略等
- 模板管理（PPTX / DOCX / PDF）
- 调度任务（APScheduler）
- 生成文件管理（`GeneratedFile` + `artifacts` 路由）

### 2.8 API Provider 管理

- 支持 Claude（Sonnet / Opus / Haiku 4.x）、Kimi、BigModel、DeepSeek（预留）
- `/settings` API key 状态查询、保存、删除
- `/chat/test-connection` 和 `/chat/test-model` 连通性测试

## 6. 当前阶段判断

当前代码已经完成"主闭环收敛"，正在进入"交付链路增强"阶段。

已经比较成型的部分：
- 基础认证（含多设备登录）
- 项目工作台主链路（8 个 Tab）
- 项目聊天（完整 SSE + 工具调用）
- 项目文档工作区（含 AI 润色）
- 项目待办（含指派 + 截止日期）
- 知识范围隔离
- 前端项目页 Tab 完全拆分
- 后端项目域 service 完全拆分
- Artifacts 生成物管理路由

技术上具备但产品表达不足：
- `GeneratedFile` / `artifacts` 路由已落地，但前端无生成物入口
- `ToolCall` 模型已落地，但工具调用过程前端无可视化
- RAG `references` SSE event 有数据，但前端引用展示弱
- 15 个专业 Skill 模板已落地，但与项目空间的联动弱
