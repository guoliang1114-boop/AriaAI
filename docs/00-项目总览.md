# AriaAI 项目总览

> 版本：v3.4
> 更新日期：2026-04-14
> 说明：基于当前 `main` 分支代码重写，用于快速建立全局认知。

---

## 1. 项目定位

AriaAI 不是单点聊天工具，而是面向咨询顾问、专业服务团队和项目交付场景的 AI 工作台。它试图把项目、客户、知识、技能、对话、文件生成和交付沉淀组织到同一套工作流里。

当前仓库包含三套主要系统：

- `AriaAI/AriaAI`：SwiftUI macOS 客户端
- `aria-web`：React + TypeScript Web 客户端
- `AriaAI/backend`：FastAPI + SQLModel 后端

---

## 2. 最近一轮关键变化

- 聊天主路由已经从“大文件”拆分为 `chat.py + conversations/export/diagnostics + chat_streaming/chat_store`
- Web 与项目页共用 `src/api/chatExport.ts`，导出能力开始收敛
- 聊天链路已有最小回归测试：`AriaAI/backend/tests/test_chat_flow.py`
- 项目空间新增 `notes` 与 `todos` 能力，并贯通到详情页
- Welcome 页面开始读取“我的待办”：`GET /projects/todos/my`
- 知识库 `vector_status` 已统一为 `pending | processing | synced | failed`
- 设置页能展示 API 地址的生效来源、当前生效值和后端保存值

这些变化说明项目已经从“功能铺设期”进入“架构收敛 + 工作台深化”阶段。

## 5. 当前架构判断

目前最积极的变化是：

- 配置与接口边界比早期更清晰
- 聊天链路已经具备基本的模块化形态
- 项目空间开始从“详情页”进化为“持续协作空间”
- 导出、标题生成、RAG 引用这类交付链路越来越完整

目前最值得优先关注的风险是：

- `aria-web/src/pages/projects/ProjectDetail.tsx` 体量过大，仍在承载过多 UI 与业务逻辑
- `AriaAI/backend/app/routers/projects.py` 已扩张成新的重路由文件
- 项目 notes/todos、知识库、设置链路的自动化测试仍明显不足
- 多处中英文文案仍存在乱码或编码历史遗留
- RAG 仍是可用 baseline，不适合更大规模检索场景
