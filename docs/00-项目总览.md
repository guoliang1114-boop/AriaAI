# AriaAI 项目总览

更新时间：2026-04-20

## 1. 项目定位

AriaAI 是面向咨询、售前、交付团队的 AI 协作工作台。它不是单纯聊天工具，而是把项目、客户、知识、Skill、生成物和后台任务治理组织成同一条业务工作流。

当前产品主线：

- 用项目承载长期上下文和交付过程。
- 用客户记忆沉淀跨项目经验、偏好和关系信号。
- 用 Skill 承载可复用的方法论与任务模板。
- 用统一任务面板治理记忆重建、摘要预热、失败重试和预算。
- 用 Alembic 迁移治理保证部署可靠性。

## 2. 当前已落地能力

### 2.1 用户与安全

- 邮箱密码登录。
- `X-Auth-Token` 鉴权。
- 多设备 Token 管理。
- 用户管理、启停用、密码重置。
- 登录失败限流。
- 弱默认 `JWT_SECRET` 启动拦截。
- Markdown 链接协议基础过滤。

### 2.2 项目工作台

- 项目 CRUD 与阶段流转。
- 项目详情聚合接口。
- 项目成员、里程碑、待办、财务、文档、笔记。
- 项目概览 AI 总结。
- 项目级 `Memory` 页面。
- 项目记忆手动刷新、槽位编辑、摘要视角。
- 项目记忆手动提升到客户记忆。

### 2.3 项目聊天

- SSE 流式输出。
- 工具调用支持。
- 标题生成。
- Markdown / PDF 导出。
- 项目上下文注入。
- 知识范围切换：项目 / 客户 / 全局。
- RAG 引用来源展示。
- 工具调用状态卡片。
- 生成物卡片与下载。
- Skill 面板与项目/客户空间联动提示。
- Skill 结果可保存并进入项目记忆刷新链路。

### 2.4 记忆系统

项目级三层记忆：

- 原始项目数据。
- 结构化项目记忆 `Project.context_memory_json`。
- 多视角摘要缓存。

客户级第四层记忆：

- 客户长期记忆 `ClientRecord.client_memory_json`。
- 项目归档自动沉淀。
- 项目记忆手动提升。
- 客户范围聊天注入。
- 客户多视角摘要与预热。

后台治理：

- 项目/客户记忆任务统一面板。
- 失败分类：`budget / rate_limit / timeout / database / data / scheduler / llm / unknown`。
- 失败明细、建议动作、直接重试。
- 项目/客户摘要预热预算。
- 失败告警汇总。

### 2.5 部署与迁移治理

- Alembic 正式迁移链路。
- `migration_governance.py` 运维脚本。
- `ensure_db.py` 幂等补齐历史轻量库。
- Alembic revision 短号 alias 修复，例如 `005` -> `005_v1_5`。
- GitHub Actions / deploy 脚本接入迁移治理流程。
- `/health/db` 与 `/health/db/migrations` 提供迁移状态。
- 设置页新增 Migration Status。

## 3. 技术栈

| 层 | 技术 |
|---|---|
| 前端 | React 19, TypeScript, Vite, React Router, i18next |
| 后端 | FastAPI, Uvicorn |
| ORM | SQLModel |
| 数据库 | PostgreSQL, SQLite fallback |
| 迁移 | Alembic |
| 调度 | APScheduler |
| RAG | fastembed + 向量相似度检索 |

## 4. 当前阶段判断

项目已经完成从“基础页面可用”到“AI 能力工程化”的第一阶段跃迁。

当前最高价值方向已经变成：

- 让 Skill 真正成为项目/客户空间里的工作流能力。
- 让记忆系统从可用 V1 走向可审计、可回滚、可运营。
- 让 Welcome / 项目概览变成每天工作的起点。
- 继续降低部署、迁移、任务失败带来的运维不确定性。

## 5. 下一版本主线

下一版本建议命名为 `vNext 工作流化迭代`，优先级如下：

1. Skill 与项目/客户空间深度联动。
2. 记忆治理产品化第二阶段。
3. Welcome 与项目概览的“今日工作起点”强化。
4. 安全与质量基线复核。
5. 性能与复杂度收敛。

详细计划见 [09-下一版本迭代计划](09-下一版本迭代计划.md)。
