> 更新日期：2026-05-24

## 1. 项目定位

AriaAI 是面向咨询团队的客户关系智能系统。

它解决的核心问题不是“再做一个 AI 聊天工具”，而是让顾问团队不必在每次使用 AI 前重新交代客户、项目、干系人、历史经验和沟通禁区。系统把项目过程、客户记忆、结构化干系人、知识文档、Skill 交付工作流和人机审批串成一条业务链路，让 AI 既能回答问题，也能基于团队长期积累的上下文工作。

北极星场景：

> 顾问在客户会议前 30 秒打开 AriaAI，就能看到这次该说什么、该避开什么、该确认什么、该推进什么。

当前产品主线：

- 项目承载交付过程、文件、任务、财务、聊天与项目记忆。
- 客户承载跨项目的长期记忆和结构化干系人网络。
- 会前简报把项目记忆、客户记忆、干系人、待办和里程碑组织成会议行动卡。
- Skill 承载可复用的咨询方法论和交付物生成流程。
- 对话系统负责上下文装配、意图路由、工具执行、任务编排与结果沉淀。
- HITAS 负责高风险工具调用的服务端持久化确认与确定性执行。
- 迁移治理、任务面板和诊断接口用于保证部署和运营稳定。

| 层 | 技术 |
|---|---|
| 前端 | React 19、TypeScript、Vite、React Router 7、Tailwind CSS 4、i18next |
| 后端 | FastAPI、Uvicorn、SQLModel |
| 数据库 | PostgreSQL，开发环境兼容 SQLite |
| 迁移 | Alembic |
| 调度 | APScheduler |
| RAG | fastembed、JSON embedding、内存余弦相似度 |
| LLM | Anthropic SDK、OpenAI-compatible providers、Kimi、DeepSeek、BigModel |
| 文档工具 | python-pptx、python-docx、openpyxl、reportlab |
| PDF 工具 | pypdf、pdfplumber |
| 安全 | X-Auth-Token、UserToken、多设备 token、Fernet 凭证加密 |

## 6. 核心数据模型

| 模型 | 说明 |
|---|---|
| `Project` | 项目主实体，包含阶段、客户名、合同金额、项目记忆状态 |
| `ClientRecord` | 客户主实体，包含客户长期记忆状态 |
| `ClientStakeholder` | 客户侧干系人画像、关注点、敏感点、沟通策略 |
| `ClientStakeholderHistory` | 干系人字段变更历史 |
| `ProjectFile` / `ProjectFolder` | 项目空间文件和文件夹，删除采用 `deleted_at` 软删除 |
| `ProjectTodo` / `Milestone` / `ProjectPayment` | 项目任务、里程碑和财务记录 |
| `Conversation` / `Message` | 对话与消息，支持项目、Skill、owner scope |
| `ChatTrace` | 单轮对话可观测记录 |
| `PendingToolAction` | HITAS 待确认工具动作 |
| `KnowledgeDocument` / `DocumentChunk` | 知识库文档和向量切片 |
| `Skill` | 数据库中的 Skill 定义 |

## 7. 核心业务能力

### 7.1 项目工作台

- 项目 CRUD、阶段流转、项目成员角色。
- 项目详情聚合：概览、简报、聊天、文档、笔记、任务、里程碑、财务、干系人、记忆、设置。
- 默认项目文件夹初始化和历史项目回填。
- 项目文件支持上传、AI 生成、软删除、文件夹管理、下载和文本读取。

### 7.2 客户关系智能

- 客户长期记忆 `client_memory_json`。
- 项目记忆 `context_memory_json` 可提升为客户记忆。
- 客户干系人独立表维护，支持 AI 候选识别和字段变更历史。
- 项目 Chat、Skill、会前简报均消费客户记忆和结构化干系人。

### 7.3 会前简报

- `GET /projects/{project_id}/briefing` 生成确定性简报。
- `POST /projects/{project_id}/briefing/refine` 生成或复用 AI 优化版。
- 前端 `ProjectBriefingTab` 展示“建议说什么、避免什么、确认什么、历史经验、干系人、信号来源”。
- 可一键把简报带入项目 Chat 继续生成会议行动稿。

### 7.4 对话与工具执行

- P0-P4 phase 架构：durable task 判断、规划、工具执行、follow-up、持久化。
- `ChatMode`、`ActionPolicy`、`ToolAccessPolicy` 显式化，降低误调工具风险。
- 项目上下文由 context builder 汇聚项目、客户、干系人、RAG、Skill 和工作台信号。
- 支持 SSE 状态、工具卡、生成物卡、对话导出、诊断 Trace。

### 7.5 HITAS

- 修改和删除等高风险工具调用会写入 `PendingToolAction`。
- 用户确认后执行数据库中冻结的 `tool_name + tool_input_json`，不再让 LLM 重放工具调用。
- 支持批次确认、原子 claim、过期处理、后台执行、指标接口和 stale reaper。

### 7.6 Skill

- DB Skill 仍是运行时主体，`AriaAI/skills/` 文件包提供更完整的 prompt 和 reference 资产。
- 内置顾问能力覆盖基础咨询、数字化、Office/PDF、提案、PPT 等场景。
- Skill 可从项目/客户上下文启动，结果可保存为项目文档或项目笔记，并触发记忆更新。

### 7.7 RAG

- 文档上传后后台解析、切块、embedding。
- 当前使用 JSON 字段保存 embedding，并在查询时把候选 chunk 加载到内存计算余弦相似度。
- 支持按 `doc_ids`、`project_id`、`client_id` 限定检索范围。

## 8. 迁移链

当前 Alembic 版本链：

```text
001_v1_1_project_context
002_v1_2_project_notes_todos
003_v1_3_project_members
004_v1_4_knowledge_doc_project_id
005_v1_5_todo_due_date
006_v1_6_client_stakeholders
007_v1_7_project_memory_snapshots
008_v1_8_client_memory_snapshots
009_v1_9_file_origin_and_source
010_v1_10_stakeholder_history
011_v1_11_chat_trace
012_v1_12_pending_tool_actions
013_v1_13_hitas_governance_fields
014_v1_14_hitas_approval_batches
015_v1_15_chat_owner_scope
016_v1_16_hitas_schema_guard
```

部署相关能力：

- 启动时执行 `create_db()` 与 `migrate_db()`。
- `/health/db` 返回数据库健康状态。
- `/health/db/migrations` 返回迁移治理状态。
- `scripts/migration_governance.py` 提供 `report / json / check / ensure / upgrade / current`。
- `016_v1_16` 是 HITAS 和 conversation scope 的 schema guard，负责幂等补齐关键字段。

## 9. 本地运行

后端：

```bash
cd AriaAI/backend
pip install -r requirements.txt
uvicorn main:app --reload
```

前端：

```bash
cd aria-web
npm install
npm run dev
```

常用验证：

```bash
cd AriaAI/backend
pytest

cd aria-web
npm run test
npm run build
```
