# Skill 能力质变升级清单

> 目的：逐个检查 48 个 Skill，推动它们从“可回答提示词”升级为“可完成专业任务的工作单元”。
> 日期：2026-05-30

---

## 1. 升级口径

本轮升级不以单纯增加行数为目标，而以能力跃迁为目标。每个 Skill 至少要补强以下能力之一，弱 Skill 需要全部补齐：

| 能力 | 说明 |
|------|------|
| 上下文吸收 | 能利用项目记忆、客户上下文、知识库、上传文件和历史交付物 |
| 复杂判断 | 有决策树、评分矩阵、适用条件、风险等级、价值/可行性比较 |
| 交付契约 | 明确输出为 memo、PPT、Excel、报告、清单、路线图或行动计划 |
| 质量门槛 | 交付前检查事实、假设、引用、数据缺口、责任人和下一步 |
| 模式分层 | 区分快速回答、标准交付、深度研究三种模式 |

## 5. 完成定义

每个 Skill 完成升级时，至少满足：

- 有明确的三种工作模式：快速、标准、深度。
- 有 Aria 上下文接入规则：项目、客户、知识库、文件。
- 有本 Skill 独有的判断模型，不只是通用流程。
- 有交付物契约和质量门槛。
- 不破坏 Agent Skills 基础 frontmatter 兼容性。

## 7. 咨询类 Skill 重点加强标准

咨询类 Skill 是 Aria 的核心差异化能力，不应只输出通用建议，而要形成“咨询交付链路”。本轮重点加强以下 10 个主干 Skill：

| 类型 | Skill |
|------|-------|
| 提案与表达 | `consulting-proposal-advisor`、`presentation-builder` |
| 战略与 AI | `digital-strategy`、`ai-strategy-report` |
| 交易与投后 | `commercial-due-diligence`、`valuation-and-pricing`、`post-merger-integration`、`debt-restructuring` |
| 项目基础能力 | `goal-definition`、`meeting-intelligence` |

咨询类 Skill 的增强标准：

- **问题诊断**：必须区分症状、根因、约束、决策问题和成功标准。
- **假设树**：复杂议题应先形成 issue tree / hypothesis tree，再展开分析。
- **证据链**：结论必须对应事实、访谈、数据、案例、假设或待验证事项。
- **方案选择**：不能只列选项，必须给出推荐方案、取舍逻辑和不推荐原因。
- **价值测算**：尽量量化收入、成本、效率、风险、现金流或战略能力价值。
- **落地路径**：输出要包含阶段、里程碑、责任人、依赖、治理和风险。
- **高管表达**：面向管理层的输出必须 conclusion-led，先讲答案，再讲证据。
- **客户上下文**：必须吸收客户记忆、项目记忆、历史会议和知识库案例，避免泛化。
- **交付物目录**：每个咨询能力必须写清楚能交付哪些资产，包含 memo、PPT、模型、清单、路线图、台账和会议材料。
