# 项目记忆落地进度

更新日期：2026-04-18
对应设计文档：[08-项目记忆架构设计.md](./08-项目记忆架构设计.md)

## 当前结论

项目级三层记忆（V1）已完成落地，主链路跑通：

- 原始数据 → structured memory → 视图摘要，三层完整
- 概览、聊天、设置、Memory 页面和多个业务 Tab 均已消费 memory
- 摘要缓存已落地，同版本不重复调模型
- stale 链路打通，8 类数据变化自动标记

**下一个里程碑**：启动第四层——客户记忆（`client_memory_json`），让跨项目的知识开始积累。同时对项目级记忆做可靠性补强（rebuild_log、分层喂数据、pinned 槽位）。

### 4. 摘要缓存已落地

为了解决“每次打开项目详情多个页面都重新调用 AI”的问题，当前已补上摘要缓存层：

- 新增 `ProjectMemorySummary` 缓存表

  - `project_id`
  - `memory_version`
  - `summary_type`
  - `language`
- `memory/summarize` 现在默认先查缓存，命中则直接返回

- 前端 `useProjectMemorySummary` 也增加了会话级缓存，切换 tab 时优先复用

这意味着：

- 同一项目、同一份 memory、同一语言下
- `AI 项目记忆摘要 / AI 风险摘要 / AI 干系人摘要`
- 不会再在每次打开页面时重复调用模型

## 下一步建议

### P1：异步流水线 + 项目级记忆可靠性补强

**1. Debounce 异步后台重建 + LLM 限流防护**

复用已有 `APScheduler`，数据变更时投入延迟 job（5 分钟 debounce）：
- 后台 job 完成后自动预生成 `overview` + `risk` 摘要写缓存
- 前端轮询 `/memory/status`，`stale=False` 时静默刷新
- 用户手动触发时取消排队 job，走 SSE 同步流式（保留进度可见性）
- 用户体验目标：改了数据 → 5 分钟后打开页面 → 摘要直接是新的，0 等待

**LLM 限流防护（三道防线）：**

| 防线 | 机制 | 实现 |
|------|------|------|
| 并发上限 | ThreadPoolExecutor `max_workers=2`，同时最多 2 个重建 job | APScheduler executor 配置 |
| 优先级队列 | 用户触发 > 页面触发 > debounce > 批量 | job 投入时设置优先级 |
| 退避重试 | 遇到 429 自动等待 1min→2min→4min，非限流错误记录失败不重试 | job 内部 try/except |
| 批量间隔 | 管理员批量重建时每个项目间隔 30 秒 | 批量 endpoint 内 delay 递增 |
| 每日预算 | 可配置每日最大后台重建次数（默认 200），超出只标 stale 不执行 | 系统设置 `MEMORY_REBUILD_DAILY_LIMIT` |

**2. `rebuild_log` 字段**

在 `save_project_memory()` 中追加：
```json
“rebuild_log”: [
  { “at”: “2026-04-18T10:00:00Z”, “trigger”: “milestone_changed”, “version”: 4 },
  { “at”: “2026-04-17T12:00:00Z”, “trigger”: “manual”, “version”: 3 }
]
```
保留最近 10 条。UI 可显示”上次因里程碑变更于 XX 重建”，成本极低，调试和用户信任都受益。

**3. 分层喂数据**

`build_project_memory_data()` 按状态区分粒度，降低大项目的重建成本：
- 未完成的里程碑、待办 → 全量
- 近期完成（30 天内）→ 保留标题
- 更早完成 → 只计数

**4. `_coverage` 字段**

memory JSON 加入本次重建消化了多少数据的记录，让系统可感知完整性：
```json
“_coverage”: { “milestones_total”: 12, “files_total”: 8, “built_at”: “...” }
```

**5. `pinned` 槽位**

Memory Tab 中每个槽位支持用户手写内容，重建时 AI 不覆盖 `pinned` 区：
```json
“key_risks”: {
  “ai”: [“客户决策周期长”],
  “pinned”: [“客户内部有反对声音，是最大的风险”]
}
```

**6. 关键动作触发知识捕获**

完成里程碑、项目阶段变更、项目归档时，弹出轻量提示：”有什么值得记录的？”（一句话即可），写入 `pinned` 或项目笔记，降低隐性知识丢失。

### P2：第四层——客户记忆启动

**核心动机**：三层记忆让 AI 在单个项目里工作得更好。但咨询价值在于跨项目的经验积累。客户记忆是让 AriaAI 从”项目工具”变成”咨询伙伴”的关键一跳。

**1. `ClientRecord` 新增 `client_memory_json`**

```json
{
  “client_profile”: “客户背景和行业”,
  “decision_patterns”: [“Q4 预算冻结，避开这个窗口谈合同”],
  “key_contacts”: [{ “name”: “张总”, “role”: “CFO”, “note”: “真正的决策人” }],
  “lessons_learned”: [“方案 A 2025 年初试过，技术部门强烈反对”],
  “project_history”: [{ “project_id”: 12, “outcome”: “赢单”, “key_factor”: “...” }],
  “sensitive_topics”: [“内部有裁员计划，不宜在提案中涉及”],
  “memory_version”: 1,
  “last_updated_at”: “...”
}
```

**2. 聊天知识范围”客户”档升级**

当前”客户”档走 RAG（向量检索）。升级后优先注入 `client_memory_json`，RAG 作为补充——和项目级 memory 的消费逻辑一致。

**3. 项目归档时自动提炼客户记忆**

项目状态变为 `archived` 时，触发一次”项目精华提炼”：将该项目 memory 的关键结论（经验教训、决策模式）写入客户记忆。

### P2 补充：系统设置 → 记忆管理（Memory Manager 升级）

当前系统设置已有基础的记忆管理入口，需要在此基础上加入**异步任务队列可视化**和**客户记忆维度**，让管理员真正能看清全局状态。

#### 页面结构

```
系统设置
  └── 记忆管理 / Memory Manager
        ├── 项目记忆总览
        ├── 异步任务队列
        └── 客户记忆总览（第四层落地后启用）
```

#### 项目记忆总览

| 列 | 说明 |
|----|------|
| 项目名 / 客户 | 可搜索、可按客户筛选 |
| memory 版本 | 当前 version 号 |
| 最后重建时间 | `memory_updated_at` |
| 状态 | `fresh` / `stale` / `missing` / `rebuilding` |
| stale 原因 | 来自 `rebuild_log` 最近一条触发原因 |
| 操作 | 立刻重建 / 跳转到项目 Memory Tab |

状态筛选：全部 / 需要更新（stale + missing） / 重建中 / 正常

批量操作：
- **批量重建 stale 项目**：按队列逐个触发，显示进度
- **批量补齐 missing memory**：为从未建过 memory 的项目初始化

#### 异步任务队列

管理员专属视图，展示 APScheduler 中当前 memory 相关 job 的实时状态：

| 列 | 说明 |
|----|------|
| 项目名 | 可跳转 |
| 任务类型 | `scheduled`（debounce 等待中）/ `running`（执行中）/ `failed` |
| 计划执行时间 | debounce job 的 `run_date` |
| 触发原因 | 哪次数据变更触发的 |
| 操作 | 取消排队 / 立刻执行 / 重试失败任务 |

这让管理员可以直接看到："哪些项目正在后台更新记忆"，而不是等用户反馈才知道。

#### LLM 使用统计与限流状态

| 指标 | 说明 |
|------|------|
| 今日后台重建次数 | 已用 / 每日预算上限（`MEMORY_REBUILD_DAILY_LIMIT`） |
| 并发槽位 | 当前占用 / 最大并发（`max_workers`） |
| 近 24 小时失败次数 | 因 429 / 超时导致的重建失败，含最近一次失败原因 |
| 退避中的任务 | 当前因限流正在等待重试的 job 列表 |

管理员可在此页面调整每日预算上限，并手动重试失败任务。

#### 客户记忆总览（第四层落地后启用）

| 列 | 说明 |
|----|------|
| 客户名 | 可搜索 |
| 覆盖项目数 | 有多少项目的精华已归入客户记忆 |
| memory 版本 | 当前版本号 |
| 最后更新时间 | |
| 状态 | `fresh` / `stale` / `missing` |
| 操作 | 重建客户记忆 / 跳转到客户详情 |
