# 项目记忆落地进度

更新日期：2026-04-18  
对应设计文档：[08-项目记忆架构设计.md](./08-项目记忆架构设计.md)

## 当前结论

项目级三层记忆已经完成 V1 主链路，客户级第四层记忆也已经从“只读骨架”推进到“可重建、可回流、可在前端查看”的阶段。

当前系统已经具备：

- 原始项目数据 -> 结构化项目记忆 -> 多视角摘要 的完整闭环
- 摘要缓存、stale 标记、异步重建状态、重建日志、来源覆盖
- 项目详情、概览、聊天、设置、系统设置中的记忆入口
- 客户级记忆的后端模型、API、聊天注入、项目回流入口、客户详情页入口

## 已完成

### 1. 项目级三层记忆主链路

已落地能力：

- `Project.context_memory_json`
- `memory_stale / memory_version / memory_updated_at`
- `memory_rebuild_status / memory_rebuild_failed_at`
- `build_project_memory_data()`
- `parse_project_memory()`
- `save_project_memory()`
- `get_project_memory_payload()`

### 2. 项目记忆的可维护性增强

已落地：

- `rebuild_log`
- `_coverage`
- `key_risks / open_questions / stakeholder_notes` 的 `ai + pinned` 双层结构
- `get_project_memory_payload()` 对外兼容扁平数组，并保留 `*_detail`

### 3. 项目记忆 API

已可用：

- `GET /projects/{project_id}/memory`
- `GET /projects/{project_id}/memory/status`
- `POST /projects/{project_id}/memory/rebuild`
- `POST /projects/memory/rebuild-batch`
- `POST /projects/{project_id}/memory/summarize`
- `POST /projects/{project_id}/generate-context`

### 4. 多视角摘要

当前已支持：

- `overview`
- `risk`
- `stakeholder`
- `delivery`
- `client-facing`
- `financial`
- `documents`

并且已经支持：

- SSE 流式输出
- 语言跟随当前用户界面语言
- 按 `project_id + memory_version + summary_type + language` 缓存复用
- `force_refresh` 强制重算

### 5. 项目记忆异步重建基础

已落地：

- 数据变化后 `memory_stale = true`
- APScheduler debounce 重建任务
- 后台任务状态：`idle / queued / rebuilding / failed`
- 重建成功后自动预生成 `overview` 与 `risk` 摘要缓存

### 6. 项目记忆的前端消费

已接入：

- `Overview`
- `Chat`
- `Memory`
- `Settings`
- `Milestones`
- `Todos`
- `Notes`
- `Financials`
- `Documents`

并且已经有：

- 独立 `Memory` 页面
- 项目设置中的“项目记忆概况”
- 系统设置中的 `Memory Manager`

### 7. 项目列表页定位调整

`/projects` 已从“记忆运营面板”回归业务首页：

- 保留项目核心业务信息
- 去掉过重的 memory 批量操作与技术细节
- 深度记忆管理集中到项目内页和系统设置页

### 8. 客户级第四层记忆

已落地：

- `ClientRecord.client_memory_json`
- `client_memory_stale / client_memory_version / client_memory_updated_at`
- `build_client_memory_data()`
- `parse_client_memory()`
- `save_client_memory()`
- 客户记忆聊天注入：`knowledge_scope = client` 时优先注入 `client_memory`

已开放 API：

- `GET /clients/{client_id}/memory`
- `GET /clients/{client_id}/memory/status`
- `POST /clients/{client_id}/memory/rebuild`
- `POST /clients/{client_id}/memory/promote-project`
- `POST /clients/{client_id}/memory/summarize`

### 9. 客户记忆与项目回流

当前已具备两条关键链路：

- 项目侧数据变更会自动把匹配客户的 `client_memory` 标记为 stale
- 客户侧可以手动将某个项目的项目记忆“提升”进客户记忆

### 10. 客户前端入口

当前已在客户详情页提供：

- 客户记忆状态展示
- 最近同步时间
- 手动“更新记忆”按钮

### 11. 回归测试

当前已覆盖的关键测试包括：

- 项目记忆重建状态流转
- 项目记忆缓存命中与强制刷新
- SSE 事件格式
- 语言透传
- `rebuild_log / _coverage`
- `client_memory` 注入聊天上下文
- 客户记忆重建
- 项目记忆变更带脏客户记忆
- 项目记忆提升到客户记忆

## 部分完成

### 1. 客户记忆仍以手动重建和手动回流为主

虽然客户记忆已经可用，但目前仍以：

- 手动重建
- 手动提升项目记忆
- 项目变更后只标记 stale

为主，还没有完全做到自动后台重建和自动吸收。

### 2. 客户前端管理仍偏轻量

当前只有客户详情页入口，还没有：

- 系统级 `Client Memory Manager`
- 批量重建客户记忆
- 客户记忆历史版本查看

## 尚未完成

### 1. 槽位级增量更新

目前项目记忆和客户记忆仍以整包重建为主，尚未做到：

- 只刷新风险槽位
- 只刷新财务槽位
- 只刷新文档槽位

### 2. 独立记忆主表与历史版本

当前项目记忆和客户记忆仍保存在主业务表字段中，尚未拆出：

- 独立 memory 主表
- 历史版本
- 回滚能力

### 3. 完整后台流水线

当前已经有 APScheduler 基础和 debounce 任务，但还未完全产品化为：

- 完整优先级队列
- 限流预算
- 失败重试策略
- 批量任务监控

### 4. 更强的客户级产品入口

尚未完成：

- 客户页独立 `Memory` 工作区
- 系统设置中的 `Client Memory Manager`
- 从项目归档自动提炼客户经验

## 下一步建议

### P1：把客户记忆做成真正的第四层

优先继续做：

1. 客户记忆的系统级管理页
2. 项目归档时自动回流客户记忆
3. 客户记忆的摘要缓存
4. 客户记忆的批量重建

### P2：把记忆流水线彻底后台化

重点包括：

1. 后台任务优先级与预算上限
2. 失败重试与告警
3. 多摘要预热策略
4. 更完整的端到端压测
