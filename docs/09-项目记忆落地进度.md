# 项目记忆落地进度

更新日期：2026-04-18  
对应设计文档：[08-项目记忆架构设计.md](./08-项目记忆架构设计.md)

## 当前结论

项目级三层记忆已经完成可用 V1，客户级第四层记忆也已经进入系统化管理阶段。

当前系统已经具备：

- 原始项目数据 -> 结构化项目记忆 -> 多视角摘要 的完整主链路
- 摘要缓存、`stale` 标记、异步重建状态、重建日志、来源覆盖
- 项目详情、概览、聊天、设置、系统设置中的项目记忆入口
- 客户记忆的后端模型、API、项目回流、聊天注入、客户详情入口
- 系统设置中的 `Client Memory Manager`
- 客户记忆批量重建能力

## 已完成

### 1. 项目级三层记忆主链路

已落地能力：

- `Project.context_memory_json`
- `memory_stale / memory_version / memory_updated_at`
- `memory_rebuild_status / memory_rebuild_failed_at`
- `build_project_memory_data()`
- `parse_project_memory()`
- `save_project_memory()`
- `get_project_memory_payload()`

### 2. 项目记忆可维护性增强

已落地：

- `rebuild_log`
- `_coverage`
- `key_risks / open_questions / stakeholder_notes` 的 `ai + pinned` 双层结构
- `get_project_memory_payload()` 对外兼容扁平数组，同时保留 `*_detail`

### 3. 项目记忆 API

已可用：

- `GET /projects/{project_id}/memory`
- `GET /projects/{project_id}/memory/status`
- `POST /projects/{project_id}/memory/rebuild`
- `POST /projects/memory/rebuild-batch`
- `GET /projects/memory/jobs`
- `POST /projects/memory/jobs/{project_id}/cancel`
- `POST /projects/memory/jobs/{project_id}/run-now`
- `POST /projects/{project_id}/memory/summarize`
- `POST /projects/{project_id}/generate-context`
- `POST /projects/memory/warm-summaries-batch`

### 4. 多视角摘要

当前已支持：

- `overview`
- `risk`
- `stakeholder`
- `delivery`
- `client-facing`
- `financial`
- `documents`

并且已经支持：

- SSE 流式输出
- 跟随当前界面语言输出
- 按 `project_id + memory_version + summary_type + language` 缓存复用
- `force_refresh` 强制重算
- 常用摘要自动预热

### 5. 项目记忆异步重建基础

已落地：

- 数据变化后自动标记 `memory_stale = true`
- APScheduler debounce 重建任务
- 后台任务状态：`idle / queued / rebuilding / failed`
- `Memory Manager` 可查看后台队列
- 可取消或立刻执行某个项目的重建/预热任务
- 重建成功后自动预热 `overview / risk / stakeholder`
- 预热具备基础限流、防重、预算和退避重试

### 6. 项目记忆前端消费

已接入：

- `Overview`
- `Chat`
- `Memory`
- `Settings`
- `Milestones`
- `Todos`
- `Notes`
- `Financials`
- `Documents`

并且已提供：

- 独立 `Memory` 页面
- 设置页中的“项目记忆概况”
- 系统设置中的 `Project Memory Manager`
- 异步进度状态可视化

### 7. 客户级第四层记忆

已落地：

- `ClientRecord.client_memory_json`
- `client_memory_stale / client_memory_version / client_memory_updated_at`
- `build_client_memory_data()`
- `parse_client_memory()`
- `save_client_memory()`
- 聊天中 `knowledge_scope = client` 时优先注入 `client_memory`

已开放 API：

- `GET /clients/{client_id}/memory`
- `GET /clients/{client_id}/memory/status`
- `POST /clients/{client_id}/memory/rebuild`
- `POST /clients/{client_id}/memory/promote-project`
- `POST /clients/{client_id}/memory/summarize`
- `POST /clients/memory/rebuild-batch`

### 8. 客户记忆回流与入口

当前已具备：

- 项目侧数据变化会自动把匹配客户的 `client_memory` 标记为 `stale`
- 客户侧可以手动将某个项目记忆“提升”进入客户记忆
- 客户详情页有客户记忆状态和手动更新入口
- 系统设置中已新增 `Client Memory Manager`
- `Client Memory Manager` 支持：
  - 全量查看客户记忆状态
  - 搜索与筛选
  - 批量刷新 `stale`
  - 批量补齐 `missing`
  - 单客户刷新
  - 跳转客户详情

### 9. 回归测试

当前已覆盖的关键测试包括：

- 项目记忆重建状态流转
- 项目记忆摘要缓存命中与强制刷新
- SSE 事件格式
- 语言透传
- `rebuild_log / _coverage`
- 项目记忆异步队列列表、取消、立即执行
- 客户记忆注入聊天上下文
- 客户记忆单项目重建
- 客户记忆批量重建
- 项目变更带脏客户记忆
- 项目记忆提升到客户记忆

## 部分完成

### 1. 客户记忆仍以手动重建为主

虽然客户记忆已经支持系统级管理和批量重建，但目前仍以：

- 手动重建
- 批量重建
- 手动提升项目记忆

为主，还没有完全做到“自动后台重建 + 自动吸收归档项目经验”的闭环。

### 2. 客户记忆前端仍偏管理视图

当前已有 `Client Memory Manager` 和客户详情页入口，但还没有：

- 客户详情中的独立 `Memory` 工作页
- 客户记忆历史版本查看
- 面向顾问的客户记忆多视角摘要工作台

## 尚未完成

### 1. 槽位级增量更新

目前项目记忆和客户记忆仍以整包重建为主，尚未做到：

- 只刷新风险槽位
- 只刷新财务槽位
- 只刷新文档槽位

### 2. 独立记忆主表与历史版本

当前项目记忆和客户记忆仍保存在业务主表字段中，尚未拆出：

- 独立 memory 主表
- 历史版本
- 回滚能力

### 3. 更完整的后台任务系统

当前已有 APScheduler 基础和队列管理接口，但还未完全产品化为：

- 完整优先级队列
- 全局预算治理
- 更完善的失败重试与告警
- 跨项目/跨客户的统一队列监控台

### 4. 客户级更强的产品入口

尚未完成：

- 客户详情中的独立 `Memory` 页面
- 客户记忆多视角摘要缓存
- 项目归档后自动提升客户经验

## 下一步建议

### P1：把客户记忆做成真正的第四层

优先继续做：

1. 客户详情独立 `Memory` 工作页
2. 客户记忆多视角摘要与缓存
3. 项目归档后自动提升客户经验
4. 客户记忆异步重建和状态可视化

### P2：把记忆流水线彻底后台化

重点包括：

1. 统一的项目/客户记忆任务队列
2. 预算、限流、失败重试和告警
3. 多摘要预热策略治理
4. 更完整的端到端压测与观测能力
