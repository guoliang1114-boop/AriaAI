## 1. 当前判断

当前主要问题已经不是“功能缺口太大”，而是“已经落地的 AI 能力如何稳定进入用户工作流”。

近期已完成的关键收口：

- 项目/客户记忆进入可运营 V1。
- 统一任务面板补齐失败分类、失败明细、重试、预算和告警汇总。
- Alembic 迁移治理从文档进入脚本和部署流程。
- 项目记忆可以手动提升到客户记忆。
- Skill 结果保存后可以刷新项目记忆，形成基本回流闭环。
- 客户侧干系人已从项目成员概念中拆出，新增独立 Tab、可视化和锚点治理页。
- 部署中 502/503/504 的首页和项目详情错误态已改为服务恢复提示，避免误判为项目不存在。

下一阶段要重点关注：

- Skill 是否能成为项目/客户空间的一等工作流入口。
- 记忆系统是否具备历史版本、回滚、审计能力。
- 任务治理是否能从“查看与重试”升级到“策略化运营”。
- 前端复杂页面和后端大路由是否继续收敛。
- 安全、Markdown、部署链路是否经得起生产复核。

## 17. 2026-04-21 系统通知治理更新

- 首页现在会展示一次性系统通知卡，解决“重要升级只存在代码和部署日志里，用户感知不到”的体验缺口。

- 后续治理点：为系统消息补 `placement`、`expires_at`、`audience`、`kind` 字段，并在消息中心修复现有中文文案编码污染。

## 18. 2026-04-21 项目摘要与时间治理更新

- 已修复项目记忆摘要流式接口在 SSE 内部直接使用全局 `engine` 的问题，改为复用当前请求 session bind，避免测试环境或非默认数据库配置下穿透到本地 PostgreSQL。
- 已将后端 app/tests 中残留的 `datetime.utcnow()` 清零，统一使用 `utc_now_naive()`，降低 Python 3.12+ 弃用警告和时区语义不一致风险。
- 项目 AI 摘要前端已合并同一项目、语言、记忆版本下的“生成全部摘要”请求，避免多个卡片同时刷新时重复调用 `/memory/summaries/generate`，降低 Kimi 429 触发概率。
- 摘要卡片已区分“尚未生成”和“已生成但暂无可展示内容”，避免财务、文档等维度数据为空时用户误以为系统没有执行生成。
- 后续治理点：`projects.py` 与 `clients.py` 仍然较大，摘要生成、任务治理、记忆重建和失败分类应继续拆到 service/router 子模块。

## 19. 2026-05-12 Markdown 安全治理更新

- Markdown 渲染链路已补出独立链接净化函数 `sanitizeMarkdownHref`，集中限制链接协议为 `http`、`https`、`mailto`、`tel`、站内路径和锚点，继续阻断 `javascript:` 等危险协议。
- `MarkdownRenderer` 保持不启用 raw HTML，并将链接净化逻辑移出组件文件，避免 Fast Refresh 规则被工具函数导出破坏。
- 本轮验证：`npm run build` 通过；`npm run lint` 已恢复为通过。
- 全量 lint 仍保留 warning 级历史债务，主要集中在 `any` 类型、Hook 依赖、Fast Refresh 导出规则和 React Compiler 纯度规则；这些不再阻断质量门，但仍需单独排期逐步收敛。
