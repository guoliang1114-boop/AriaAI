> 更新日期：2026-08-27
> 当前版本：v0.0.4
> 主题：**Run Harness v1 + 用户记忆 v1 + 对话体验与安全收口**  
> 关联文档：
> - [10-代码Review遗留事项](./10-代码Review遗留事项.md)
> - [11-Model-Harness产品方案设计](./11-Model-Harness产品方案设计.md)

## 1. 版本目标

> 发布状态：核心范围已完成。Product Run Event、统一活动时间线、正式 ChatRun、Turn Receipt/Steering、项目/客户/用户记忆、候选审批与版本冲突守卫、Skill 质量门禁、Provider 评测和生产数据库隔离 E2E 均已接入；上线结果以对应 GitHub Actions 为准。

V0.0.4 的目标不是新增大量业务功能，而是把当前已经暴露出来的 AI 体验问题、连续性问题和安全治理问题集中收口。

这一版的核心判断：

- 项目对话不能继续直接暴露底层工具日志。
- AI 回复必须具备稳定的即时反馈和真实流式体验。
- Skill、工具、任务、交付物需要进入统一的用户可理解时间线。
- 用户层记忆应先以显式、可编辑、可删除的轻量方式落地。
- 当前 code review 遗留项需要清理，避免后续 Harness 重构时继续放大。

V0.0.4 的产品结果应该是：

> 用户感觉 AI 不再只是“会回答”，而是“能稳定地在项目里工作，并且记得我的偏好”。

## 2. 范围总览

| 主干 | 目标 | 优先级 | 本版结果 |
|---|---|---:|---|
| A. Run Harness v1 | 统一项目对话的事件、时间线和流式体验 | P0 | 对话过程稳定、可解释、不暴露内部噪音 |
| B. 用户记忆 v1 | 让 AI 记住用户偏好和工作方式 | P0 | 用户偏好跨项目生效，且可查看、可删除 |
| C. 遗留与硬化 | 清理 review 遗留、安全和体验隐患 | P1 | 敏感设置、重复输出、loading、用户级设置收口 |
| D. 测试与发布治理 | 给 Harness 和 Skill 补回归网 | P1 | Event contract、Skill e2e、发布检查清晰 |

## 3. 版本原则

1. **先收口体验，再扩大能力**  
   V0.0.4 先解决用户已经看见的问题，不做完整 Agent 平台。

2. **前端消费产品事件，不消费内部日志**  
   工具、任务、Skill 的底层事件先由 Event Harness 映射为 Product Run Event。

3. **普通问答保持安静，复杂任务才展示过程**  
   只读工具、上下文读取、普通问答不展示“任务进度”；Skill、交付物、长任务和确认动作才进入时间线。

4. **用户记忆默认显式确认**  
   第一版不做全自动记忆，避免把临时表达或客户事实污染为用户偏好。

5. **新旧协议可灰度、可回滚**  
   Product Run Event v1 先与旧事件双发，前端用 feature flag 切换消费路径。

## 4. 主干 A：Run Harness v1

> 来源：[11-Model-Harness产品方案设计](./11-Model-Harness产品方案设计.md) Phase 1。

### 4.1 A1：Product Run Event v1

目标：定义后端到前端的稳定事件协议，避免前端直接理解底层 tool call。

事件建议：

| 事件 | 用途 |
|---|---|
| `run_started` | 一次 AI 执行开始 |
| `status` | 产品级状态文案 |
| `text_delta` | 模型正文增量 |
| `step_started` | 可展示步骤开始 |
| `step_completed` | 可展示步骤完成 |
| `tool_progress` | 可展示工具进度 |
| `task_update` | 长任务进度 |
| `confirmation_required` | 需要用户确认 |
| `artifact_ready` | 交付物可用 |
| `message_persisted` | assistant message 已保存 |
| `run_done` | run 完成 |
| `run_failed` | run 失败 |

后端范围：

- 新增 Event Harness 薄层。
- 将现有 `status`、`tool_executing`、`tool_result`、`task_run`、`agent_step`、LLM chunk 映射为 Product Run Event。
- 支持新旧事件双发。
- 支持 feature flag 或兼容开关。
- 修复 LLM chunk 被后端整轮缓存后批量发送的问题，确保 `text_delta` 尽量实时转发。

前端范围：

- 新增 Product Run Event 解析分支。
- 旧事件消费路径保留一段时间。
- `streamingSteps` 改为真实消费 Product Run Event，不再成为死代码。

验收：

- 普通问答收到 `run_started`、`status`、`text_delta`、`run_done`。
- Skill/任务场景收到对应 step/tool/task 事件。
- 同一条回复在流式阶段和刷新后展示结果一致。
- 新旧事件双发期间，旧前端路径不受影响。

### 4.2 A2：项目对话活动时间线

目标：把 Skill、工具、任务、交付物过程统一展示为用户可理解的活动时间线。

前端范围：

- 新增 `buildActivityTimeline()` 规范化函数。
- 新增 `ProjectChatActivityTimeline` 组件。
- `ChatStreamingMessage` 和 `ProjectChatMessageBubble` 共用活动时间线展示逻辑。
- 默认展示策略：
  - 进行中：展开当前步骤。
  - 已完成：折叠为单行摘要。
  - 普通问答：不展示内部步骤。
  - 失败：展示失败步骤和可操作提示。

展示规则：

| 场景 | 展示 |
|---|---|
| 普通问答 | 只显示 AI 状态和正文 |
| 明确读文件 | 简短显示“正在读取相关文件” |
| Skill 执行 | 显示 Skill 横幅和关键步骤 |
| 长任务 | 显示 4 步任务进度 |
| 工具生成交付物 | 显示 artifact ready |
| 高风险动作 | 显示确认卡片 |

验收：

- 普通问答不再出现“步骤 1/4”或只读工具日志。
- Skill 调用顶部显示 Skill 名称。
- 工具、任务和交付物在同一条时间线中呈现。
- 流式中看到的时间线，刷新后仍能复现。

### 4.3 A3：后台任务进度内联

目标：复杂任务不再要求用户跳到任务面板才能看到进度。

范围：

- 将 `task_update` 灌入活动时间线。
- TaskRun 典型 4 步：
  1. 收集上下文
  2. 生成结构或大纲
  3. 生成并保存交付物
  4. 整理结果与链接
- 任务面板继续作为历史和详情入口。

验收：

- 长任务在对话内可看到进度。
- 生成物完成后出现可打开/下载入口。
- 任务面板和对话内状态不冲突。

### 4.4 A4：PPT 生成路径可见

目标：让用户理解 PPT 是“按当前大纲生成”还是“自动生成项目 PPT”。

范围：

- 在 PPT 触发入口提供轻量选择：
  - 按我的大纲
  - 自动生成项目 PPT
- 默认沿用现有智能路由。
- 两条路径都进入同一活动时间线。

验收：

- 用户可显式选择 PPT 生成方式。
- 默认路径仍可自动判断。
- 时间线能体现使用了哪种路径。

## 5. 主干 B：用户记忆 v1

> 来源：[12-记忆系统优化方案](./12-记忆系统优化方案.md) Phase 1。

### 5.1 范围

新增用户层记忆，用于保存用户偏好、工作方式和输出风格。

第一版建议结构：

```json
{
  "response_preferences": {
    "language": "zh",
    "verbosity": "normal",
    "tone": "direct_collaborative",
    "format_preferences": ["conclusion_first", "action_plan"]
  },
  "work_style": {
    "prefers_root_cause_first": true,
    "prefers_no_code_changes_without_confirm": true,
    "prefers_docs_before_large_refactor": true
  },
  "product_preferences": {
    "hide_internal_tool_logs": true,
    "show_progress_for_long_tasks_only": true,
    "prefer_lightweight_preview": true
  }
}
```

### 5.2 后端范围

- 增加按用户隔离的 User Memory 存储。
- 提供读取、更新、删除 API。
- runtime 准备阶段注入简短 User Memory。
- 增加“记住这个偏好”的确认写入入口。
- 明确过滤客户事实、项目事实和敏感信息，防止写入用户记忆。

### 5.3 前端范围

- 设置页新增“个人 AI 记忆”或“用户偏好”卡片。
- 用户可查看、编辑、删除每条偏好。
- 对话中支持“记住这个偏好”确认卡。
- 删除偏好后立即生效。

### 5.4 规则边界

| 信息 | 写入位置 |
|---|---|
| 用户喜欢中文、先给结论、不擅自改代码 | 用户记忆 |
| 客户决策慢、预算敏感、某人是关键决策人 | 客户记忆 |
| 项目处于 lead 阶段、合同金额、当前风险 | 项目记忆 |
| PPT 应按咨询故事线输出 | Skill/组织方法论 |

第一版不做自动长期记忆，只支持：

- 用户手动设置。
- 用户明确说“记住”。
- AI 检测到偏好后发确认卡，用户确认后写入。

### 5.5 验收

- 用户偏好跨项目生效。
- 用户可查看、编辑、删除偏好。
- 删除后下一轮对话不再注入该偏好。
- 客户/项目事实不会进入用户记忆。
- “记住这个偏好”确认前不写入。
- 相关 API 与 prompt 注入有单测覆盖。

## 6. 主干 C：遗留与硬化

> 来源：[10-代码Review遗留事项](./10-代码Review遗留事项.md)。

| 编号 | 项目 | 范围 | 验收 |
|---|---|---|---|
| C1 | 敏感全局设置加 admin 门 | `api_base_url` 等设置写入增加 admin 校验 | 非 admin 无法修改敏感设置 |
| C2 | Markdown 正文重复显示去重 | 避免 tool 输出与流式正文重复出现 | 相同 markdown 不重复渲染 |
| C3 | 切会话 loading 卡住兜底 | 请求结束与 conversation 匹配解耦 | 快速切换会话不会卡 loading |
| C4 | `font_size` 改为用户维度 | 与用户偏好/用户设置统一 | 不同用户互不影响 |
| C5 | `agent_step` 死代码处理 | 被活动时间线消费或移除 | 不再存在未使用状态 |
| C6 | `stage` 命名兼容清理 | 评估旧 shim 是否可下线 | 不破坏旧数据展示 |

原则：

- C 类任务不扩大范围。
- 能被主干 A/B 自然消化的，不单独重复实现。
- 涉及行为变化的必须补单测。

## 7. 主干 D：测试、观测与发布治理

### 7.1 Skill 端到端测试

补 1-2 个端到端测试：

- Skill 选中。
- 路由进入 Skill。
- mock LLM 或 mock 工具。
- 生成交付物。
- 发出 Product Run Event。
- `run_done` 与 artifact metadata 正确。

验收：

- 至少覆盖一个 PPT/交付物类 Skill。
- 断言事件序列和最终 artifact。

### 7.2 Event Contract 测试

为 Product Run Event v1 增加 contract/golden 测试。

覆盖：

- 普通问答。
- 明确读取文件。
- Skill 执行。
- 长任务。
- confirmation_required。
- run_failed。

验收：

- 事件字段稳定。
- display mode 稳定。
- 旧事件双发兼容可测试。

### 7.3 观测基线

V0.0.4 不做完整 dashboard，但需要最低限度日志：

- run count by display mode。
- run final status。
- 首 token 时间。
- 总耗时。
- 工具错误率。
- run_failed 原因分类。

验收：

- 可以从日志中判断 V0.0.4 是否比 v0.0.2 更稳定。
- 灰度期间能发现异常率是否超过阈值。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 事件双发导致前端路径分裂 | 时间线和旧 UI 不一致 | 新组件只消费 Product Run Event，旧路径冻结 |
| 普通问答仍展示内部工具过程 | 用户困惑 | display mode 默认 quiet，read-only 工具不展示 |
| 用户记忆被模型过度推断 | 记忆污染 | 只显式写入或确认写入 |
| 用户记忆混入客户/项目事实 | 权限和语义混乱 | 后端分类过滤 + 前端文案提醒 |
| 真流式改造影响工具调用 | 对话失败率上升 | 分阶段灰度，普通问答先开，工具链后开 |
| C2 去重误删正文 | 内容丢失 | 精确匹配策略，保守处理，单测覆盖 |
| per-user 设置迁移丢失旧值 | 用户体验倒退 | 首次读取时从 localStorage/旧配置迁移 |
| 范围蔓延到 v0.0.5 内容 | 延误发布 | 第 8 节作为硬边界 |

## 14. 成功标准

V0.0.4 成功的标志不是“做了多少功能”，而是以下变化真实发生：

- 用户不再被内部工具过程打扰。
- 项目对话的过程展示更稳定、更可信。
- AI 回复具备即时反馈和真实流式体验。
- 用户偏好可以跨项目影响 AI 表达方式。
- 高风险和长期记忆写入都有明确确认边界。
- 后续 Memory Candidate、AIRun 持久化和 Harness Phase 2 有了稳定地基。
