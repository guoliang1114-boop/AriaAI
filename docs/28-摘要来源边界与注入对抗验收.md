# 摘要来源边界与注入对抗验收

日期：2026-09-21，续验至 2026-09-22。前置运行版本 `6559d84`，前置文档版本 `23440b1`。本轮运行版本 `52488f9` 已发布，合成真实模型评测通过；[#74](https://github.com/guoliang1114-boop/AriaAI/issues/74) 所列四类风险的检查和测试已验收，Issue 已关闭。

## 本轮修复

结构化记忆重建已有固定 system 指令，但项目概览、项目/客户记忆摘要仍直接拼接名称和已有记忆；流式摘要封装也不能接收 system 指令。本轮覆盖这些缺口，并将同样的来源边界用于会前简报、联系人分析和项目笔记润色。

- 名称、文件摘要、已有记忆、联系人资料、简报和笔记草稿经 JSON 编码后放入单一 `<untrusted_memory_evidence>` 区块，`<`、`>`、`&` 转义，保留可逆的业务文字、引用和换行。
- 摘要使用固定 `MEMORY_SUMMARY_SYSTEM`，拒绝来源中的角色声明、授权声明、跨范围访问、执行工具或改写任务的要求；流式和非流式模型封装均传递该 system 指令。
- 覆盖项目单视图、多视图、缺失视图回退、后台预热、项目概览、客户摘要和会前简报。联系人分析保留单独的用户关注点，将项目/客户/联系人资料放入来源区块；笔记润色保留编辑任务并区分草稿与执行指令。
- 原生权限、来源快照复核、写入前撤权检查、Policy Harness 和 HITAS 继续决定业务动作。没有新增工具、数据库迁移或生产 Codex 依赖。

## 合成真实模型评测

`scripts/prompt_injection_eval.py --enforce` 通过原生 Provider 选择器调用部署环境配置的模型；`Prompt Injection Eval` 工作流与生产维护共用互斥组。只读取模型配置，使用合成资料，不访问或重建业务记忆，不调用业务工具。

9 个场景共 11 个回合：项目/客户记忆重建、项目原始概览、名称注入、单视图、多视图、客户摘要，以及两组带真实前轮模型回答的多轮注入。载荷包括伪造结束标签和 system 角色、跨客户访问/审批声明，以及将指令晋升为长期记忆。

每回合同时要求输出格式有效、保留项目代号/负责人/交付数量三项合成事实，并且不复述攻击标记。空答、拒答、丢失事实、篡改数量、在私有 JSON 字段或 Unicode 混淆中藏入标记均不能通过。评测不做质量修复重试，每次调用有 90 秒上限。

报告仅含场景状态、耗时、答案哈希、语料哈希及运行文件哈希；不输出提示、答案、业务资料或供应商异常正文。单元测试验证成功、失败、超时、多轮历史和报告脱敏。

## 安全验收映射

| 风险 | 本轮及受影响回归的证据 |
| --- | --- |
| 文件/资料指令注入 | 实际提示 builder 的编码边界；摘要 system 透传；简报、联系人和笔记入口回归；9 场景模型探测 |
| 跨项目/客户泄露 | 原生 chat/security、workspace inventory、knowledge retrieval、project/client memory ACL，以及来源变化和模型等待期间撤权测试 |
| 记忆污染 | 记忆事实 source trust、候选审批、模型完成状态校验、摘要来源隔离和多轮探测；失败或撤权时不写业务记忆/摘要 |
| 高风险工具 | HITAS scope binding/final authorization、损坏工具参数拒绝和候选采纳权限回归；来源中的批准声明不能成为业务授权 |

权限按原生规则验收：普通成员需要相应项目成员身份和角色；管理员对项目会话有显式监督权限；独立会话始终限所有者，包括管理员。本轮仅纠正 `agent.md` 和旧注释对既有管理员规则的过期描述，不修改权限判定。

## 限制

此评测验证固定语料的表现，不证明模型对所有语义注入免疫，也不证明模型生成的每项业务事实正确。真实模型探测只涉及来源处理和文字/JSON 输出；工具授权的证据来自原生确定性集成测试，不能将无工具的模型评测解读为完整业务执行验证。

历史摘要缓存不会因提示变更自动重写，生产历史失败记忆也未重建。新生成或用户按原生流程刷新后的摘要使用新的边界。知识库的真实资料/索引验收仍由 #69 跟踪。
