# 项目三层记忆落地进度

更新日期：2026-04-17  
对应设计文档：[08-项目三层记忆设计.md](./08-项目三层记忆设计.md)

## 当前结论

`08-项目三层记忆设计` 已完成可用的第一版落地，当前状态可以概括为：

- 已打通主链路：原始上下文 -> structured memory -> 视图摘要
- 已从概览页扩展到聊天页、执行页、设置页和项目列表页
- 已具备流式摘要、语言跟随、stale 提示、手动重建、自动刷新等基础体验
- 仍处于 V1 阶段，尚未进入槽位级增量更新、多份 memory 拆分、完整异步任务化的终局形态

## 已完成

### 1. 第二层 structured memory 已落库

后端 `Project` 已新增并使用以下字段：

- `context_memory_json`
- `memory_stale`
- `memory_version`
- `memory_updated_at`

### 2. memory 构建与保存链路已完成

当前已落地：

- `build_project_memory_data()`
- `build_project_memory_prompt()`
- `parse_project_memory()`
- `save_project_memory()`
- `get_project_memory_payload()`

### 3. memory API 已可用

当前已有：

- `GET /projects/{project_id}/memory`
- `GET /projects/{project_id}/memory/status`
- `POST /projects/{project_id}/memory/rebuild`
- `POST /projects/memory/rebuild-batch`
- `POST /projects/{project_id}/memory/summarize`

### 4. 第三层视图摘要已落地

- `POST /projects/{project_id}/generate-context` 已改为优先基于 structured memory 生成概览摘要
- `memory/summarize` 当前支持：
  - `overview`
  - `risk`
  - `stakeholder`
  - `delivery`
  - `client-facing`
  - `financial`
  - `documents`

### 5. AI 项目总结体验已补强

- `AI 项目总结` 已支持流式输出
- 多视角 `memory/summarize` 也已切到 SSE 流式输出
- 摘要语言会跟随当前用户界面语言
- 支持重试、视角切换、流式状态展示

### 6. 项目聊天已复用 structured memory

- `context_builder.py` 已改为优先使用 structured memory
- 旧的 `context_summary` 仅作兼容兜底
- 聊天空态快捷动作已改为 memory-aware prompt
- 聊天头部已显示 memory 状态、版本、更新时间，并支持手动重建

### 7. stale 标记已接入项目变更事件

以下行为会触发 `memory_stale = True`：

- 项目基本信息更新
- 文档新增、更新、删除、上传
- 文件夹新增、删除
- 里程碑新增、更新、删除
- 待办新增、更新、删除
- 财务记录新增、删除
- 项目笔记更新
- 项目成员增删

### 8. 概览页与聊天页已接入 memory 状态和自动刷新

当前支持：

- 查看 memory 状态
- 查看版本号
- 查看更新时间
- 手动触发重建
- `stale` 时显示明显提示
- `stale` 时前端轻量自动尝试重建
- memory 重建后，当前摘要会自动按新 memory 刷新

### 9. 更多页面已开始直接消费 memory

当前已接入：

- `ProjectMilestonesTab`
  - 顶部展示 `AI 交付摘要`
  - 基于 `delivery` 视角流式生成
- `ProjectTodosTab`
  - 顶部展示 `AI 风险摘要`
  - 基于 `risk` 视角流式生成
- `ProjectNotesTab`
  - 顶部展示 `AI 干系人摘要`
  - 基于 `stakeholder` 视角流式生成
- `ProjectFinancialsTab`
  - 顶部展示 `AI 财务风险摘要`
  - 基于专门的 `financial` 视角生成
- `ProjectDocumentsTab`
  - 顶部展示 `AI 文档洞察`
  - 基于专门的 `documents` 视角生成
- `ProjectSettingsTab`
  - 侧栏展示 `AI 项目状态摘要`
  - 基于 `overview` 视角生成

### 10. 项目列表页已开始感知并操作 memory

- `ProjectKanbanCard`
  - 已显示 memory 状态徽标
  - 可区分：
    - 未生成记忆
    - 记忆待刷新
    - 记忆已同步
  - 若项目已有 `context_summary`，卡片优先显示摘要
- `ProjectsHeader`
  - 支持 `只看待刷新`
  - 支持 `只看未生成`
  - 支持 `刷新待刷新记忆`
  - 支持 `补齐缺失记忆`
  - 可直接查看项目总数、记忆已同步、记忆待刷新、未生成记忆这 4 组状态统计
  - 会给出当前建议优先处理的阶段，并支持一键处理最急阶段
  - 批量处理后会显示本次更新结果
- `ProjectKanbanPhaseHeader`
  - 已支持按阶段刷新 memory
  - 商务阶段、交付阶段、归档阶段都可以独立维护本阶段 memory
  - 当本阶段没有 stale 但仍有 missing 时，会自动切到“补齐缺失记忆”
- `Projects`
  - 已接入后端原生 `memory/rebuild-batch`
  - 列表页不再逐个串行请求单项目重建接口
  - 列表页默认按 memory 健康度排序，未生成与待刷新项目会优先显示

### 11. 测试已覆盖关键 memory 能力

当前已补的关键验证包括：

- `build_project_context_prompt()` 仅强调当前项目
- `build_project_summary_from_memory_prompt()` 能按语言输出
- `build_project_memory_view_prompt()` 支持 `risk / financial / documents`
- `generate-context` 能透传请求语言
- `memory/summarize` 的 SSE 事件格式正常
- `memory/status -> memory/rebuild -> status` 流程正常
- `memory/rebuild-batch` 可只重建请求中的 stale 项目
- `memory/rebuild-batch` 可补齐缺失的 memory

## 部分完成

### 1. 当前仍以“整包重建”为主

当前方式是：

- 数据变化后先标记 `stale`
- 在概览摘要、手动重建、批量刷新、memory summarize 等入口按需重建

尚未做到：

- 槽位级增量更新
- 文档、财务、待办、风险信号的局部刷新
- 真正的后台异步分层刷新策略

### 2. 多视角能力已具备，但复用仍可继续扩大

当前已经有统一接口和一批消费页面，但还可以继续补到：

- 项目详情更多卡片
- 项目列表页更丰富的摘要预览
- 更多 workflow / skill / artifact 入口

## 尚未完成

### 1. 独立 `project_memory` 表

当前 memory 仍保存在 `Project` 字段内，尚未拆成独立表，也没有版本历史与回滚能力。

### 2. 多份 memory 拆分

尚未拆为：

- `core memory`
- `risk memory`
- `delivery memory`
- `sales memory`

### 3. 真正异步化

当前仍以请求触发和前端触发为主，尚未做成完整的异步任务 / 定时刷新体系。

### 4. 完整测试矩阵

目前已有 helper、接口和部分链路测试，但还未覆盖完整的：

- API 回归矩阵
- 多视角 summarize 全量测试
- 前后端联调测试
- 大项目上下文性能测试

## 下一步建议

最值得继续推进的是：

1. 把当前“整包重建”演进为槽位级增量更新
2. 把批量刷新进一步升级为真正的后端异步任务
3. 评估是否拆出独立 `project_memory` 表和版本历史
4. 继续把 memory 扩展到更多工作流和页面入口
