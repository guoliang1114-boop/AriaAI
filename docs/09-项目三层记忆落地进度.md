# 项目三层记忆落地进度

更新日期：2026-04-17
对应设计文档：[08-项目三层记忆设计.md](./08-%E9%A1%B9%E7%9B%AE%E4%B8%89%E5%B1%82%E8%AE%B0%E5%BF%86%E8%AE%BE%E8%AE%A1.md)

## 当前结论

`08-项目三层记忆设计` 已经完成第一版落地，当前状态属于：

- 已实现可用的 V1
- 已打通“原始上下文 -> structured memory -> 视图摘要”的主链路
- 仍未进入“增量更新 / 独立 memory 表 / 多视角 memory”的完整阶段

## 已完成

### 1. 第二层 structured memory 已落地

后端已经新增并使用以下字段：

- `Project.context_memory_json`
- `Project.memory_stale`
- `Project.memory_version`
- `Project.memory_updated_at`

### 2. memory 构建链路已落地

已实现：

- `build_project_memory_data()`
- `build_project_memory_prompt()`
- `parse_project_memory()`
- `save_project_memory()`
- `get_project_memory_payload()`

### 3. memory 接口已落地

目前已经有：

- `GET /projects/{project_id}/memory`
- `GET /projects/{project_id}/memory/status`
- `POST /projects/{project_id}/memory/rebuild`
- `POST /projects/{project_id}/memory/summarize`

### 4. 视图摘要已接到第三层

- `POST /projects/{project_id}/generate-context` 已改为优先基于 structured memory 生成概览摘要
- `memory/summarize` 已支持：
  - `overview`
  - `risk`
  - `stakeholder`
  - `delivery`
  - `client-facing`

### 5. 聊天上下文已复用第二层

- `context_builder.py` 已改为优先使用 structured project memory
- 旧的 `context_summary` 仅作为兼容兜底

### 6. stale 标记已接入项目变更事件

以下改动已会触发 `memory_stale = True`：

- 项目基本信息更新
- 文档新增、更新、删除、上传
- 文件夹新增、删除
- 里程碑新增、更新、删除
- 待办新增、更新、删除
- 财务记录新增、删除
- 项目笔记更新
- 项目成员增删

### 7. 前端概览页已接入 memory 状态

项目概览页目前已支持：

- 查看 Project Memory 状态
- 查看版本号
- 查看更新时间
- 手动触发重建

## 部分完成

### 1. 目前仍是“整包重建”

当前是：

- 数据变化后标记 `stale`
- 在概览 summary / 手动重建 / summarize 入口处按需整包重建

尚未做到：

- 槽位级增量更新
- 文档、财务、待办、风险信号的局部刷新

### 2. 多视角摘要已有接口，但 UI 还未全面接入

后端已支持按视角生成摘要，但前端当前主要只显式消费了 `overview`。

## 尚未完成

### 1. 独立 `projectmemory` 表

当前 memory 仍然存放在 `Project` 表字段里，还没有拆成独立表，也没有历史版本回滚能力。

### 2. 多份 memory 拆分

尚未拆为：

- `core memory`
- `risk memory`
- `delivery memory`
- `sales memory`

### 3. 真正异步化

当前重建仍然主要依赖请求触发，尚未做成完整的异步任务 / 定时刷新体系。

### 4. 完整测试矩阵

当前已经有 helper 级别与构建级验证，但还没有覆盖完整的：

- API 回归测试
- 多视角 summarize 测试
- 前后端联调测试
- 大项目上下文性能测试

## 推荐的下一步

最值得继续推进的是：

1. 给 `memory/summarize` 补前端消费入口，先接 `risk` 和 `delivery`
2. 做 memory 状态在更多页面的可见性提示
3. 把整包重建演进为局部槽位增量更新
4. 评估是否升级到独立 `projectmemory` 表
