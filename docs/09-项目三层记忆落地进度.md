# 项目三层记忆落地进度

更新日期：2026-04-17  
对应设计文档：[08-项目三层记忆设计.md](./08-项目三层记忆设计.md)

## 当前结论

`08-项目三层记忆设计` 已经完成可用的 V1 落地，主链路已经跑通：

- 原始项目数据 -> structured memory -> 视图摘要
- 概览、聊天、设置、Memory 页面和多个执行页都已经开始消费 memory
- 项目级与系统级都已经有记忆管理入口
- 常用摘要已经从“每次打开都重新调 AI”升级为“按 memory version 缓存复用”

当前系统已经能满足业务可用，但仍未进入“槽位级增量更新”和“完整异步流水线”阶段。

## 已完成

### 1. 第二层 structured memory 已落地

`Project` 模型已包含并实际使用以下字段：

- `context_memory_json`
- `memory_stale`
- `memory_version`
- `memory_updated_at`

后端已具备：

- `build_project_memory_data()`
- `build_project_memory_prompt()`
- `parse_project_memory()`
- `save_project_memory()`
- `get_project_memory_payload()`

### 2. memory API 已可用

当前已提供：

- `GET /projects/{project_id}/memory`
- `GET /projects/{project_id}/memory/status`
- `POST /projects/{project_id}/memory/rebuild`
- `POST /projects/memory/rebuild-batch`
- `POST /projects/{project_id}/memory/summarize`
- `POST /projects/{project_id}/generate-context`

### 3. 第三层视图摘要已落地

当前已支持的摘要视角：

- `overview`
- `risk`
- `stakeholder`
- `delivery`
- `client-facing`
- `financial`
- `documents`

其中：

- `generate-context` 用于项目概览摘要
- `memory/summarize` 用于多视角摘要
- 多视角摘要已支持 SSE 流式输出
- 摘要语言会跟随当前用户界面语言

### 4. 摘要缓存已落地

为了解决“每次打开项目详情多个页面都重新调用 AI”的问题，当前已补上摘要缓存层：

- 新增 `ProjectMemorySummary` 缓存表
- 缓存键基于：
  - `project_id`
  - `memory_version`
  - `summary_type`
  - `language`
- `memory/summarize` 现在默认先查缓存，命中则直接返回
- 手动点击“重新生成”时会跳过缓存并更新缓存
- 前端 `useProjectMemorySummary` 也增加了会话级缓存，切换 tab 时优先复用

这意味着：

- 同一项目、同一份 memory、同一语言下
- `AI 项目记忆摘要 / AI 风险摘要 / AI 干系人摘要`
- 不会再在每次打开页面时重复调用模型

### 5. memory stale 链路已打通

以下行为会标记 `memory_stale = True`：

- 项目基本信息更新
- 文档新增、更新、删除、上传
- 文件夹新增、删除
- 里程碑新增、更新、删除
- 待办新增、更新、删除
- 财务记录新增、删除
- 项目笔记更新
- 项目成员增删

当前前端体验已支持：

- stale 状态提示
- 手动重建 memory
- 部分页面静默自动尝试重建
- memory 重建后摘要自动刷新

### 6. 项目内独立 Memory 页面已落地

项目详情中已新增独立 `Memory` tab，业务用户可以直接查看：

- 项目概况
- 当前目标
- 近期进展
- 下一步动作
- 关键风险
- 待确认问题
- 重要文档
- 财务状态
- 交付信号
- 干系人备注

同时页面中已提供：

- `AI 项目记忆摘要`
- `AI 风险摘要`
- `AI 干系人摘要`

### 7. 设置页和系统设置中的记忆管理已落地

项目设置页当前提供：

- 项目记忆概况
- 最近同步时间
- 来源覆盖
- 更新项目记忆
- 跳转到项目 Memory 页面

系统设置当前提供统一的 `记忆管理 / Memory Manager`：

- 全项目状态筛选
- 搜索项目 / 客户 / 摘要
- 批量更新待刷新记忆
- 批量补齐缺失记忆
- 单项目更新
- 直接跳到项目 Memory 页面

### 8. memory 已接入多个业务页面

当前已接入：

- `ProjectOverviewTab`
- `ProjectChatTab`
- `ProjectMemoryTab`
- `ProjectSettingsTab`
- `ProjectMilestonesTab`
- `ProjectTodosTab`
- `ProjectNotesTab`
- `ProjectFinancialsTab`
- `ProjectDocumentsTab`

### 9. 项目列表页已回归业务定位

`/projects` 页面已从“memory 运营面板”回收为业务首页：

- 保留项目业务信息和看板视图
- 不再承载过重的 memory 批量运营动作
- memory 的深度管理集中到项目内页和系统设置页

### 10. 回归测试已补强

已覆盖的关键测试包括：

- `build_project_summary_from_memory_prompt()` 按语言输出
- `build_project_memory_view_prompt()` 支持多视角
- `generate-context` 能透传语言
- `memory/summarize` SSE 事件格式正常
- `memory/status -> memory/rebuild -> status` 流程正常
- `memory/rebuild-batch` 能重建 stale 项目
- `memory/rebuild-batch` 能补齐缺失 memory
- `memory/summarize` 命中缓存时不会再次调用模型
- `memory/summarize` 强制刷新时会绕过缓存并回写缓存

## 部分完成

### 1. 仍以整包重建为主

当前仍是：

- 数据变化先标记 `stale`
- 再在摘要、页面进入、手动重建或批量重建时按需重建

尚未做到：

- 槽位级增量更新
- 只刷新风险槽位 / 财务槽位 / 文档槽位
- 完整后台异步任务化

### 2. 多视角已具备，但预生成策略仍可继续优化

当前已经有缓存复用，但仍属于“首请求生成、后续复用”。

后续仍可继续做：

- memory 重建后后台预生成常用摘要
- 常用视角优先预热
- 冷门视角按需生成

## 尚未完成

### 1. 独立 `project_memory` 主表与历史版本

当前 memory 仍保存在 `Project` 字段中，尚未拆出独立主表，也没有历史版本和回滚能力。

### 2. 多份 memory 拆分

尚未拆为：

- `core memory`
- `risk memory`
- `delivery memory`
- `sales memory`

### 3. 完整异步化

当前仍以请求触发和前端触发为主，尚未形成完整的任务队列 / 定时刷新体系。

### 4. 完整性能测试矩阵

目前已有关键回归，但还未覆盖：

- 大项目长上下文性能测试
- 多语言摘要压测
- 更完整的前后端联调场景

## 下一步建议

最值得继续推进的是：

1. 把“整包重建”演进为槽位级增量更新
2. 为常用摘要增加后台预生成 / 预热机制
3. 评估是否拆出独立 `project_memory` 表和历史版本
4. 继续把 memory 扩展到更多 workflow、skill 和 artifact 入口
