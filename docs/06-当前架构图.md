## 4. 聊天链路

```mermaid
sequenceDiagram
    participant User
    participant Web
    participant ChatAPI as /chat/send
    participant Services as Claude/Kimi + RAG + Tools
    participant DB

    User->>Web: 输入消息
    Web->>ChatAPI: POST /chat/send
    ChatAPI->>DB: 读取会话/项目/技能/设置
    ChatAPI->>Services: 组装上下文并调用模型
    Services-->>ChatAPI: 流式 chunk / tool result
    ChatAPI-->>Web: SSE stream
    ChatAPI->>DB: 写入 assistant message
    Web-->>User: 实时展示结果
```

## 6. 当前架构特征

- 双客户端共享同一后端 API
- 后端模块边界已基本形成
- 聊天路由承担较多编排责任
- 生成物和上传文件走本地文件系统
- RAG 与文件生成均内嵌在后端内

---

## 7. 当前架构主要风险

- Web 配置源不统一
- 聊天编排过重
- RAG 与数据层耦合较深
- 运行产物进入仓库
- 源码乱码影响长期维护
