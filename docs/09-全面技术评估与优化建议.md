# AriaAI 全面技术评估与优化建议

更新时间：2026-05-12（复审）

## 一、项目概况

AriaAI 是一个全栈 AI 咨询工作台。

- **前端**：React 19 + TypeScript 5.9 + Vite 8 + Tailwind CSS 4（SPA，非 SSR）
- **后端**：FastAPI 0.115 + SQLModel + Alembic（SQLite / PostgreSQL）
- **AI**：多 LLM 提供商（Claude、Kimi、Deepseek、BigModel、MiMo），RAG 向量检索，SSE 流式对话
- **部署**：GitHub Actions CI/CD → SCP/SSH → PM2 + Nginx（BaoTa 面板）
- **生产地址**：`https://aria.d2cgo.co`

### 4.1 架构问题

#### 零 ErrorBoundary ❌

整个代码库没有一个 `ErrorBoundary` 组件。任何懒加载页面在渲染时抛错，都会导致整个应用白屏。

**建议**：至少在 `App.tsx` 的 `LazyPage` 外层包裹 ErrorBoundary，提供降级 UI 和错误上报。

#### 40 个重复的 `lazy()` 包装器 ❌

`App.tsx` 中 403 行，每个路由都有相同的 `.then((module) => ({ default: module.X }))` 模式重复 40 次。

```typescript
// 当前：每个路由 ~6 行
const Welcome = lazy(() => import('./pages/Welcome').then((m) => ({ default: m.Welcome })));
const Chat = lazy(() => import('./pages/chat/Chat').then((m) => ({ default: m.Chat })));
// ... 重复 40 次

// 建议：提取工具函数
function lazyPage(loader: () => Promise<Record<string, React.ComponentType>>, name: string) {
  return lazy(() => loader().then((m) => ({ default: m[name] })));
}
const Welcome = lazyPage(() => import('./pages/Welcome'), 'Welcome');
```

#### `warmPrimaryRoutes` 抵消代码分割 ❌

`routeLoaders.ts:42-52` 在空闲时预加载 8 个页面模块，本质上取消了懒加载的收益。

**建议**：移除 `warmPrimaryRoutes`，改为用户 hover 导航时预加载（已有 `primaryRouteLoaders` 实现此功能）。

#### 死代码未清理 ❌

`src/pages/` 根目录下存在遗留页面文件，与子目录中的正式版本重复：

- `src/pages/Chat.tsx`（10,623 bytes）
- `src/pages/Skills.tsx`（8,301 bytes）
- `src/pages/Projects.tsx`（11,647 bytes）
- `src/pages/Dashboard.tsx`（9,049 bytes）
- `src/pages/conversations/Conversations.tsx`（4,422 bytes）

**建议**：确认无引用后删除。

### 4.3 状态管理

当前使用 React Context API（`AuthContext`、`ThemeContext`、`ToastContext`），对当前规模合适。

**核心缺失：无服务端状态管理库**。每个页面手动 `useEffect` + `useState` 管理 loading/error/data，导致：

- 重复的 fetch 模式遍布各页面
- 无请求缓存
- 无后台自动刷新
- 无乐观更新
- 无请求去重

**建议**：引入 TanStack Query（react-query），逐步迁移 API 调用。

- 无模态框/下拉菜单的焦点管理
- 无 skip-to-content 链接
- 自定义设计系统的颜色对比度未验证
- ESLint 未配置 `eslint-plugin-jsx-a11y`

### 4.5 SEO
