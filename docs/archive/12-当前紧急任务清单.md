### 任务 2：服务器 Nginx 安全头 + gzip

**背景**：当前生产环境 Nginx 没有安全头和 gzip 压缩。Cloudflare 处理了 SSL，但 Nginx 层面的安全配置仍缺失。

**操作步骤**：
1. 登录宝塔面板（`http://85.137.244.146:8888`）
2. 找到 aria.d2cgo.co 的 Nginx 配置
3. 在 `server` 块中添加：

```nginx
# gzip
gzip on;
gzip_vary on;
gzip_min_length 1024;
gzip_types text/plain text/css application/json application/javascript text/xml application/xml text/javascript image/svg+xml;

# Security headers
add_header X-Frame-Options "SAMEORIGIN" always;
add_header X-Content-Type-Options "nosniff" always;
add_header X-XSS-Protection "1; mode=block" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;

# Upload size
client_max_body_size 50M;
```

4. 重载 Nginx：`nginx -s reload`
5. 验证：`curl -I https://aria.d2cgo.co` 确认 headers 包含上述安全头

**验收标准**：
- `curl -I https://aria.d2cgo.co` 返回 `X-Frame-Options: SAMEORIGIN`
- `curl -I https://aria.d2cgo.co` 返回 `X-Content-Type-Options: nosniff`
- gzip 生效：`curl -H "Accept-Encoding: gzip" -I https://aria.d2cgo.co` 返回 `Content-Encoding: gzip`
- 上传 50MB 文件不返回 413

## 三、P1 任务详情

### 任务 4：LLM Router 替代规则匹配

**背景**：当前 `detect_project_task_type()` 用关键词匹配（"准备" + "PPT"），但用户表达千变万化。生产数据显示：
- "帮我做个 deck" → 不会被识别为 PPT 任务
- "出一份给客户的材料" → 不会被识别
- "搞个表格" → 不会被识别

**方案**：用一次轻量 LLM 调用替代规则匹配。

**技术设计**：

```python
# app/services/task_router.py

TASK_TYPES = {
    "generate_client_ppt": "用户需要生成 PPT / deck / 演示材料 / slides",
    "generate_project_excel": "用户需要生成 Excel / 表格 / 访谈表 / 清单 / 台账",
    "generate_project_docx": "用户需要生成 Word / DOCX / 文档 / 报告 / 方案",
    "generate_project_pdf": "用户需要生成 PDF",
    "run_skill": "用户需要执行某个 Skill / 方法论 / 分析框架",
    "summarize_projects": "用户需要总结 / 汇总多个项目的状态 / 进展 / 风险",
    "query_milestones": "用户需要查询 / 检查里程碑 / 待办 / 截止日期",
    "general_qa": "普通问答，不需要执行任务",
}

async def route_user_intent(content: str, project_context: str = "") -> str:
    """用 LLM 分类用户意图，返回 task_type。"""
    prompt = f"""你是一个意图分类器。根据用户消息，判断用户想要做什么。

用户消息：{content}

可选分类：
{chr(10).join(f'- {k}: {v}' for k, v in TASK_TYPES.items())}

只返回分类名称，不要解释。"""

    result = await complete_with_selected_model(
        [{"role": "user", "content": prompt}],
        max_tokens=50,
    )
    task_type = result.strip().lower()
    return task_type if task_type in TASK_TYPES else "general_qa"
```

**修改范围**：
- 新建 `app/services/task_router.py`
- 修改 `chat_streaming.py`：将 `detect_project_task_type` 替换为 `route_user_intent`
- 保留 `detect_project_task_type` 作为 fallback（LLM 调用失败时降级到规则匹配）

**验收标准**：
- "帮我做个 deck" → 识别为 `generate_client_ppt`
- "出一份给客户的材料" → 识别为 `generate_client_ppt`
- "这个项目风险是什么" → 识别为 `general_qa`
- "帮我总结所有项目" → 识别为 `summarize_projects`
- LLM 调用失败时降级到规则匹配，不报错

**预计投入**：2 小时

### 任务 5：Planner 动态步骤生成

**背景**：当前所有任务都是硬编码 4 步（收集上下文 → 生成结构 → 生成文件 → 整理结果）。不同任务需要不同步骤：
- PPT：大纲 → 内容 → 设计 → 导出
- Excel：数据收集 → 表头设计 → 填充 → 格式化
- 跨项目总结：收集各项目 → 分别总结 → 聚合 → 生成报告

**方案**：在 TaskRun 创建时，用 LLM 生成步骤列表。

**技术设计**：

```python
# app/services/task_planner.py

async def plan_task_steps(
    task_type: str,
    user_request: str,
    project_context: str,
) -> list[dict]:
    """根据任务类型和用户请求，动态生成步骤列表。"""
    
    if task_type in TASK_STEP_TEMPLATES:
        # 已知任务类型用模板，更快更稳定
        return TASK_STEP_TEMPLATES[task_type]
    
    # 未知任务类型用 LLM 生成
    prompt = f"""你是一个任务规划器。根据用户的请求，生成执行步骤。

用户请求：{user_request}
项目上下文：{project_context}

要求：
1. 每个步骤有 name（步骤名）和 description（步骤描述）
2. 步骤数量 3-6 个
3. 最后一步必须是"整理交付结果"
4. 返回 JSON 数组

示例：
[
  {{"name": "收集项目上下文", "description": "读取项目记忆、文件、干系人信息"}},
  {{"name": "生成交付物结构", "description": "确定文件结构和内容大纲"}},
  {{"name": "生成并保存文件", "description": "生成文件并保存到项目空间"}},
  {{"name": "整理交付结果", "description": "汇总执行结果，返回给用户"}}
]"""

    result = await complete_with_selected_model(
        [{"role": "user", "content": prompt}],
        max_tokens=500,
    )
    return json.loads(extract_json(result))
```

**修改范围**：
- 新建 `app/services/task_planner.py`
- 修改 `task_orchestrator.py`：创建 TaskRun 时调用 Planner 生成步骤

**验收标准**：
- 已知任务类型（PPT/Excel/Word/PDF）使用模板，不调用 LLM
- 未知任务类型调用 LLM 生成步骤
- 生成的步骤保存为 TaskStep
- LLM 生成失败时降级到默认 4 步模板

**预计投入**：1 天

### 任务 6：Text Artifact 支持

**验收标准**：

### 任务 7：人工确认步骤

**背景**：生产场景中，以下操作需要用户确认：
- 生成的 PPT 覆盖了之前的版本
- 发送给客户材料前
- 删除旧文件前
- 批量操作前

**方案**：TaskStep 增加 `requires_confirmation` 字段。Executor 执行到该步骤时暂停，等待用户确认。

**技术设计**：

```python
# TaskStep 模型新增字段
requires_confirmation: bool = False
confirmation_prompt: str = ""  # "即将覆盖文件 X，确认继续？"
confirmed_at: Optional[datetime] = None
confirmed_by: Optional[int] = None  # user_id
```

```python
# Executor 执行逻辑
async def execute_step(step: TaskStep, ...):
    if step.requires_confirmation and not step.confirmed_at:
        step.status = "waiting_confirmation"
        # 发送 SSE 事件通知前端
        yield sse_event("confirmation_required", {
            "step_id": step.id,
            "prompt": step.confirmation_prompt,
        })
        return  # 暂停，等待用户确认
    
    # 正常执行...
```

**前端**：
- 聊天界面弹出确认卡片："即将覆盖文件 X，确认继续？"
- 用户点击"确认" → 调用 `POST /task-runs/{id}/steps/{step_id}/confirm`
- Executor 继续执行

**修改范围**：
- `app/models/db.py`：TaskStep 增加确认相关字段
- `app/services/task_orchestrator.py`：Executor 支持暂停等待确认
- `app/routers/projects_deps.py`：新增确认 API
- `aria-web/src/pages/projects/ProjectChatMessages.tsx`：确认卡片组件

**验收标准**：
- TaskStep 可以标记为 `requires_confirmation`
- Executor 在确认步骤暂停，发送 SSE 事件
- 前端显示确认卡片
- 用户确认后 Executor 继续执行
- 用户拒绝后 TaskStep 标记为 `skipped`

**预计投入**：1 天
