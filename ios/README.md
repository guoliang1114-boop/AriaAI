# Aria iOS · SwiftUI 本地交互演示

原生 iOS 前端，以提供的 HTML 原型最终浅色样式为参考。品牌为 **A / Aria / 让复杂工作有清晰的下一步。** 使用 SwiftUI、系统字体和 SF Symbols，不嵌入 WebView，不依赖第三方库。

## 当前状态

- 已提供完整 Xcode 工程、9 个 Swift 应用源文件、应用图标和 XCTest 测试目标。
- 已通过 **148 项可移植结构与安全检查**，并经过独立源码复核。
- **未执行 Swift 编译、XCTest、iOS 模拟器、真机或 VoiceOver 测试**：交付环境没有 macOS、Xcode 或 Swift 工具链。源码检查不能替代编译或界面验收。
- 这是 mock-only 前端，不是可发布的生产 App，也未接入 AriaAI 后端。

## 在 Xcode 中运行

1. 使用安装 Xcode 16 或更新版本的 Mac，并安装一个 iOS 17 或更新版本的模拟器运行时。
2. 打开 `Aria.xcodeproj`。在 AriaAI 仓库中，该文件位于 `ios/Aria.xcodeproj`。
3. 选择 **Aria** scheme 和一个 iPhone 模拟器，点击 Run（⌘R）。没有外部包需要下载。
4. 首次启动会显示启动页和三页引导。登录可使用 `demo@example.com` 与 `demo123` 等模拟内容；请勿输入真实密码。
5. 真机运行需在 Signing & Capabilities 中选择自己的开发团队，并按需修改 bundle identifier。工程不包含签名证书或开发团队资料。

最低系统版本：iOS 17.0。iPhone 为竖屏；iPad 支持横竖屏并限制部分内容宽度。iPad 和极端文字尺寸布局仍需在 Xcode 中检查。

### 命令行检查

在本目录执行：

```bash
python3 Scripts/validate_project.py
```

在 Mac 上完成真实构建：

```bash
xcodebuild -project Aria.xcodeproj -scheme Aria   -configuration Debug -sdk iphonesimulator   -destination 'generic/platform=iOS Simulator'   CODE_SIGNING_ALLOWED=NO build

xcrun simctl list devices available
# 将 SIMULATOR_UDID 换成上一步列出的可用设备 ID。
xcodebuild -project Aria.xcodeproj -scheme Aria   -destination 'platform=iOS Simulator,id=SIMULATOR_UDID' test
```

工程已直接提交，不需要 XcodeGen。只有增删源文件或修改构建配置时，才需要重新生成：

```bash
python3 Scripts/generate_project.py
python3 Scripts/validate_project.py
```

生成器输出固定的对象 ID，可以复现已提交的工程和共享 scheme。

## 第二轮交互完善

- 草稿和引用按会话保留，新建、切换和搜索跳转不再丢失未发送内容；退出才清除全部草稿（已保存的历史仍保留）。
- “停止整理”只取消当前会话，旧请求不能覆盖重新开始的回复，也不会生成已取消的审批。
- 阅读历史消息时，新回复不强制把页面拉到底部；显示可点击的“新回复”提示。
- 输入区使用安全区 inset；键盘打开时收紧行数和引用预览，提供收起键盘按钮。大字模式简化顶部操作并将筛选/状态分段切换为菜单。
- 页面刷新采用随视图取消的任务和请求标记，离开后不会应用迟到的结果。
- 语音在应用非活跃时暂停计时和光球动画。电话演示进入后台时取消未连接呼叫，或结束已连接演示并记录摘要；不会在后台拨号或录音。

## 第三轮：本地演示连续性

- 修改会在约 300ms 后合并保存；应用离开活跃状态和退出模拟登录时会尝试立即保存。突然终止或存储故障仍可能使最近未成功保存的改动丢失，以界面状态为准。
- 重启恢复消息 ID/时间、审批关联、逐会话草稿/引用和当前会话。不会恢复登录，也不会继续上次尚未完成的模拟回复；发送内容保留，并提供恢复说明。
- 保存异常或容量不足时，主页面出现可进入“数据控制”的提示。写入失败保留当前内存内容和原快照；可修正草稿后重试。读取失败、文件损坏、未知版本时暂停自动写入，先用示例内容临时演示，原文件不改动。
- 被保护的文件可重试读取，但已有新的临时改动时不会重新载入旧文件覆盖它们。需要恢复保存时，可明确确认归档并重置；当前尚未保存的临时改动会丢弃。
- 退出清除邮箱、未发送草稿/引用和待回复任务，返回登录页；已经保存的对话与审批历史保留。退出时若写入失败，登录页会继续提示；不能保证磁盘上的旧草稿已清除，需重试成功。
- “重置本地演示”先复制现有磁盘快照到本机归档，再原子写入初始示例；两步均成功后才替换内存状态。没有旧文件时直接创建示例。它不是永久删除操作，旧归档不会自动删除。

### 存储格式与边界

文件位于应用沙盒 `Application Support/AriaDemo/demo-state.json`，使用版本化 Codable JSON（当前 schema 2）、原子替换和完整文件保护；目录排除设备备份，不接入 iCloud 或其他同步。[Apple 的完整文件保护](https://developer.apple.com/documentation/foundation/fileprotectiontype)下，设备锁定时写入可能失败，需要解锁后重试。

兼容的 schema 1 是没有草稿字段的迁移测试格式，之前交付的版本并未写入它。读取后转换为 schema 2；首次保存前先归档旧文件。未来版本不会被猜测性转换。校验文件大小（最大 5MiB）、重复 ID、会话/审批关联、条数和文本上限，失败不自动截断或丢弃内容。

演示上限为 200 个会话、20,000 条消息、5,000 个审批、单段文本 100,000 UTF-8 字节。发送、新建和通话摘要在写入历史前检查容量并为待完成回复留空间；超长草稿仍可编辑，但需要缩短才能保存或发送。没有后台任务、文件导入导出或自动清理。

归档为同一沙盒目录中的 `recovery-<UUID>.json`。当前没有应用内浏览/恢复归档功能；开发验收可通过 Xcode 下载应用容器检查。恢复说明只在本次运行中展示，不是归档列表。普通重置不会清除归档，反复重置会占用本机空间。此存储实现用于小规模本地演示，尚未在设备上验证性能或文件保护行为。

## 原型对齐与原生调整

- 采用 HTML **最后生效**的浅色覆盖，而非较早的深色规则：背景 `#F7F7F8`、白色卡片、正文 `#29292D`、次要文字 `#68686E`、强调色 `#0F8F72`。
- 保留最终的三页引导文案、五个导航入口、项目主题示例内容、审批层级、设置分组、白色语音/电话页与三种光球配色。
- 语音控件为静音/字幕/结束三个深色按钮。点击正在说话的光球可打断并回到听的状态；电话挂断为红色。
- 使用原生 TabView、NavigationStack、sheet、菜单与键盘行为；会话列表采用原生弹层。未声称 CSS 像素级复刻。
- 修复原型展示脚本中的状态局限：新建和切换会话有独立消息；搜索包含新消息；所有消息共用复制/回复交互；审批决定跨页面一致；重复进入通话会重置控件。
- 登录增加邮箱格式和六位模拟密码校验；不会制造真实账号、条款接受或密码找回流程。未接入真实条款页面。
- 电话保留运营商计费的设计说明，但明确为无费用的模拟体验，不展示未经证实的实际价格。
- 为本地演示添加说明、无障碍标签、减弱动态效果支持与大字控件布局。系统深色模式不会改变浅色主题。
- 原始 HTML、上传文件、参考截图和个人账号资料不包含在代码包或公共提交中。

## Mock 与隐私边界

无 HTTP 请求、WebSocket、后台服务、账号服务、遥测或分析 SDK。无 AVAudioSession、录音、STT、TTS、CallKit、真实拨号、付款、OAuth 或 Google API。

登录密码只存在于登录视图的临时状态，成功或离开页面后立即清空，不进入 AppStore，不写入 UserDefaults、Keychain 或日志。邮箱只保留于当前进程，退出即清空。快照不包含邮箱、密码、认证令牌、登录状态或会话凭据；每次重新打开仍需经过模拟登录。

聊天、审批、逐会话草稿/引用与会话选择现在保存在本机。所有模拟邮箱共享同一份演示数据，没有真实账号隔离；请只输入虚构内容，不输入敏感资料。收藏、目标清单、设置开关仍为内存/页面状态。通知开关不会触发系统权限，示例资料按钮不读取本机文件。电话键盘只显示数字，不发送拨号音。

后续若连接真实 AriaAI 服务，项目、客户、资料、审批、权限与审计仍应由 AriaAI 原生服务管理。此版本不引入 Codex SDK、App Server 或运行时子进程依赖。
